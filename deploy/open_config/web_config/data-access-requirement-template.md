# ZenVis 数据接入需求模板

> 填写说明：
> 1. 只需要描述数据格式、字段含义、样例数据，以及数据来源、解析清洗映射和推送规则。
> 2. 写入默认使用系统内置 ZenVis ClickHouse 的 `zenvis` 库，不需要填写目标端点、账号或数据库连接信息。
> 3. 不确定的信息可以写“未知”，并尽量提供样例值，智能体会基于样例给出建议。

## 1. 数据格式定义

### 1.1 实体定义

| 项目 | 内容 |
| --- | --- |
| 实体英文名 | 例如：user_event、asset_inventory；不确定可留空 |
| 实体中文名 | 例如：用户事件、资产清单 |
| 数据描述 | 例如：记录用户登录、点击、浏览等行为事件 |
| 数据类型 | 例如：事件日志 / 资产信息 / 风险告警 / 指标数据 |
| 目标表名（可选） | 例如：msg_user_event；不填则由智能体生成 |

### 1.2 字段清单

| 字段名 | 样例值 | 中文名 | 字段含义 | 建议类型 | 是否展示 | 查询方式/备注 |
| --- | --- | --- | --- | --- | --- | --- |
| id |  | 唯一标识 | 数据唯一标识 | String | 是 | equal、in |
| event_time |  | 事件时间 | 事件发生或入库时间 | DateTime64(3) | 是 | 时间范围 |
| event_type |  | 事件类型 | 业务事件分类 | String | 是 | equal、in |
| message |  | 原始消息 | 原始日志或详情 | String | 否 | match |

### 1.3 示例数据

请至少提供 1 条真实或脱敏后的原始数据。可以是 JSON、日志行、CSV 行或字段清单。

```json
{
  "id": "",
  "event_time": "",
  "event_type": "",
  "message": ""
}
```

### 1.4 关键字段与特殊类型

| 项目 | 内容 |
| --- | --- |
| 唯一标识字段 | 例如：id；没有则写“无” |
| 排序字段 | 例如：id、event_time |
| 时间字段 | 例如：event_time、server_time、insert_time |
| 枚举字段 | 例如：event_type：登录=login、退出=logout |
| 数组字段 | 例如：tags：Array(String) |
| JSON 字段 | 例如：detail：JSON |
| 其他特殊字段 | 例如：IP、数值、布尔、嵌套对象 |

## 2. 数据来源、解析清洗映射与推送规则

### 2.1 数据来源定义

| 项目 | 内容 |
| --- | --- |
| 数据源类型 | 例如：Kafka / syslog / file / HTTP / demo_logs / 其他 |
| 连接信息 | 例如：topic、文件路径、API 路径；无连接信息可写“无” |
| 认证方式 | 例如：无 / basic / token / 证书；不建议填写真实密钥 |
| 输入格式 | 例如：JSON / CSV / syslog / 文本日志 |
| 输入样例 | 可复用 1.3，也可单独补充 |

### 2.2 解析、清洗与映射规则

| 项目 | 内容 |
| --- | --- |
| 解析规则 | 例如：按 JSON 解析、按逗号分隔、正则提取 |
| 字段映射 | 例如：srcIp -> src_ip，eventTime -> event_time |
| 清洗规则 | 例如：字段名转小写、去除空值、补齐默认值 |
| 转换规则 | 例如：时间格式转换、枚举值映射、字符串转数值 |
| 异常数据处理 | 例如：丢弃、写控制台、保留原始消息 |

### 2.3 推送规则

| 数据类型或条件 | 对应实体 | 说明 |
| --- | --- | --- |
| 例如：event_type in [login, click] | user_event | 写入用户事件实体 |
| 例如：全部数据 |  | 单实体场景可写“全部数据 -> 当前实体” |
