# ZenVis 元数据配置需求模板

> 填写说明：
> 1. 本模板只用于描述要发布到 Meta 的实体、字段、样例数据和存储建议。
> 2. 数据推送服务的 Kafka、Vectum、解析映射和推送规则不在本模板中填写，请在数据推送服务智能体中单独描述。
> 3. 写入默认使用系统内置 ZenVis ClickHouse 的 `zenvis` 库，不需要填写目标端点、账号或数据库连接信息。
> 4. 不确定的信息可以写“未知”，并尽量提供样例值，智能体会基于样例给出建议。

## 1. 实体定义

| 项目 | 内容 |
| --- | --- |
| 实体英文名 | 例如：user_event、asset_inventory；不确定可留空 |
| 实体中文名 | 例如：用户事件、资产清单 |
| 数据描述 | 例如：记录用户登录、点击、浏览等行为事件 |
| 数据类型 | 例如：事件日志 / 资产信息 / 风险告警 / 指标数据 |
| 目标表名（可选） | 例如：msg_user_event；不填则由智能体生成 |

## 2. 字段清单

| 字段名 | 样例值 | 中文名 | 字段含义 | 建议类型 | 是否展示 | 查询方式/备注 |
| --- | --- | --- | --- | --- | --- | --- |
| id |  | 唯一标识 | 数据唯一标识 | String | 是 | equal、in |
| event_time |  | 事件时间 | 事件发生或入库时间 | DateTime64(3) | 是 | 时间范围 |
| event_type |  | 事件类型 | 业务事件分类 | String | 是 | equal、in |
| message |  | 原始消息 | 原始日志或详情 | String | 否 | match |

## 3. 示例数据

请至少提供 1 条真实或脱敏后的原始数据。可以是 JSON、日志行、CSV 行或字段清单。

```json
{
  "event_id": "",
  "event_time": "",
  "event_type": "",
  "message": ""
}
```

## 4. 关键字段与特殊类型

| 项目 | 内容 |
| --- | --- |
| 业务唯一标识字段 | 例如：event_id；没有则写“无”。平台记录ID `zenvis_id` 由系统自动创建和赋值，不需要填写 |
| 排序字段 | 例如：event_id、event_time；未指定时可使用平台创建时间 `zenvis_insert_time`，不要使用 `zenvis_id` |
| 业务时间字段 | 例如：event_time、server_time；平台创建时间 `zenvis_insert_time` 由系统自动创建和赋值，不需要填写 |
| 枚举字段 | 例如：event_type：登录=login、退出=logout |
| 数组字段 | 例如：tags：Array(String) |
| JSON 字段 | 例如：detail：JSON |
| 其他特殊字段 | 例如：IP、数值、布尔、嵌套对象 |

## 5. 存储与建表建议

| 项目 | 内容 |
| --- | --- |
| ClickHouse 引擎 | 例如：MergeTree；不填则由智能体按数据特征建议 |
| 分区字段 | 例如：按 server_time 月分区；不填则由智能体建议 |
| 排序键 | 例如：event_id、event_time |
| 保留周期 | 例如：不限制 / 180 天 |

> 本智能体只负责生成、写入并读回校验 Meta，不创建或修改数据推送任务。Meta 发布完成后，请到数据推送服务智能体继续配置数据来源和推送链路。
