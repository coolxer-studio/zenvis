## 产品定位

ZenVis 是配置驱动的数据分析应用框架。平台把常见的数据平台能力沉淀为可复用的基础设施，让团队将精力集中在业务数据定义、分析方法和应用体验上。

ZenVis 的能力可以概括为：

```text
数据接入 → 元数据与存储 → 检索与统计 → 可视化与应用 → AI 分析与处置
                          ↑
                    插件化扩展
```

## 解决的问题

| 常见问题 | ZenVis 的处理方式 |
| --- | --- |
| 数据模型硬编码，字段变化成本高 | 用 Meta 配置声明实体、属性、显示、操作符和存储规则 |
| 每个业务重复开发查询与分页 | 提供统一实体、检索、统计、趋势和详情 API |
| 应用和看板与平台强耦合 | 支持低代码应用、静态 HTML、外链和插件化菜单 |
| 接入链路分散、难以复用 | 通过插件内推送任务组织 Source、Kafka、Transform 和 Sink |
| AI 能力缺少数据与权限边界 | 通过 RAG、Skill、MCP scope、审批策略和审计控制工具使用 |
| 外部业务服务缺少统一运行视图 | 通过 Starter 或公开 API 汇聚实例心跳与业务事件 |

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 实体（Entity） | 可检索的数据集合，对应业务对象和实际存储表 |
| 属性（Attribute） | 实体字段，定义类型、显示、操作符、候选值、复制和跳转行为 |
| 操作符（Operator） | 检索条件支持的比较方式，如等于、包含、区间和空值判断 |
| 推送任务 | 由数据服务执行的数据采集、转换、路由和写入配置 |
| 看板 | 内置组件、低代码页面、HTML 页面或外部链接形式的可视化入口 |
| 插件 | 可安装的业务能力包，可同时提供数据、API、UI、看板、MCP、Skill 和菜单 |
| DIH | ZenVis 的数智中心，承载问答、业务 Agent、审批、报表与后台分析任务 |
| 业务应用服务 | 向 ZenVis 上报实例状态与业务事件的外部应用 |

## 核心能力

### 数据接入与存储

- MySQL 保存用户、角色、菜单、配置、会话、插件和任务等平台数据。
- ClickHouse 保存插件实体和分析型业务数据。
- Redis 保存 Session、缓存和部分运行状态；Redis Stack 用于向量检索。
- Kafka 与 Vectum 承担流式数据接入和推送任务运行。

### 检索与分析

- 元数据驱动的实体列表、字段选择和候选值。
- 普通条件和受限高级表达式检索。
- 个人过滤器保存、更新、失效检测和兼容升级。
- 实体计数、增量、趋势、字段统计和 IP 关联统计。

### 可视化与应用

- 内置看板用于平台原生页面。
- 低代码页面与应用基于配置快速交付业务功能。
- HTML 看板适合自包含的大屏和专题页面。
- 外链页面用于集成既有 BI 或业务系统。

### 插件扩展

插件以独立归档安装，生命周期可覆盖：

- Meta 和 ClickHouse 表结构；
- 数据推送任务；
- 动态 Spring API 与 MySQL 迁移；
- 低代码 UI、HTML 页面和看板；
- MCP 服务、Skill 和菜单；
- README 与可进入 RAG 的 `00_doc` 文档。

### AI 与自动化

- 普通问答和深度思考使用会话记忆，并可按配置检索公共 RAG。
- 业务 Agent 显式加载 Skill，并只获得其 scope 允许的 MCP 工具。
- 工具执行统一应用 `ALLOW / ASK / DENY` 策略和调用审计。
- AI 分析任务支持排队、计划执行、优先级、审批和取消。
- 报表 Agent 可以生成、改写、保存、归档并导出结构化文档。

## 典型场景

- 安全事件、网络流量、资产、风险和运营数据分析。
- 指标趋势、设备状态、日志和 IoT 数据监测。
- 多源数据统一检索和跨实体 IP 调查。
- 面向业务人员的低代码应用和专题大屏。
- 通过自然语言完成查询、研判、配置建议和报表编写。
- 将外部业务应用的健康状态与重要事件纳入统一运维视图。

## 产品边界

- ZenVis 提供框架和通用能力，具体业务数据含义由 Meta、推送任务和插件定义。
- 普通问答不执行 MCP 工具；需要读取业务数据或执行动作时使用相应业务 Agent。
- 插件卸载会清理平台安装项，但不会自动删除插件业务表和历史迁移记录。
- AI 输出用于辅助分析，涉及写入或处置的动作必须遵循工具策略、审批与权限控制。
