# 服务管理

“服务管理”用于管理数据推送任务，并只读查看外部业务服务程序的运行状态。内置菜单为“数据推送服务”和“业务应用服务”。已有环境升级后，原本拥有“服务管理”父菜单权限的角色会自动获得“业务应用服务”菜单权限。

## 数据推送服务

数据推送服务用于创建、启动、停止和查看数据推送任务及运行日志。任务配置、启停和日志查看方法沿用现有功能；接口说明见 [PushTaskController](../../05-API参考/控制器/PushTaskController.md)。

## 业务应用服务

业务应用服务是轻量、只读的服务状态中心。页面每 10 秒自动刷新，不提供手工创建、编辑、删除或注销实例操作。实例由业务程序通过公开心跳接口自动注册。

### 服务概览

页面顶部展示：

- 业务服务数和实例总数。
- 健康、降级、主动下线和心跳离线实例数。
- 异常合计，即主动下线与心跳离线数量之和。
- 最近 24 小时接收的事件数量和本次检查时间。

### 实例状态

可以按关键词、环境和有效状态筛选实例。关键词会匹配服务标识、服务名称、实例标识和主机。

| 状态 | 说明 |
|---|---|
| 健康 `UP` | 心跳未超时，实例主动上报健康 |
| 降级 `DEGRADED` | 心跳未超时，但实例仍可提供降级服务 |
| 主动下线 `DOWN` | 心跳未超时，实例明确上报不可用 |
| 心跳离线 `OFFLINE` | 最后心跳超过离线阈值，默认 90 秒 |

点击“详情”可查看版本、环境、主机端口、管理地址、上报状态、状态说明、首次和最后心跳、最后事件、来源地址以及实例元数据，并查看该实例的最近事件。

客户端上报的心跳时间只用于展示。有效状态始终按服务器实际接收心跳的时间计算，因此修改客户端时钟不会改变在线状态。

### 事件记录

可以按关键词、服务标识、实例标识、事件类型、事件级别和发生时间范围筛选事件。点击“详情”查看事件 ID、标题、消息、Trace ID、客户端发生时间、服务器接收时间和扩展数据。

事件级别包括 `INFO`、`WARN`、`ERROR`、`CRITICAL`。已离线但曾经通过心跳注册的实例仍可以上报事件；从未注册的实例事件会被拒绝。

### 数据保留

默认保留事件 30 天。只有最后心跳和最后事件都超过实例保留期的长期离线实例才会清理；近期事件会继续保留实例。清理任务默认每小时执行一次。

### 接入与排障

业务程序必须先上报心跳，再上报事件。公开上报接口不需要登录，但生产环境应在部署侧控制网络来源。请求字段、示例、大小限制、事件幂等和配置项见 [业务应用服务接口文档](../../05-API参考/控制器/BusinessServiceController.md)。

常见问题：

- 实例频繁在 `UP` 与 `OFFLINE` 之间切换：心跳周期过长或网络抖动，建议心跳周期显著小于 90 秒。
- 同一服务出现多条实例：这是多副本的正常表现；若为同一进程，请检查 `instance_id` 是否每次启动或每次心跳都在变化。
- 事件被拒绝：确认完全相同的 `service_code + instance_id` 已成功上报心跳。
- 事件 ID 冲突：同一实例的原事件可使用原 ID 重试；新事件和其他实例必须使用新的全局唯一 ID。
