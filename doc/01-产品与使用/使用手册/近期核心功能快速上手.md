# 近期核心功能快速上手

本文面向新同事，快速说明近期产品和工程侧几个容易踩坑的核心功能：内置超级管理员、数据看板路由、全局检索过滤器、前端 API 前缀。

## 1. 内置超级管理员

系统启动时会自动创建内置超级管理员角色和用户。

| 项目 | 说明 |
| :--- | :--- |
| 默认账号 | `super@admin.com` |
| 默认名称 | `超级管理员` |
| 初始化顺序 | 先初始化超级管理员，再初始化机构管理员 |
| 可见范围 | 仅超级管理员账号可在用户/角色管理中看到超级管理员用户和角色 |
| 操作限制 | 超级管理员用户不允许通过用户管理编辑或删除；超级管理员角色不允许编辑或删除 |
| 菜单权限 | 默认拥有全部菜单权限，新建菜单会自动同步给超级管理员角色 |

普通管理员和机构管理员在用户列表、角色列表、角色下拉、详情接口中都看不到超级管理员账号和角色，也不能手工把超级管理员角色分配给普通用户。

更多说明见 [系统管理](功能说明-系统管理.md)。

## 2. 数据看板类型与路由编码

看板分为四类，只有内置看板需要填写路由编码。

| 类型 | 标识 | 必填字段 | 打开方式 |
| :--- | :--- | :--- | :--- |
| 内置看板 | `BUILT` | `name`、`type`、`code` | 前端通过 `code` 找到内置组件 |
| 低代码页面看板 | `LOW_CODE_PAGE` | `name`、`type`、`configIndex` | 通过 AMIS 配置索引渲染 |
| HTML 页面看板 | `HTML_PAGE` | `name`、`type`、`htmlPath` | 通过 HTML 路径打开静态页面 |
| 外链看板 | `LINK` | `name`、`type`、`url` | 通过 URL 打开外部页面 |

当前系统状态内置看板编码为 `system-board`，并兼容旧编码 `msg-board`。如果内置看板配置了未知 `code`，前端会展示空状态，不会回退到默认看板。

非内置看板不依赖 `code` 选中或高亮，推荐使用 `id` 定位，例如 `/dashboard/index?id=xxx`。旧的 `code/name` query 仍保留兼容。

系统始终保留一个默认看板。普通进入看板页时显示默认项，带 `id`、`code` 或 `name` 的链接仍优先打开指定看板。HTML 看板的 `htmlPath` 必须是相对文件路径，例如 `reports/overview.html`，实际访问地址由前端补成 `/zenvis/html-page/reports/overview.html`。

更多说明见 [大屏看板](功能说明-大屏看板.md)。

## 3. 全局检索过滤器

全局检索支持普通筛选和高级 where 表达式。过滤器保存后可在左侧抽屉中快速复用。

### 普通筛选

普通筛选通过图形化控件选择字段、操作符和值，适合日常查询。多个条件可选择 AND 或 OR 关系。

### 高级 where 表达式

高级检索支持安全子集形式的 where 表达式：

```sql
ip = '10.0.0.1'
`ip` = '10.0.0.1'
module_type_name = '网站攻击' and attack_type_name in ('信息泄露', 'SQL注入')
```

字段必须来自当前实体元数据；支持 `= != > < >= <= like between in is null is not null`。不支持任意 SQL、子查询、函数调用、注释拼接或无字段条件。

### 更新过滤器

更新过滤器时，后端会先读取已有过滤器，再补齐本次请求中缺失的实体、展示字段、检索类型、普通条件或高级 where 表达式，最后复用新建过滤器的规则生成逻辑保存。这样可以避免“新建成功、更新失败”的不一致。

规则列表和详情按创建用户个人隔离。选择规则时，新前端使用一次 `/rule/detail` 原子回填配置；有效规则只查询一次，失效规则保留原条件供修复但不会自动执行。字段或操作符发生元数据漂移后，列表会显示 `invalid` 和问题数量。

规则配置使用 V2 逻辑字段结构保存，旧 compact/expanded 规则继续读取并在下次成功更新时升级；旧自由 SQL 规则只允许编辑或删除。

更多说明见 [全局检索](功能说明-全局检索.md)、[Retrieval 模块快速上手](../../03-架构设计/retrieval-module.md)和 [Retrieval REST API](../../05-API参考/控制器/RetrievalController.md)。

## 4. 前端 API 前缀

当前 `zenvis-frontend` 的 `VITE_BASE_URL` 统一为 `/`，前端和 AMIS/HTML 页面中的接口地址应使用：

```text
/api/...
```

不要再使用旧路径：

```text
/zenvis/api/...
```

开发环境中 Vite 代理 `/api`、`/system-files`、`/html-page` 到后端。生产环境 Nginx 也应保持同样的根路径代理约定。

更多说明见 [部署配置](../../02-快速开始与部署/deployment.md)。
