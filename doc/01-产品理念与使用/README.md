# 产品理念与使用

ZenVis 是面向企业数据分析场景的配置化应用框架。它把数据接入、元数据建模、检索统计、可视化、权限管理和受控 AI 能力组织在同一条可扩展链路中，使团队可以围绕业务数据和分析方法交付应用，而不必反复建设通用底座。

## 为什么设计 ZenVis

企业数据应用常见的问题不是缺少某一个页面，而是每个项目都要重新实现一整套接入、建模、查询、权限和展示链路：

- 字段和业务口径写死在代码中，模型变化会同时牵动数据库、接口和页面。
- 采集、检索、统计、看板和权限散落在多个系统，能力难以复用。
- 行业能力与平台代码强耦合，升级平台或交付新场景的成本很高。
- AI 能读取什么数据、调用什么工具、执行什么动作缺少明确边界。

ZenVis 的目标是把这些重复能力沉淀为稳定的平台契约，让业务差异通过配置、插件和受控工具表达。

## 设计理念

### 配置优先，Meta 驱动

实体、属性、操作符、显示规则和存储方式首先由 Meta 描述。统一检索、统计、详情和可视化能力消费同一份数据语义，减少多处重复定义和长期漂移。

### 通用能力平台化

平台负责会话、权限、菜单、配置、检索、看板、任务调度和运行观测等通用能力。业务团队只需要补充数据模型、接入规则、分析逻辑和页面体验。

### 插件作为交付单元

一个插件可以同时携带 Meta、推送任务、动态 API、数据库迁移、低代码页面、HTML 页面、看板、菜单、MCP、Skill 和文档。安装、升级、恢复和卸载围绕同一个能力包完成，避免业务扩展散落在平台工程中。

### 从数据到行动形成闭环

ZenVis 以一条连续链路组织产品能力：

```text
数据接入 → 元数据与存储 → 检索与统计 → 可视化与应用 → AI 分析与处置
                          ↑
                    插件化扩展
```

检索、图表和 AI 使用相同的实体与字段语义；分析结果可以继续生成报表、应用或配置，但写入动作必须进入明确的权限与审批流程。

### 权限、审批与审计优先

AI 并不天然拥有系统权限。业务 Agent 只能获得 Skill 声明范围内的 MCP 工具，工具再按 `ALLOW / ASK / DENY` 策略执行。需要确认的动作显示审批卡片，调用过程保留审计记录。

### 保持开放和可替换

数据接入、模型服务、业务应用和外部工具均通过明确接口连接。平台既提供默认实现，也允许团队替换组件或通过插件集成既有系统。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 实体（Entity） | 可检索的数据集合，对应一个业务对象和实际存储结构。 |
| 属性（Attribute） | 实体字段，定义类型、标签、显示、操作符、候选值和跳转行为。 |
| 操作符（Operator） | 检索条件支持的比较方式，例如等于、包含、区间和空值判断。 |
| 推送任务 | 由数据服务运行的数据采集、转换、路由和写入配置。 |
| 看板 | 内置组件、低代码页面、HTML 页面或外部链接形式的数据入口。 |
| 插件 | 可安装的业务能力包，可同时提供数据、API、UI、AI 工具和文档。 |
| Skill | 面向 Agent 的业务流程、提示词和可用工具范围声明。 |
| MCP 服务 | 向 Agent 暴露受策略控制工具的本地或外部服务。 |
| DIH | 数智中心，承载问答、业务 Agent、审批、后台任务和报表工作台。 |

## 适用场景

- 汇聚资产、设备、日志、网络流量、风险或业务事件并统一检索。
- 构建指标趋势、运行状态、异常发现和专题分析看板。
- 用低代码页面、HTML 页面或外链快速交付业务应用。
- 将行业数据模型、接入链路、页面和 AI 工具封装为插件。
- 通过自然语言完成知识问答、数据查询、受控工具调用和报表编写。
- 汇聚外部业务服务的实例心跳和重要事件。

## 产品边界

- ZenVis 是分析与数据应用框架，不替代 ERP、订单、财务等复杂交易系统。
- 平台不用于毫秒级实时控制、工业联锁或其他安全关键闭环。
- 高级检索只接受受限表达式，不允许任意 SQL、函数、子查询或注释拼接。
- 普通知识问答不调用 MCP；需要读取业务数据或执行动作时，应选择对应业务 Agent。
- AI 输出用于辅助分析。写入、安装、卸载和处置动作仍受用户权限、工具策略和审批约束。
- 插件页面是动态能力，具体使用说明由插件自己的 `README` 和 `00_doc` 维护。

## 用户角色

| 角色 | 典型职责 |
| --- | --- |
| 普通使用者 | 使用看板、检索和已授权的业务应用。 |
| 分析人员 | 使用数智中心、检索、数据可视化和报表能力。 |
| 业务管理员 | 管理业务数据接入、配置、看板和业务服务。 |
| 系统管理员 | 管理菜单、插件、Skill、MCP、RAG、用户和角色。 |
| 内置超级管理员 | 拥有全部菜单权限，并负责平台级初始化和高权限维护。 |

实际可见功能由角色菜单权限决定；文档中的“系统管理”操作默认要求相应管理权限。
