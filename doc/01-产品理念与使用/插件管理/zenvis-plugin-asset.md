# 资产管理

> 把主机、终端、IoT、移动端、探针、应用、服务、API、日志和文件资产统一到一个可检索、可治理的资产视图中。

## 用途与价值

企业资产信息经常散落在多个系统：服务器在 CMDB、终端在桌面管理系统、应用和 API 在研发平台，日志和文件又各有一套清单。结果是“有多少资产、谁负责、重要性如何、风险在哪”很难用一张图回答。

本插件用十类实体建立统一的资产底账，并为每类资产提供检索、详情、治理属性维护和跨实体 IP 调查能力：

- **统一分类**：硬件、软件和数据类资产使用一致的状态、归属、标签、重要等级和风险等级字段。
- **可治理**：支持上下线状态、重要性和风险等级维护，而不是只做静态清单展示。
- **可关联**：主机、PC、IoT 和移动端的内外网 IP 可以直接进入跨实体命中调查。

**适用对象**

- 资产管理员：维护资产底账、归属和生命周期状态。
- 安全运营人员：按重要性和风险等级筛选重点资产，结合 IP 做关联排查。
- 运维人员：查看服务器、服务、API 和日志资产的分布。

## 核心能力

- 十类 ClickHouse 实体，覆盖硬件资产、软件资产和数据资产。
- 统一的状态、归属、标签、访问性、重要等级、风险等级和扩展信息字段。
- 每类资产都有独立列表、详情页和治理属性维护入口。
- 资产规则配置：支持新增、更新、删除、批量操作和分页查询。
- 资产 IP 命中调查：按 IP 跨主机、PC、IoT 和移动端实体检索。
- 资产治理态势看板：展示总量、今日新增、在线资产、高风险资产、类型规模、近 7 日趋势、风险分布和生命周期状态。
- 内置资产模拟数据任务，安装后可快速验收页面。

## 数据与页面

**数据实体**

| 实体 | 说明 |
| --- | --- |
| `asset_host` | 主机资产 |
| `asset_pc` | PC 终端资产 |
| `asset_iot` | IoT 设备资产 |
| `asset_mobile` | 移动端设备资产 |
| `asset_probe` | 数据探针 SDK 资产 |
| `asset_app` | APP 应用程序资产 |
| `asset_service` | 系统服务资产 |
| `asset_api` | RESTful API 接口资产 |
| `asset_log` | 日志资产 |
| `asset_file` | 文件资产 |

每类资产由平台自动补充 `zenvis_id` 和 `zenvis_insert_time`；业务字段 `id` 是来源系统的资产标识，详情、修改和删除使用平台 `zenvis_id`。

**菜单与页面**

| 入口 | 类型 | 说明 |
| --- | --- | --- |
| 设备指纹策略 | 配置菜单 | 设备指纹相关配置入口 |
| 资管可视化配置 | 配置菜单 | 资产管理应用配置入口 |
| 资产管理 | 低代码应用 | 十类资产列表、详情和治理维护 |
| 资产 IP 命中调查 | 低代码页面 | 按 IP 跨实体检索 |
| 资产治理态势 | HTML 看板 | 资产规模、风险与生命周期总览 |

## 典型使用流程

1. 确认平台已有可用的 ClickHouse 数据源。
2. 在[插件管理](插件管理.md)中安装插件，确认十张表和模拟数据任务已创建。
3. 未接入真实数据时，先通过模拟任务检查列表、详情、治理编辑、IP 调查和看板。
4. 接入真实资产源时，按“来源 → Kafka → 校验转换 → ClickHouse”的两段式链路配置，并设置独立死信主题。
5. 为角色分配资产管理、IP 调查和配置菜单权限。
6. 正式数据验证通过后，在[数据推送服务](../服务管理/数据推送服务.md)中停止模拟数据任务。

## 注意事项

- 插件需要可用的 ClickHouse 数据源；安装前应确认连接参数。
- 内置模拟任务默认每 5 秒生成一条资产样例，只用于开发、演示和页面验收，不能作为生产数据接入方案。
- 真实资产源的生产接入协议、鉴权和样例报文尚未随插件固定，接入前需要按实际来源补充采集与转换配置。
- 资产规则表由插件 MySQL 迁移初始化；安装升级不会搬迁历史记录，卸载插件也不会删除该表。
- 聚合调查使用平台的实体统计接口，资产查询与修改统一走实体接口，不使用旧的核心资产路径。

安装、升级和卸载操作见[插件管理](插件管理.md)。
