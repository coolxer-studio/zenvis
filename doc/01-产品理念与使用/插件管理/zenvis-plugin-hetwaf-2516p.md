# 惠尔特 HET-WAF-2516P 防火墙

> 把惠尔特 HET-WAF-2516P 防火墙的 Syslog 日志接入 ZenVis，转化为可检索、可统计、可复盘的安全事件。

## 用途与价值

防火墙本地的日志通常只能逐条查看，难以跨时间检索，也不方便把攻击趋势、处置动作和客户端来源放在一起分析。本插件把设备日志拆成两类数据：

- **规则事件**：字段结构完整的 WAF 规则命中事件，按客户端 IP、请求域名、URL、检测类型、处置动作等字段结构化入库。
- **原始事件**：DDoS、未知格式或后续新增格式的消息，不强行拆字段，完整保留原文。

这样既能对常见攻击做精确检索和统计，又不会因为格式不匹配而丢失原始证据。

**适用对象**

- 安全运营人员：查看攻击事件、处置结果和高风险客户端。
- 网络与设备管理员：确认防火墙日志是否正常接入。
- 应急分析人员：按 IP、域名、检测类型回溯事件并保留原文。

## 核心能力

- 通过 UDP `12516` 接收防火墙 Syslog，端口和监听地址可配置。
- 校验发送端来源 IP，默认只接受指定 WAF 地址，可通过环境变量覆盖。
- 自动区分规则事件与原始事件，分别写入两张 ClickHouse 表。
- 解析失败、来源非法或结构异常的消息进入独立死信主题，不静默丢弃。
- 提供规则事件、原始事件的列表检索和按 `zenvis_id` 的独立详情页。
- 安全态势看板展示事件总量、今日事件、拒绝率、客户端 IP 与规则数、近 7 日趋势、处置动作、Top 客户端 IP、检测类型和最近事件。
- 内置可独立停止的演示数据任务，未接入真实设备时也能预览页面效果。

## 数据与页面

**数据实体**

| 实体 | 说明 | 主要用途 |
| --- | --- | --- |
| `het_waf_2516p_rule_event` | 规则事件 | 结构化检索、攻击统计、处置分析 |

## 典型使用流程

1. 在部署环境中为 `zenvis-service-vectum` 暴露 `12516/UDP`；Kubernetes 部署需同步暴露 UDP 端口。
2. 在防火墙上配置 Syslog 服务器地址，指向 ZenVis 的采集端口；插件不会自动修改设备配置。
3. 在[插件管理](插件管理.md)中安装插件，确认 Syslog 采集、Kafka 入库和演示数据三个任务的状态。
4. 发送一条真实 Syslog，核对规则事件表或原始事件表是否出现对应记录。
5. 打开低代码应用检索事件，并从看板确认趋势和分布。
6. 正式数据稳定后，在[数据推送服务](../服务管理/数据推送服务.md)中停止演示数据任务。

## 注意事项

- 默认只允许来源 IP `192.168.42.234` 的日志，接入其他设备前需通过 `HET_WAF_2516P_SOURCE_IP` 调整。
- Kafka 采用至少一次投递，插件不做去重，重放历史消息可能产生重复记录。
- 演示数据会写入正式原始主题并经过同一套校验链路，正式上线后应停止；停止任务不会删除已入库的演示数据。
- 插件负责采集、解析和展示，不负责修改防火墙、Kafka 或 ClickHouse 的部署参数。
- 首次部署后仍需用现场设备验证 Syslog 编码和字段结构。

安装、升级和卸载操作见[插件管理](插件管理.md)。
