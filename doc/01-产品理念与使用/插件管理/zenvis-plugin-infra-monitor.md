# 基础设施端点监测

> 把 ZenVis 部署内 MySQL、Redis、Kafka、ClickHouse 和 MinIO 的运行状态收拢到一块大屏，快速判断“哪个组件不正常、数据延迟多大”。

## 插件概览

| 项目 | 内容 |
| --- | --- |
| 插件名称 | 基础设施端点监测 |
| 包名 | `com.coolxer.plugin.infra.monitor` |
| 当前版本 | 1.0.0 |
| 插件形态 | 指标采集、归档与可视化型插件 |
| 数据实体 | 1 个：基础设施指标样本 |
| 主要入口 | 基础设施指标监控应用、基础设施指标大屏 |

## 用途与价值

平台由多个中间件组成，排查问题时经常需要逐个登录 Exporter 或监控端点查看指标，既慢又容易遗漏。本插件把六个组件的 Prometheus 指标统一采集、归档并展示：

- **统一状态**：用 `healthy`、`degraded`、`down` 三种状态表达组件是否正常。
- **可追溯**：指标样本写入 ClickHouse，页面展示的是已入库数据，不是实时直连端点。
- **可复制配置**：大屏可直接生成 Prometheus `scrape_configs`，方便接入外部监控。

**适用对象**

- 平台运维人员：日常巡检、故障定位和容量观察。
- 部署与交付人员：确认新环境中间件是否正常工作。
- 值班人员：通过数据延迟和状态快速判断采集链路是否中断。

## 核心能力

- 监测 MySQL、Redis、Redis-Stack、Kafka、ClickHouse 和 MinIO 六个组件。
- 每 30 秒并行抓取 Prometheus 指标，经 Kafka 归档到 ClickHouse。
- 展示组件状态、数据延迟、验证指标、最近入库时间和关键指标。
- 提供按服务、指标和时间筛选的历史样本列表与单条详情。
- 大屏包含 8 个 KPI、六个组件卡片、抓取配置弹窗、归档指标弹窗和数据链路说明。
- 支持手动刷新和默认 30 秒自动刷新，并处理加载、空数据和错误状态。
- 展示接口只聚合 ClickHouse 最新批次，不直接访问 Exporter 或指标端点。

## 典型使用流程

1. 确认部署环境已启用 MySQL、Redis、Redis-Stack 和 Kafka 的 Exporter，以及 ClickHouse、MinIO 的原生指标端点。
2. 在[插件管理](插件管理.md)中安装插件，确认两个推送任务已创建。
3. 在[数据推送服务](../服务管理/数据推送服务.md)中启用采集和入库任务。
4. 等待至少一个采集周期，打开“基础设施指标监控”或“基础设施指标大屏”查看状态。
5. 如需接入外部 Prometheus，在大屏“抓取配置”中复制配置并加入抓取任务。

## 注意事项

- 插件不启动 Prometheus，只负责从已有端点抓取；端点不可达时状态会显示为 `down`。
- 指标样本保留 30 天，过期数据会被 ClickHouse TTL 清理。
- 组件集合和关注指标白名单固定；新增服务需要同时修改采集任务、入库校验、展示接口和 Meta，并提升版本。
- MinIO 指标端点使用 public 认证，ClickHouse `9363/metrics` 也应只绑定可信网络；如果扩大监听范围，应增加认证或网络策略。
- Kafka 为至少一次投递，重试或重放可能产生重复样本；趋势分析时应按 `sample_id` 或聚合函数处理。
- 页面状态来自最近入库批次，采集任务停止后会在新鲜度阈值到期后显示 `down`。

安装、升级和卸载操作见[插件管理](插件管理.md)。
