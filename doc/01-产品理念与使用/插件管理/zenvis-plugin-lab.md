# 插件能力实验室

> 一个可安装、可运行的全栈插件样例，用双实体演示 ZenVis 插件从数据接入到 AI 能力的完整组合方式。

## 插件概览

| 项目 | 内容 |
| --- | --- |
| 插件名称 | 插件能力实验室 |
| 包名 | `com.coolxer.plugin.lab` |
| 当前版本 | 1.0.1 |
| 插件形态 | 全栈示例型插件 |
| 数据实体 | 2 个：实验室访问事件、实验室风险线索 |
| 主要入口 | 实验室应用、实验室 IP 关联调查、HTML 大屏、数据观察台 |

## 用途与价值

插件开发者经常需要回答一个问题：一个插件到底能交付哪些能力，这些能力之间如何配合？插件能力实验室把一个完整插件的各层能力放进同一个可运行示例：

```text
Meta 数据模型
  → 演示日志 → 双 Kafka Topic → 消费与死信
  → ClickHouse 实体数据
  → 低代码应用、详情页、IP 调查与看板
  → 动态 REST API、MySQL 迁移、MCP
  → RAG 数据集、知识库与 Skill
```

它不是单纯的字段清单，而是可以逐层观察、验证和替换的样例，适合用来学习插件结构，也适合作为交付前的安装验收对象。

**适用对象**

- 插件开发者：参考目录结构、数据模型、接入链路和页面组织方式。
- 平台交付人员：验证安装、升级、菜单、MCP、RAG 和 Skill 是否正常。
- 产品与测试人员：快速了解一个插件可以组合哪些平台能力。

## 核心能力

- 双实体 `lab_access_event` 与 `lab_risk_signal`，ClickHouse 表同名。
- `demo_logs` → 双 Kafka Topic → 双 Source 消费 → ClickHouse 的演示链路，并带统一死信。
- 动态笔记 REST API、MySQL 迁移、分页查询和状态统计。
- 四页低代码应用、两个实体详情页和跨实体 IP 调查页。
- HTML 实时大屏与低代码数据观察台。
- 三种菜单入口：配置、应用、独立页面。
- `lab` MCP 两个只读工具：能力目录与笔记检索。
- `lab-docs` 数据集、`lab-kb` 知识库和“插件能力实验室导览”Skill。

**菜单与页面**

| 入口 | 类型 | 说明 |

| 插件能力实验室数据观察台 | 低代码看板 | 数据观察与验证 |

## 典型使用流程

1. 在[插件管理](插件管理.md)中安装插件，确认两个推送任务和三种菜单入口已创建。
2. 确认“实验室演示数据生成”和“实验室 Kafka 接入与死信”任务生效。
3. 打开“插件能力实验室”，依次查看能力总览、访问事件、风险线索和实验室笔记。
4. 打开“实验室 IP 关联调查”，输入演示地址（如 `10.24.8.15`）做跨实体查询。
5. 在大屏看板中查看 HTML 大屏和低代码数据观察台。
6. 在 MCP 管理页确认 `lab` 服务发现两个只读工具，在 Skill 管理页检查导览 Skill。
7. 在 RAG 管理页确认 `lab-kb` 知识库状态。

## 注意事项

- 所有事件、IP、规则、风险分和笔记均为合成数据，IP 关联只演示查询方式，不代表真实攻击链或因果归属。
- 风险等级不是生产环境的安全结论，不能直接用于真实风险评估。
- MCP 只提供只读工具；笔记写入只通过 REST API 或低代码页面完成。
- 插件使用全新安装身份，不兼容旧 `com.coolxer.plugin.user.event`，也不复用旧实体、表、API 或菜单。
- 知识库构建依赖 Embedding 和 Redis；构建失败不会回滚插件安装，修复后可在 RAG 管理页手工重建。

安装、升级和卸载操作见[插件管理](插件管理.md)。
