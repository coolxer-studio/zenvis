# 运营分析

> 统一采集用户行为、性能与应用质量事件，帮助运营和研发从同一份数据中理解用户怎么用、应用跑得怎么样。

## 插件概览

| 项目 | 内容 |
| --- | --- |
| 插件名称 | 运营分析 |
| 包名 | `com.coolxer.plugin.operation` |
| 当前版本 | 1.0.0 |

| 主要入口 | 运营分析应用、运营 IP 命中调查、运营行为态势看板 |

## 用途与价值

用户行为数据往往分散在客户端埋点、服务端日志和性能监控系统中：运营能看点击量，研发能看崩溃率，但很难把一次用户旅程串起来。本插件把十类事件统一到同一套实体模型中，提供一致的检索、详情、统计和 IP 关联能力。

**它解决什么问题**

- 行为事件口径不一致，跨端分析需要反复对齐字段。
- 应用性能、崩溃和 ANR 与用户行为割裂，难以定位影响范围。
- 出现异常 IP 或网络问题时，缺少跨事件的关联入口。

**适用对象**

- 产品运营人员：分析功能使用、页面访问和用户路径。
- 客户端与前端研发：排查崩溃、无响应、网络请求和资源利用问题。
- 数据分析人员：基于统一实体做趋势、分布和聚合分析。

## 核心能力

- 十类 ClickHouse 实体覆盖用户行为、应用性能和异常事件。
- Meta 为不同字段类型声明检索操作符，并补充候选值映射、复制、自动补全、详情跳转和 IP 链接。
- 所有列表以 `zenvis_id` 为平台主键，按 `event_time` 倒序，详情通过实体接口精确查询。
- 概览页和“运营行为态势”HTML 看板调用真实实体分析接口，不使用静态图表数据。
- IP 命中调查覆盖各实体的 `lan_ip`、`wan_ip`，网络事件同时覆盖 `source_ip`、`target_ip`。
- 内置模拟数据任务，默认每 5 秒生成一条样例，便于安装后快速验收页面。

| 入口 | 类型 | 说明 |

## 典型使用流程

1. 在[插件管理](插件管理.md)中安装插件，确认推送任务和菜单已创建。
2. 未接入真实数据时，先保留模拟数据任务，检查列表、详情、IP 调查和看板是否正常。
3. 接入真实埋点或服务数据时，按插件契约配置采集与入库任务，并确认字段映射。
4. 为角色分配“运营分析”和“运营 IP 命中调查”菜单权限。
5. 正式数据验证通过后，在[数据推送服务](../服务管理/数据推送服务.md)中停止模拟数据任务。

## 注意事项

- 模拟数据任务直接写入 ClickHouse，只用于开发、演示和页面验收，不能替代生产采集链路。
- 模拟任务会持续增加记录，不需要时应及时停用。
- 页面中的统计结果来自已入库数据；采集任务停止后，概览和看板不会继续更新。

安装、升级和卸载操作见[插件管理](插件管理.md)。
