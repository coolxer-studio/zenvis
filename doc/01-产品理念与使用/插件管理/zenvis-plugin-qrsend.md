# QRSend 二维码离线传输

> 用屏幕和摄像头在两台设备之间传输文本、文件或文件夹，不需要网络、账号或配对服务器。

## 插件概览

| 项目 | 内容 |
| --- | --- |
| 插件名称 | QRSend 二维码离线传输 |
| 包名 | `com.coolxer.plugin.qrsend` |
| 当前版本 | 1.0.0 |
| 插件形态 | 纯前端静态工具插件（HTML 页面） |
| 数据实体 | 无 |
| 主要入口 | 左侧菜单“二维码离线传输” |

## 用途与价值

在隔离网、内外网之间、临时工位或无法建立数据通道的场景中，传一个文件往往比想象中麻烦。QRSend 把数据切分、压缩并做喷泉编码（RaptorQ），发送端在屏幕上持续播放二维码流，接收端用摄像头读取任意足够大的子集即可重建原始数据：

- **不依赖网络**：整条链路只经过屏幕和摄像头。
- **可以中断和续传**：接收端给出 resume code，发送端只补发缺失部分。
- **抗丢帧**：漏读部分二维码不影响最终结果。
- **本地处理**：数据在浏览器私有存储中流式读写，不上传服务器。

**适用对象**

- 隔离环境运维人员：在不能联网的设备之间传递配置、日志或工具。
- 现场交付人员：临时把文件从一台设备传到另一台设备。
- 安全分析人员：需要避免经过第三方服务器的场景。

## 核心能力

- 支持文本、文件和文件夹传输。
- RaptorQ 喷泉编码，任意足够大的符号子集即可重建数据。
- 摄像头实时扫描、已录制视频、屏幕捕获三种接收方式。
- 断点续传：通过 `QSR1-XXXXXXXX` 形式的 resume code 补发缺失数据。
- 设备配对与端到端加密（age），每个分段和文件使用 BLAKE3 校验。
- 双向反馈、局域网加速、彩色码、每帧多个二维码等可选能力。
- 浏览器 OPFS 流式存储，大文件不占满内存。
- 中英双语界面，跟随浏览器语言并可手动切换。

## 数据与页面

本插件不定义 Meta 实体、不创建 ClickHouse 表、不配置推送任务，也不提供看板。

| 入口 | 类型 | 说明 |
| --- | --- | --- |

页面内包含发送、接收、收件箱、设备、功能预览和存储等子页面。

## 典型使用流程

1. **发送**：进入“发送”，选择文本、文件或文件夹；如有需要，选择加密到已信任设备。
2. **接收**：在另一台设备进入“接收”，用摄像头对准发送端屏幕，或选择已录制视频、屏幕捕获。
3. **续传**：接收端提示缺少数据时，复制 resume code 并在发送端填入，发送端只补发缺失部分。
4. **配对（可选）**：在“设备”中互相添加设备 ID 并核对指纹，之后可做端到端加密传输。
5. **高级能力**：在“功能预览”中按需开启双向传输、自动调速、声音反馈、局域网加速、彩色码等实验特性。

## 注意事项

- QRSend 依赖安全上下文才能使用 WebCrypto、OPFS 和 Service Worker，建议通过 HTTPS 或 localhost 访问；明文 HTTP 的局域网 IP 访问会导致加密、设备配对和大文件流式存储不可用。
- 实时扫描需要授予摄像头权限；被拒绝时可改用“从视频文件接收”或“从屏幕捕获接收”。
- 传输内容在浏览器本地处理，不经过 ZenVis 服务端，也不写入平台存储。
- 卸载插件不会清除浏览器中的 OPFS、IndexedDB 和 localStorage 残留；如需彻底清理，可在“存储”页面删除，或清理站点数据。
- 上游 QRSend 仍处于早期版本，不同版本之间的互通以随包资源为准。
- 高级能力默认关闭，建议在实际场景中逐步开启并验证。

安装、升级和卸载操作见[插件管理](插件管理.md)。
