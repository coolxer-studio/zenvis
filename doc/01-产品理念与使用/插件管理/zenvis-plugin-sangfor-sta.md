# 深信服 STA 潜伏威胁探针

> 对接深信服 STA 潜伏威胁探针 V2.0 的 55 类日志，把流量、协议审计和安全事件统一入库、检索和关联调查。

## 插件概览

| 项目 | 内容 |
| --- | --- |
| 插件名称 | 深信服 STA 潜伏威胁探针 |
| 包名 | `com.coolxer.plugin.sangfor.sta` |
| 当前版本 | 1.0.0 |
| 插件形态 | 探针日志接入与分析型插件（Kafka → ClickHouse） |
| 数据实体 | 55 个，覆盖流量日志、47 类协议审计和 4 类安全日志 |
| 主要入口 | 深信服 STA 应用、STA IP 关联调查、深信服 STA 配置 |
| 安装包 | [com-coolxer-plugin-sangfor-sta-1.0.0.tar.gz](https://gitee.com/coolxer-studio/zenvis/releases/download/zenvis-plugin-1.0.0/com-coolxer-plugin-sangfor-sta-1.0.0.tar.gz) |

## 用途与价值

STA 探针会产生大量协议级审计数据，单类日志字段多、类型差异大。如果只把原始 JSON 堆在一边，很难回答“某个 IP 访问了哪些协议”“某类安全事件集中在哪些资产”等问题。

本插件按日志类型建立 55 个实体和 55 张表，每类日志一一对应一个 Kafka 路由和一个转换器：

- **流量与协议可检索**：网络流量、TCP/UDP、HTTP、DNS、数据库、文件传输、邮件、远程登录等协议审计都能按字段筛选。
- **安全事件可统计**：WAF、IPS、UTM、PVS 安全日志与流量日志放在同一套模型下。
- **跨实体可关联**：通过源 IP 和目的 IP 在 50 类主要实体之间做关联统计。

**适用对象**

- 安全运营人员：查看威胁事件、协议分布和高风险 IP。
- 网络分析人员：审计内网协议使用、文件传输和登录行为。
- 应急响应人员：按 IP 跨协议回溯资产行为。

## 核心能力

- 消费 STA 写入 Kafka 的原始日志，按 `logtype` 路由到 55 类实体。
- 字段名统一为小写 snake_case，再按目标实体严格校验必填字段、数量、类型、时间和枚举。
- 每类日志对应独立的 ClickHouse 表，字段完整保留。
- 未知 `logtype` 和校验失败记录进入独立死信主题，不静默丢弃。
- 低代码应用提供接入总览、4 类流量日志、47 类协议审计和 4 类安全日志页面。
- 接入总览展示近 7 天流量趋势、应用协议占比、网络动作占比、Top 10 源 IP 和安全日志分布。
- STA IP 关联调查按源 IP 和目的 IP 跨 50 类主要实体统计。
- 每个实体都有独立列表页和基于 `zenvis_id` 的详情页，IP 字段可直接跳转调查页。
- 内置可独立停止的演示数据任务，设备未接入时也能预览页面。

## 数据与页面

**数据实体（按类别）**

| 类别 | 数量 | 示例 |
| --- | --- | --- |
| 流量日志 | 4 | 网络流量、IP 日志、TCP 日志、UDP 日志 |
| 协议审计 | 47 | HTTP、DNS、FTP、SMB、SSH、RDP、数据库登录、邮件、文件审计等 |
| 安全日志 | 4 | WAF、IPS、UTM、PVS |

所有实体使用 `sangfor_sta_<logtype>` 命名，数据表使用 `zenvis.t_sangfor_sta_<logtype>`。

**菜单与页面**

| 入口 | 类型 | 说明 |
| --- | --- | --- |
| 深信服 STA 配置 | 配置菜单 | 插件配置入口 |
| 深信服 STA 潜伏威胁探针 | 低代码应用 | 接入总览与 55 类日志列表、详情 |
| STA IP 关联调查 | 低代码页面 | 按源 IP、目的 IP 跨实体统计 |

本插件不注册独立 HTML 看板，接入总览由低代码应用提供。

## 典型使用流程

1. 确认 STA 设备已把日志写入 Kafka，并确认 ZenVis 可以读取对应主题。
2. 在[插件管理](插件管理.md)中安装插件，确认 55 个实体、数据表和两个推送任务已创建。
3. 检查“深信服 STA Kafka 校验转换入库”任务状态；设备未接入时可先观察演示数据任务。
4. 等待消息经正式链路入库后，打开低代码应用查看总览和各类日志列表。
5. 在 IP 关联调查中输入源 IP 或目的 IP，查看跨协议命中情况。
6. 正式设备接入并验证数据正常后，在[数据推送服务](../服务管理/数据推送服务.md)中停止演示数据任务。

## 注意事项

- 仅支持 STA 主动写入 Kafka 的模式，不包含 SFTP 文件落地、Syslog 接收或设备 API 拉取。
- 插件按参考实现要求 55 类日志字段完整存在；缺失可选字段也会进入死信，部署前应核对设备固件版本。
- 演示任务默认向正式源主题写入数据，正式上线后必须手动停止，避免演示数据与真实设备数据混合。
- 停止演示任务不会删除已入库数据，也不影响正式入库任务的消费组和表结构。
- 源接口中的 Base64 内容保持原值，插件不做解码。
- 插件不依赖 OneSOC，可与其同时安装，但不与 OneSOC 共用实体、表、ID 或 UI 配置。
- 静态构建通过不代表目标环境联调通过，上线前仍需用现场 Kafka 和 ClickHouse 验证。

安装、升级和卸载操作见[插件管理](插件管理.md)。
