# 智能体安全监测

> 接入智能体安全事件与会话消息，定位提示注入、越狱、敏感数据外泄等风险，并还原完整的会话现场。

## 用途与价值

智能体应用的风险不只在单次请求：一次提示注入可能跨越多轮对话，敏感数据也可能在会话过程中逐步泄露。本插件同时接入两条上游流：

- **Sentinel 安全事件流**：记录提示注入、越狱、敏感数据、资源攻击、越界请求和数据外渗等命中结果。
- **Warden 会话流**：记录会话的开始、追加、快照和改写事件，用于还原消息线。

两条流通过 `message_id` / `msg_hash` 关联，既能看“哪里命中了风险”，也能回到“当时的完整会话是什么样”。

**适用对象**

- AI 应用安全运营人员：跟踪风险命中、趋势和高风险会话。
- 智能体研发人员：复盘会话现场，定位提示词或工具调用问题。
- 安全分析人员：借助只读 Skill 做证据化研判。

## 核心能力

- 直接消费 `ai-agent-security-result` 与 `ai-agent-chat-message` 两个上游主题，不额外转存 Kafka。
- 对安全事件和会话事件分别做协议校验、字段转换和异常隔离，失败消息进入独立死信主题。
- 安全事件列表与详情：展示判定、请求与会话、命中文档、规则、证据和 1.1 字段。
- 会话事件列表与详情：展示会话上下文、消息数组、改写记录和请求头快照。
- 按 `session_id` 重建会话消息线，合并 started / append / snapshot / mutation 事件。
- 安全态势总览：展示两类事件的累计与今日量、趋势、类型分布、会话覆盖和消息规模。
- 提供三个只读 AI Skill，分别用于安全事件分析、安全态势分析和会话现场分析。

## 典型使用流程

1. 在[插件管理](插件管理.md)中安装插件，确认两个 Meta 实体和推送任务已创建。
2. 在[数据推送服务](../服务管理/数据推送服务.md)中手动启用“Sentinel安全事件解析入库”和“Sentinel会话事件解析入库”两个任务。
3. 在[角色管理](../系统管理/角色管理.md)中分配菜单；会话事件包含消息原文，应只授权给必要的角色。
4. 从安全事件列表检索风险命中，打开详情查看判定和证据。
5. 点击关联的 `session_id` 进入会话现场，按时间线还原会话过程。
6. 需要自然语言分析时，在数智中心使用对应的只读研判 Skill。

## 注意事项

- 插件**不会阻断或改写**请求。上游的 `action` 是策略建议动作，不代表请求已经被拦截。
- 会话事件包含消息原文，可能含敏感内容；页面和 Skill 均为只读，访问范围仍需由角色权限和数据治理要求控制。
- 两条流均为至少一次投递，插件入库不主动去重；安全事件按 `event_id`、会话事件按幂等键在查询和重建时处理重复。
- `started` 事件上游没有独立 ID，多实例同时首见时可能重复，消息线重建会按类型和会话 ID 兜底去重。
- 两张 ClickHouse 表按 `zenvis_insert_time` 月分区，行级 TTL 为 90 天；调整 TTL 可能导致历史数据删除。
- 插件不提供外部 MCP 连接和写操作，三个 Skill 均为只读检索。

安装、升级和卸载操作见[插件管理](插件管理.md)。
