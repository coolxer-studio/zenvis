# MCP 服务

## 功能定位

MCP 服务用于统一管理 AI 可调用的工具服务、调用策略、审批队列和审计记录。它把外部能力接入与权限控制放在同一处，使 AI 的工具调用可配置、可审批、可追踪。

## 进入方式

使用具备系统管理权限的账号登录，依次进入 **系统管理 → MCP 服务**。

## 页面说明

![MCP 服务主界面](../_images/系统管理/MCP服务-主界面.png)

页面围绕四类信息组织：

- 服务与工具：查看已接入的 MCP 服务以及每个服务提供的工具。
- 调用策略：按工具设置允许、需要审批或拒绝。
- 审批队列：处理待确认的高风险调用。
- 调用审计：追踪调用方、参数摘要、执行结果和时间。

页面还提供面向 AI 的工具提示配置，用于说明工具的用途与约束。

## 核心操作

1. 查看服务连接状态和已发现的工具，确认能力边界。
2. 按工具风险设置 `ALLOW`、`ASK` 或 `DENY` 策略。
3. 对需要人工确认的请求，在核对调用目的和影响后处理审批。
4. 通过审计记录排查失败调用、异常参数和权限问题。
5. 优化工具提示，使 AI 能正确判断何时以及如何使用工具。

## 权限与约束

- MCP 配置、策略和审批属于高权限操作，仅授权管理员可执行。
- `ALLOW` 适合低风险、可回滚的只读调用；有外部写入或明显副作用的工具应优先使用 `ASK`。
- 审批只针对一次具体调用，不能替代底层系统自身的身份认证和权限控制。
- 页面或日志中不应展示密码、Token、模型密钥等敏感信息。

## 常见问题

### 服务在线但 AI 为什么不能调用某个工具？

依次检查工具是否被发现、策略是否为允许或需要审批、当前请求是否仍在审批队列，以及底层服务是否接受当前身份。

### 为什么调用一直显示等待？

如果策略为 `ASK`，调用会等待有权限的管理员处理审批；同时检查审批是否过期或底层连接是否中断。
