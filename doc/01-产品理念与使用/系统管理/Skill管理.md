# Skill 管理

## 功能定位

Skill 管理用于发现、查看和启停平台 AI Skill。Skill 以标准目录和 `SKILL.md` 描述一组可复用的任务能力，为知识问答、数据接入、数据可视化和报表制作等 AI 工作流提供明确的操作边界。

## 进入方式

使用具备系统管理权限的账号登录，依次进入 **系统管理 → Skill 管理**。

## 页面说明

页面以列表或卡片展示已扫描到的 Skill、来源、启用状态和说明，并提供查看详情、启用或停用、重新加载等操作。内置 Skill 会与数智中心中的相应入口协同工作。

## 操作前检查

- 阅读完整 `SKILL.md`，核对适用范围、依赖、工具访问和潜在写入动作。
- 第三方 Skill 先在隔离环境验证，不要只根据名称或简介启用。
- 停用前确认没有运行中的 AI 分析任务依赖该 Skill。

## 核心操作

1. 查看 Skill 详情和 `SKILL.md`，确认适用任务、输入输出与执行约束。
2. 启用经过验证且需要投入使用的 Skill；停用暂不允许被 AI 调用的能力。
3. Skill 文件发生合规更新后，使用重新加载刷新平台识别结果。
4. 调试 AI 任务时，结合具体入口的提示信息确认实际使用了哪个 Skill。

## 结果确认

- 重新加载后列表显示正确来源、说明和启用状态。
- 对应数智中心入口能发现已启用 Skill，停用项不再被新任务选择。
- 实际工具调用仍遵守 MCP 策略，没有因启用 Skill 获得额外权限。

## 权限与约束

- Skill 状态影响 AI 可调用能力，仅管理员可以调整。
- Skill 只是任务规范和能力封装，不会绕过用户权限、MCP 工具策略或审批流程。
- 修改 Skill 源文件属于部署与开发工作，不在本页面内完成。
- 启用第三方 Skill 前应审查其指令、依赖、数据访问范围和潜在副作用。

## 常见问题

### 新增的 Skill 为什么没有出现在页面中？

确认目录结构和 `SKILL.md` 是否符合约定，然后执行重新加载；如仍未识别，检查部署目录和系统日志。

### 停用 Skill 后会删除文件吗？

不会。停用只改变平台是否允许使用该能力，不等同于删除 Skill 文件。
