# 备份与恢复

备份只有经过读取校验和恢复演练后才可信。`deploy/backups/` 是本机暂存区，不是异地备份系统。

## Compose 备份

```bash
./zenvisctl compose backup
```

工具会短暂停止服务，创建一致性冷备，然后恢复原先运行的服务。每份备份位于 `deploy/backups/compose-<时间>/`，包含：

- `payload.tar.gz`：`.env`、Compose 文件、应用配置、开放配置和数据目录；
- `manifest.env`：版本、架构和创建时间；
- `compose-config.yml`、`images.txt`：当时的渲染配置与镜像信息；
- `running-services.txt`：备份前运行的服务。

检查并异地复制：

```bash
tar -tzf deploy/backups/<备份ID>/payload.tar.gz
```

恢复使用[升级与回滚](升级与回滚.md#compose-回滚)中的显式回滚命令。不要只解压数据库子目录，也不要在数据库运行时覆盖其内部文件。

## Kubernetes 应用数据备份

生产集群先完成外部依赖备份，再执行：

```bash
./zenvisctl k8s backup \
  --external-ref backup://change-20260731-001 \
  --namespace zenvis-prod \
  --release zenvis \
  -f /secure/path/zenvis-production.yaml
```

本地备份包含开放配置、Vectum 工作区、Helm 状态、资源清单和外部备份引用。应用卷导出依赖 Pod 可运行；若 Pod 已损坏，应使用存储系统快照或从 PVC 修复 Pod 导出。

## 外部依赖责任

| 依赖 | 备份要求 |
| --- | --- |
| MySQL | 一致性逻辑/物理备份，记录 binlog 或时间点恢复位置 |
| ClickHouse | 使用 ClickHouse Backup、磁盘快照或云服务备份，并验证表和分区 |
| Redis / Redis Stack | RDB/AOF 或受管服务快照；向量索引应确认可重建性 |
| Kafka | 根据保留策略备份关键 topic，或保证数据源可重放 |
| PVC | 使用 CSI VolumeSnapshot 或存储平台快照作为第二恢复路径 |

## 恢复演练

至少每季度在隔离环境演练一次：

1. 校验备份清单、压缩包和外部备份引用。
2. 恢复到与原环境隔离的主机或 Namespace。
3. 使用备份中的固定版本启动，不先升级。
4. 验证账号、Meta、页面、插件、数据量、检索、任务和 AI 配置。
5. 记录实际 RPO、RTO、失败点和改进项。

备份保留周期由数据级别决定；至少同时保留近期备份、升级前备份和异地副本，并对 `.env`、Secret 导出物和备份目录实施加密与访问审计。
