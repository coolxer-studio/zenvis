# 配置参考

## Compose 配置来源

`deploy/.env.example` 是可提交的字段模板，`./zenvisctl compose init` 生成实际的 `deploy/.env`。Compose 使用 `deploy/config/` 中的应用配置，通过环境变量注入敏感值。

### 基础参数

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `ARCH` | 镜像架构，只支持 `amd64`、`arm64` | 自动检测 |
| `TZ` | 容器时区 | `Asia/Shanghai` |
| `ZENVIS_VERSION` | 后端和前端镜像标签 | `latest` |
| `VECTUM_VERSION` | Vectum 独立镜像标签 | `latest`（本次部署模板固定为 `1.0.1`） |
| `ZENVIS_IMAGE_REGISTRY` | 镜像仓库前缀 | 项目默认仓库 |
| `ZENVIS_WEB_BIND_ADDRESS` | Web 监听地址 | `0.0.0.0` |
| `ZENVIS_API_BIND_ADDRESS` | API 监听地址 | `127.0.0.1` |
| `ZENVIS_INFRA_BIND_ADDRESS` | 数据库和中间件监听地址 | `127.0.0.1` |
| `ZENVIS_WEB_PORT` | Web 主机端口 | `11000` |
| `ZENVIS_API_PORT` | API 主机端口 | `11001` |
| `VECTUM_PORT` | Vectum 主机端口 | `11002` |

三个监听地址和三个主机端口必须在 `deploy/.env` 中显式保留；`./zenvisctl compose init` 会从模板写入上表默认值，并为升级前已存在的 `.env` 自动补齐缺失项。

### 凭据参数

以下字段不可为空，由 `init` 独立随机生成：

- `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`CLICKHOUSE_PASSWORD`、`REDIS_PASSWORD`、`MINIO_ROOT_PASSWORD`；
- `KAFKA_CLUSTER_ID`；
- `API_BEARER_TOKEN`、`MCP_BEARER_TOKEN`、`VECTUM_AUTH_TOKEN`；
- `ZENVIS_BOOTSTRAP_SUPER_ADMIN_PASSWORD`、`ZENVIS_BOOTSTRAP_ADMIN_PASSWORD`。

初始化账号变量只在账号不存在时使用。更改 `.env` 中的值不会重置已有用户密码。API Bearer Token 默认映射到 `API_BEARER_USER=admin@admin.com`，该用户必须存在且具备目标接口权限。

### 对象存储参数

后端按业务域使用四个独立 MinIO Bucket，通用附件接口只允许访问默认 Bucket：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `MINIO_BUCKET` | `zenvis-attachments` | 通用附件与 `/api/v1/minio` 接口 |
| `MINIO_RAG_BUCKET` | `zenvis-rag` | RAG 原文、插件数据集 |
| `MINIO_CHAT_BUCKET` | `zenvis-chat` | 聊天附件 |
| `MINIO_PLUGINS_BUCKET` | `zenvis-plugins` | 插件包、升级候选和版本快照 |
| `MINIO_REPORTS_BUCKET` | `zenvis-reports` | 报表修订正文和 DOCX/PDF 导出 |

默认 Bucket 和四个业务 Bucket 名称必须非空，默认 Bucket 不得与业务 Bucket 重复，四个业务 Bucket 之间也必须互不重复。后端启动时会自动创建缺失的 Bucket，创建失败、MinIO 不可达或对象缺失时直接返回错误，不采用本地文件、默认 Bucket 或 MySQL 正文降级。下载仍经过后端鉴权接口，不签发预签名 URL。通用 `/api/v1/minio` 接口拒绝指定四个业务 Bucket。

对象键布局固定如下，业务代码不得自行拼接未经校验的路径：

| 业务域 | 对象键 |
| --- | --- |
| RAG 公共数据集 | `rag/datasets/{datasetId}/...` |
| RAG 插件数据集 | `rag/plugins/{packageName}/{datasetCode}/{operationId}/...` |
| 聊天附件 | `chat/{userId}/{fileId}/{sanitizedFileName}` |
| 插件正式包 | `packages/{packageName}/{sha256}.tar.gz` |
| 插件升级候选/快照 | `upgrades/{packageName}/{operationId}/candidate.tar.gz`、`snapshot.tar.gz` |
| 报表修订正文 | `documents/{documentId}/revisions/{revision}/content.{md|html}` |
| 报表导出 | `documents/{documentId}/revisions/{revision}/exports/v1/{format}/{exportHash}.{docx|pdf}` |

本次迁移不提供存量回填和旧路径兼容：旧聊天附件、旧 RAG 数据集、旧插件记录和旧报表修订按新边界处理。插件需要重新上传并安装，RAG 数据集需要重新创建或导入，报表修订需要在新对象布局下重新生成。

### AI 参数

AI 能力可选。未启用时保持 `APP_AI_EMBEDDING_ENABLED=false`，相关地址、密钥和模型可以为空。启用时按服务提供方填写：

- `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_CHAT_MODEL`；
- `OPENAI_EMBEDDING_BASE_URL`、`OPENAI_EMBEDDING_API_KEY`、`OPENAI_EMBEDDING_MODEL`；
- `OPENAI_COMPLETION_URL`、`OPENAI_COMPLETION_MODEL`。

修改嵌入模型或向量维度后，需要重建 Redis Stack 中对应的向量索引。模型服务必须使用与 OpenAI API 兼容的协议。

内置 MCP 固定拆成 `retrieval`、`config`、`push-task`、`visualization` 和
`analysis-task` 五个服务，统一使用 `MCP_BEARER_TOKEN`。部署配置中的
`app.ai.mcp.builtin-server.version`、`request-timeout` 和 `keep-alive-interval` 可调整
协议版本信息与超时；服务 code、分组和 `/mcp/{serviceCode}/...` 端点不可动态修改。

### 持久化智能体任务

DIH 业务 Agent 统一使用持久化 Agent Run。默认启用全部业务 Agent 类型；白名单和禁用名单只用于灰度发布与应急回滚。部署层变量如下：

| 变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `APP_AI_AGENT_RUN_ENABLED` | `true` | 持久化 Agent Run 总开关 |
| `APP_AI_AGENT_RUN_ENABLED_TYPES` | `*` | 允许创建 Run 的 Agent 类型；`*` 表示全部，多个值用逗号分隔 |
| `APP_AI_AGENT_RUN_DISABLED_TYPES` | 空 | 临时禁用的 Agent 类型，多个值用逗号分隔；优先级高于启用范围 |
| `APP_AI_AGENT_RUN_MAX_CONCURRENCY` | `4` | 单实例并发执行的 Run 数 |
| `APP_AI_AGENT_RUN_DISPATCH_DELAY_MS` | `1000` | 调度扫描间隔 |
| `APP_AI_AGENT_RUN_LEASE_SECONDS` | `60` | worker 租约时长；心跳按租约比例续期 |
| `APP_AI_AGENT_RUN_MAX_STEPS` | `30` | 单个 Run 默认决策步数上限 |
| `APP_AI_AGENT_RUN_MAX_DURATION_SECONDS` | `1800` | 单个 Run 默认有效执行时长；等待审批不计时 |
| `APP_AI_AGENT_RUN_MAX_TOOL_CALLS` | `80` | 单个 Run 跨步骤累计工具调用上限 |
| `APP_AI_MCP_APPROVAL_TIMEOUT_SECONDS` | `300` | 普通同步审批超时；Run 审批固定使用 24 小时窗口 |

被禁用或未包含在显式白名单中的 Agent 继续使用旧单轮流式路径。前端在 Run 创建返回 `503` 时会自动回退，但正常产品能力不应依赖回退路径。

内置示例提示词是确定性演示夹具，不属于真实业务任务；它们仍优先走示例流式链路，不创建 Run。直接向 Run API 提交示例时会返回 `503`，客户端应回退到聊天示例链路。

升级到包含 Agent Run 的版本时，需要同时部署数据库初始化 SQL 和后端代码。新增表为 `t_ai_agent_run`、`t_ai_agent_run_event`、`t_ai_agent_run_input` 和 `t_ai_report_draft`；已有会话与 MCP 调用记录通过可空列兼容，不需要回填历史数据。

## Helm values

| 配置段 | 说明 |
| --- | --- |
| `global` | 镜像仓库、ZenVis 固定版本、架构、时区、拉取策略与 pull secret |
| `secrets.existingSecret` | 已存在的凭据 Secret |
| `persistence` | 应用卷和内置依赖卷的 StorageClass 与容量 |
| `backend`、`frontend`、`vectum` | 单副本、镜像名、资源 requests/limits 与 Service；`vectum.image.version` 默认为 `latest` |
| `embedded` | 是否在集群内部署五种依赖 |
| `external` | 外部 MySQL、ClickHouse、Redis、Kafka 与 MinIO 地址；`external.minio.buckets` 配置四个业务 Bucket |
| `ingress` | 域名、IngressClass 和 TLS Secret |
| `networkPolicy` | 是否启用基础 NetworkPolicy |

`values-dev.yaml` 打开所有内置依赖；本次开发和生产部署模板都将 Vectum 版本固定为 `1.0.1`。`values-production.example.yaml` 展示外部依赖配置。生产文件应放在安全路径，不要提交包含内网地址或凭据的副本。

Helm 只接入外部 MinIO，不包含内置 MinIO 模板。`external.minio.endpoint` 必填，`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD` 由 `secrets.existingSecret` 注入；该账号必须有权访问并创建默认 Bucket 和四个业务 Bucket。

## 修改原则

- 先运行 `doctor` 或 `helm lint`，再应用变更。
- 镜像版本必须与数据迁移兼容，生产环境禁用浮动标签。
- 不修改持久化目录中的数据库内部文件；使用应用或数据库提供的迁移机制。
- 不在 Nginx、properties、Compose、values 或文档中硬编码密码和令牌。
