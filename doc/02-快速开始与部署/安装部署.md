# 安装部署

## 部署拓扑

`zenvis-backend/deploy/docker-compose.yml` 提供完整环境编排：

当前编排使用 Kafka 4.2.0、MySQL 8.4、ClickHouse 25.9、Redis 7 和 Redis Stack 7.2.0-v18 镜像；前后端与 Vectum 使用与 `ARCH` 对应的当前镜像。这里记录的是仓库现状，不代表对未来版本的最低兼容承诺。

| 服务 | 宿主端口 | 数据用途 |
| --- | ---: | --- |
| `zenvis-frontend` | 11000 | Web 控制台与 `/zenvis` 反向代理 |
| `zenvis-backend` | 11001 | REST API、Swagger、MCP Server 与静态资源 |
| `vectum-service` | 11002 | 数据推送任务管理与运行 |
| `mysql-service` | 3306 | 平台配置和事务数据 |
| `clickhouse-service` | 8123、9000、9009 | 分析数据 HTTP、Native 与集群通信 |
| `redis-service` | 6379 | Session 与缓存 |
| `redis-stack-service` | 16379 | 向量索引 |
| `kafka-service` | 9094 | 宿主机访问 Kafka；容器内使用 9092 |

所有容器加入 `zenvis-network`。前端 Nginx 把 `/zenvis/` 去除前缀后转发到后端 `11001`。

## 准备配置

### 架构

部署目录的 `.env` 使用 `ARCH` 选择镜像架构。应根据主机设置为部署镜像支持的值，例如 `amd64` 或 `arm64`。

### 必须设置的凭据

生产部署至少应显式配置：

| 环境变量 | 用途 |
| --- | --- |
| `MYSQL_PASSWORD` | ZenVis MySQL 用户密码 |
| `CLICKHOUSE_PASSWORD` | ClickHouse `default` 用户密码 |
| `REDIS_PASSWORD` | Redis 与 Redis Stack 密码 |
| `API_BEARER_TOKEN` | 普通 REST API Bearer Token |
| `API_BEARER_USER` | Bearer Token 映射的有效 ZenVis 用户邮箱 |
| `MCP_BEARER_TOKEN` | MCP Server SSE/消息接口 Token |
| `VECTUM_AUTH_TOKEN` | 后端调用 Vectum 的 Token |
| `OPENAI_BASE_URL` | OpenAI 兼容服务地址 |
| `OPENAI_API_KEY` | 模型服务 Key |
| `OPENAI_CHAT_MODEL` | 默认聊天模型 |

不要在生产环境使用仓库示例默认值。更换模型或 embedding 维度后，需要按新模型重建 Redis 向量索引。

### 应用配置目录

后端通过 `app.paths.*` 使用统一配置根目录，主要子目录为：

| 路径 | 作用 |
| --- | --- |
| `web_config` | 系统信息和前端资源 |
| `html-page_config` | HTML 页面资源 |
| `plugin-package_config` | 已安装插件 |
| `skill_config` | AI Skill |
| `dih-session-workspace` | 会话附件与工作区 |
| `meta_config` | Retrieval Meta |

生产容器把部署目录中的 `open_config` 挂载到后端配置路径。升级前应备份此目录。

## 容器部署

### 启动

```bash
cd zenvis-backend/deploy
docker compose pull
docker compose up -d
docker compose ps
```

建议按以下顺序排查启动状态：

1. MySQL、ClickHouse、Redis、Redis Stack；
2. Kafka 与 Vectum；
3. ZenVis Backend；
4. ZenVis Frontend。

### 健康检查

```bash
curl http://localhost:11001/actuator/health
curl http://localhost:11001/api/v1/system/about/info
curl -I http://localhost:11000
```

Compose 中后端容器实际使用 `/api/v1/system/about/info` 判活；`/actuator/health` 和 `/actuator/info` 仍作为诊断端点暴露。前端容器检查根路径，Vectum 检查自身 `/actuator/health`。

### 日志

```bash
docker compose logs -f --tail=200 zenvis-backend
docker compose logs -f --tail=200 vectum-service
docker compose logs -f --tail=200 clickhouse-service
```

Docker 日志配置了滚动限制，但 ClickHouse、MySQL、Kafka 和应用数据目录仍需独立容量监控。

### 升级

1. 备份 MySQL、ClickHouse 和 `open_config`。
2. 阅读版本变更，确认插件迁移与配置兼容性。
3. 拉取或构建新镜像。
4. 先升级后端，再升级插件和前端。
5. 检查健康状态、Swagger、登录、检索、看板与推送任务。

插件已经执行的 MySQL 迁移文件不可修改；升级只能增加更高版本迁移。

## 手动部署

### 后端构建

```bash
cd zenvis-backend
mvn clean test
mvn clean package -DskipTests
```

构建产物由 Maven 配置生成。运行时指定外部配置文件：

```bash
java -jar target/application.jar \
  --spring.config.location=file:./application.properties
```

后端要求 JDK 17，并需要能够访问 MySQL、ClickHouse、Redis、Redis Stack、Vectum 和模型服务。

### 前端构建

```bash
cd zenvis-frontend
yarn install
yarn test
yarn build:pro
```

产物在 `dist/`。Nginx 需提供静态文件，并配置：

```nginx
location /zenvis/ {
    rewrite ^/zenvis(.*)$ $1 break;
    proxy_pass http://zenvis-backend:11001;
}
```

如果更换对外前缀，应同步修改前端 `VITE_BASE_URL`、开发代理和生产 Nginx，不能只改其中一处。

## 数据库与存储

### MySQL

- 保存系统配置、账号权限、会话、插件、任务与审计数据；
- 当前使用 JPA 自动更新基础表，插件业务表使用版本化迁移；
- 备份应包含结构、数据和字符集信息。

### ClickHouse

- 保存 Meta 对应的分析实体；
- 插件自动建表通常使用 `MergeTree()`；
- 表结构与 Meta、Vector Sink 必须同步；
- 备份需覆盖表定义、分区和数据。

### Redis 与 Redis Stack

- Redis 故障会影响 Session、缓存和部分状态；
- Redis Stack 故障主要影响 RAG，普通问答采用降级策略；
- 修改 embedding 模型或维度后必须重建向量索引。

## 生产安全

- 仅暴露业务需要的端口，数据库和中间件优先放在内部网络。
- 为 API、MCP、Vectum、数据库和模型服务使用不同凭据并定期轮换。
- 限制 `app.ai.mcp.allow-private-server-urls`，避免非受控环境访问内网地址。
- 为上传目录、插件包和 HTML 页面配置文件权限及恶意内容检查。
- 对 MySQL、ClickHouse、`open_config` 和插件归档建立定期备份与恢复演练。
- 通过 HTTPS 反向代理对外提供 Web、API 和 MCP。

## 备份建议

| 对象 | 最低要求 |
| --- | --- |
| MySQL | 定期全量备份，并在重要升级前创建恢复点 |
| ClickHouse | 按业务保留周期备份表定义和数据分区 |
| `open_config` | 版本化备份 Meta、插件、Skill、UI 和系统信息 |
| 部署配置 | 备份不含明文密钥的模板；密钥进入专用密钥管理系统 |
| 插件包 | 保留实际安装版本及其 SHA-256 |

## 排障

### 后端不健康

检查数据库连接、配置挂载、端口占用和 JVM 日志。后端端口为 `11001`，容器健康检查访问系统信息接口。

### 前端空白或接口 404

确认 `dist` 已正确构建，Nginx 监听 `11000`，`/zenvis/` 重写目标为后端，浏览器请求未被其他代理重复去除前缀。

### 推送任务无数据

依次检查 Vectum 服务、Kafka topic、Source、Transform 错误、DLQ 和 ClickHouse Sink。不要仅根据 ClickHouse 历史数据判断链路健康。

### AI 或 RAG 不可用

模型失败与 RAG 失败是两个独立问题。先检查模型地址/Key/模型名，再检查 embedding 开关、Redis Stack 和向量索引。
