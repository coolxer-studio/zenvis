# AI 问答与会话

本文说明数智中心普通问答、深度思考、模型选择、会话历史、附件和流式消息的当前行为，并提供使用与运维排障方法。

## 使用前提

| 依赖 | 用途 | 不可用时 |
| --- | --- | --- |
| ZenVis 后端与 MySQL | 会话、消息、模型调用编排 | 数智中心不可正常使用 |
| OpenAI 兼容 Chat 服务 | 普通问答和深度思考 | 自定义问答失败，确定性演示仍可能可用 |
| Redis Stack 与 embedding | RAG 语义检索 | 问答与业务会话降级为无 RAG 模式 |
| MinIO `zenvis-chat` | 上传、预览和读取聊天附件 | 附件上传与预览失败，已上传附件不可读取 |
| 浏览器 `/zenvis` 代理 | 同源访问后端 API | 页面可能出现 404 或认证失效 |

先在登录会话或配置好的 Bearer Token 下检查：

```bash
curl -H "Authorization: Bearer <API_BEARER_TOKEN>" \
  http://localhost:11001/api/v1/dih/health

curl -H "Authorization: Bearer <API_BEARER_TOKEN>" \
  http://localhost:11001/api/v1/dih/model/list
```

模型服务未配置不影响后端其他平台能力启动，但真正请求模型时会失败。

## 普通问答与深度思考

### 普通问答

普通问答使用 `type=ask`：

- 可以从全部未删除 RAG 知识库召回参考文档；
- 使用会话历史维持多轮上下文；
- 不加载 Skill；
- 不注入本地或外部 MCP 工具；
- RAG 不可用时继续无知识库问答。

### 深度思考

深度思考只对 `type=ask` 生效。前端发送 `deep_think=true` 后，后端根据模型能力读取原生 reasoning 字段或请求模型输出可解析的 `<think>` 内容。

业务智能体和 `skill:<skillId>` 入口有各自的工作流与工具边界，不能通过 `deep_think=true` 改变这些边界。

界面显示的思考片段取决于模型是否返回可展示内容。不能把页面没有展示思考过程理解为请求未执行。

### 自动 RAG 范围

平台在每轮请求中自动检索并注入参考资料，不需要模型调用检索工具：

| 会话 | 检索范围 | 无可用范围时 |
| --- | --- | --- |
| 普通问答、深度思考 | 全部未删除知识库 | 跳过向量查询，继续回答 |
| 业务 Agent / Skill | 当前所选启用 Skill 绑定知识库的并集 | 跳过向量查询，不回退全库 |

RAG 上下文会进入系统提示词并计入输入 Token 预算，但不占用 MCP 工具名额、工具调用预算或审批流程。检索无命中、未绑定知识库、Embedding 关闭或向量服务异常时，当前轮继续回答并记录原因。

每次同步检索还会生成一条独立的“知识库检索”记录，包含查询摘要、范围、状态、原因、耗时和命中来源。记录在模型首条增量前输出，以 `searchId` 幂等更新；前端显示为独立折叠卡，不并入“工具活动”。状态映射为 `ok → succeeded`、`no_match → empty`、前置跳过原因 → `skipped`、检索异常 → `failed`。查询和命中摘要最多展示 500 字，历史会话不会回填该记录。

### 工具活动与调用预算

业务 Agent 和 Skill 实际执行的 MCP 调用以 `callId` 合并为一条工具记录：开始、成功和失败更新同一项，不重复生成消息。默认折叠输入和返回结果，运行中、成功和失败使用不同状态语义。

工具预算只在实际调用通过 Schema 校验并进入工具执行阶段后扣减。模型返回非法参数、缺少必填字段或参数类型错误时，平台会请求模型修正一次，该次未执行的调用不占用额度；否则最后一次非法重试可能提前耗尽预算，使修正后的合法调用无法执行。审批拒绝和策略拒绝已经位于该执行阶段，因此仍可能占用一次预算，但不会产生底层工具的业务结果。

### 持久化智能体任务

启用持久化运行的业务 Agent 不再依赖“一条消息对应一次模型流”的短生命周期。平台会创建 Agent Run，保存目标、计划、步骤、审批、工具计数、有效执行时间、检查点和只追加事件；页面关闭后由后端调度器继续执行。

- 同一会话只有一个活动 Run，新消息在当前步骤结束后作为 steer 注入。
- 输入框在运行期间保持可用，页面卸载只断开事件连接，不取消任务。
- 用户从任务中心或运行卡执行暂停、继续、取消和审批。
- 等待审批、等待用户和暂停不占用 worker，也不计入有效执行时间。
- 重新打开会话时先读取活动 Run 和快照，再从本地保存的事件序号续订。
- 多轮会话按消息 `runId` 为每一轮恢复独立任务卡；任务完成触发消息重载时，历史轮次卡片仍需保留，不能只显示最后一个 Run。
- `WAITING_USER` 时自动弹出补充信息框并展示完整问题；提交后通过 steer 继续原任务，关闭弹窗后可从任务卡重新打开。
- 任务卡首屏提供默认折叠的“执行过程”，按检索、工具和上下文压缩三类活动汇总；实时运行读取事件流，历史任务按活动类型分页恢复。
- 除普通问答外，所有业务智能体统一使用持久化运行；需要确认的业务卡片会保存为消息并将 Run 置为 `WAITING_USER`，用户操作后恢复同一任务。

完整状态机、预算、恢复和事件协议见[智能体任务与持久化运行](/04-AI与数据智能/智能体任务与持久化运行.md)。

## 模型选择

模型列表综合：

- `spring.ai.openai.chat.options.model` 配置的默认模型；
- OpenAI 兼容服务 `/v1/models` 返回的模型；
- 固定的 `auto` 选项。

`model` 为空、为 `auto` 或为兼容的历史自动值时，后端在运行时选择可用模型。`auto` 不是模型服务名称，也不保证一定能找到可调用模型。

主要配置：

| 配置 | 说明 |
| --- | --- |
| `spring.ai.openai.base-url` | OpenAI 兼容服务地址 |
| `spring.ai.openai.api-key` | 模型服务 API Key |
| `spring.ai.openai.chat.options.model` | 默认 Chat 模型 |
| `app.ai.openai.force-http1` | 是否强制 OpenAI 兼容调用使用 HTTP/1.1 |

不要在文档、日志截图或前端环境变量中复制真实 Key。

## 会话、页面历史与模型记忆

ZenVis 同时维护两类数据：

| 数据 | 用途 |
| --- | --- |
| ZenVis 会话消息 | 页面历史、附件元信息、结构化消息、业务卡片和右侧工作台状态；附件正文在 MinIO |
| Spring AI Chat Memory | 提供给模型的多轮上下文 |

两者不是同一份数据。典型表现：

- 页面能看到旧消息，不代表这些消息全部仍在当前模型上下文中；
- 上下文压缩或截断不应删除页面历史；
- 删除会话会影响该会话关联的授权和工作台数据；
- 相同 `chat_id` 仍按当前用户隔离，其他用户不能读取。

会话支持列表、置顶、重命名、删除和重新打开。接口中的数据库记录 `id` 与业务 `sessionId/chat_id` 不是同一个标识，调用接口时不能混用。

## 上下文预算

当前生产基线：

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `app.ai.dih.context.window-tokens` | `102400` | 模型上下文窗口预算 |
| `app.ai.dih.context.output-reserve-tokens` | `16384` | 为模型输出预留 |
| `app.ai.dih.context.safety-margin-tokens` | `4096` | 安全余量 |
| `app.ai.dih.context.max-history-tokens` | `24000` | 历史消息预算 |
| `app.ai.dih.context.summary-tokens` | `2048` | 历史摘要预算 |
| `app.ai.dih.context.recent-turns` | `6` | 优先保留的最近轮次 |
| `app.ai.dih.context.max-attachment-chars-per-file` | `12000` | 单个文本附件进入本轮 Prompt 的字符上限 |
| `app.ai.dih.context.max-attachment-chars` | `24000` | 本轮所有文本附件的合计字符上限 |

系统会在窗口预算内保留系统规则、当前请求、近期对话和摘要。达到预算时旧历史或附件内容可能被截断；这属于受控行为，不应通过无限提高配置掩盖超长会话。

### 输出长度与截断

Skill 可通过 `runtime.limits.maxOutputTokens` 覆盖本轮最大输出 Token；未配置时回退 `app.ai.dih.context.output-reserve-tokens`。该值同时受模型服务自身输出上限约束。

模型以 `finish_reason=length` 结束时，后端追加内部截断标记并停止按完整结果处理。普通聊天保留已经生成的文本，不把截断内容声明为完整答案；旧报表路径还会检查 `zenvis:report-document-config` 围栏是否闭合，围栏不完整时移除半截报表、显示失败通知且不写入右侧文档。

持久化 Agent Run 把截断视为当前步骤未完成：保留安全检查点并重试当前步骤，最多重试 2 次；连续截断后暂停并标记 `OUTPUT_TRUNCATED`，不会把截断文本当作成功结果。报表 Run 按章节写入，单章失败只影响当前章节，其他已保存章节保留。

长报表应优先缩小单次范围或分章节生成。使用相同 Prompt 和相同输出上限反复重试，仍可能再次截断；单纯提高上限只能降低触发概率，不能替代分节生成或工具化增量写入。

## 附件

### 上传与类型

- 单个聊天附件最大 100 MB，单条消息最多 10 个附件；平台 multipart 仍保留 300 MB 上限，附件服务独立执行 100 MB 限制。
- 上传直接流式写入 `zenvis-chat`，原文件对象键为 `chat/{userId}/{fileId}/{sanitizedFileName}`；派生数据写入独立的 `chat-derived/{userId}/{fileId}/`，不会破坏“附件前缀下只有一个原文件”的旧读取逻辑。
- 上传接口立即返回，不等待正文解析。客户端轮询 `GET /api/v1/dih/upload/{fileId}/status`，存在 `pending`、`processing` 或 `failed` 附件时禁止发送。
- 支持 PDF、DOCX、XLSX、PPTX、CSV/TSV、现有 35 类文本/代码扩展名，以及 PNG、JPEG、WebP、GIF、BMP 图片。
- 不执行扫描件 OCR，不支持旧版 `.doc/.xls/.ppt`、压缩包、音视频和未知二进制正文。此类文件仍可上传，但只提供元信息并标记为 `unsupported`。
- 格式由扩展名、Content-Type 和文件头共同判断；PDF、现代 Office 和图片的伪装文件会被拒绝或解析失败。PDF 加密、损坏 Office 文件和无法解码的压缩包会返回明确失败原因。
- 图片通过 PNG/JPEG/WebP/GIF/BMP 魔数校验后直接为 `ready`。单张图片进入视觉模型前还有 20 MB 上限；超过上限时仍可下载和查看元信息，但不会编码成 `image_url` 发送给模型。

文件名只保留 basename，并清洗路径分隔符、控制字符和不允许的字符。对象的实际 `contentType` 根据文件头与类型判断写入；图片扩展名或浏览器声明不能单独决定媒体类型。

### 解析状态与生命周期

统一状态为 `pending`、`processing`、`ready`、`partial`、`failed`、`unsupported`：

- `pending`、`processing`、`failed` 禁止发送；失败附件可在页面重试或重新上传。
- `ready` 可发送；`partial` 和 `unsupported` 可发送，但页面必须提示“仅能使用已解析内容/元信息”。
- 解析失败自动重试 2 次。服务重启后会回收心跳超时的 `pending/processing` 任务；未被任何会话引用的附件在 24 小时后删除原文件和派生数据。
- 旧消息里没有附件记录的 `readable/image/unsupported` 继续兼容；首次被状态接口或工具访问时按需补建记录并异步解析。

默认解析上限为 1,000 页、500 张幻灯片、100 个工作表、每表 1,000,000 行、50,000 个分块和 10 分钟超时。超限统一标记为 `partial`，并在 `warning` 中说明截断范围。

### 页面交互

- 点击待发送区或历史消息中的非图片附件卡片，使用鉴权下载接口获取原文件；点击图片附件卡片打开受保护的图片预览。
- 附件卡片上的“移除”“重试”按钮只执行对应操作，点击事件不得继续冒泡触发卡片下载或预览。移除成功后只调用删除接口，不应发起附件下载请求。
- 解析中的附件显示上传/解析进度；`pending`、`processing`、`failed` 禁用发送，`partial` 和 `unsupported` 在发送前显示覆盖范围警告。

### 大文件上下文

- 小文本仍可直接注入，保留单文件 12,000 字符、本轮合计 24,000 字符预算。
- 大文件默认注入结构化目录、文件统计、表格表头、首页/首节摘要和 Top 8 命中片段；所有附件上下文合计不超过 24,000 字符。
- 文本按约 1,800 字符、约 10% 重叠切块；PDF 按页、PPT 按幻灯片、Word 按章节、表格按约 300 行切块，每个片段都带可回查 locator。
- 关键词检索始终可用，使用 CJK bigram + ASCII 分词和 BM25。`app.ai.embedding.enabled=true` 且 Redis 可用时，额外使用独立索引 `zenvis_attachment_vector`；向量结果与关键词结果通过 RRF 融合，向量不可用时自动降级。
- 附件正文始终按“不可信资料”注入，模型不得执行文档中的指令、代码、链接或工具调用要求。回答引用附件时必须同时给出文件名和页码、工作表、幻灯片或行号。

### 只读附件工具

所有会话都可以使用附件只读工具，但工具闭包只包含当前用户、当前会话或当前 Run 允许的附件：

- `attachment_list`：附件、状态、类型、大小和页/表/幻灯片数量。
- `attachment_outline`：目录、页码、章节、工作表和行列范围。
- `attachment_search`：在允许附件内执行混合检索并返回 locator 与分数。
- `attachment_read`：按 `page:3`、`slide:2`、`section:1.2`、`sheet:Sheet1!rows:100-200` 或 `lines:1200-1400` 回查正文。
- `attachment_table_query`：对 CSV/TSV/XLSX 做列选择、过滤、排序、分组和 `count/sum/avg/min/max` 聚合。

`ask` 仍不加载业务 MCP/Skill 工具；只有存在附件时才加载附件工具。业务 Agent 会把附件工具与既有 MCP/Run 工具按名称去重合并。附件工具不进入审批流程，但沿用 `tool_call` 事件、工具调用预算和审计。默认每轮 6 次调用、单次 8,000 字符、累计 24,000 字符。

图片与文档同时存在时，先执行图片取证阶段，再把取证结果交给带附件工具的回答阶段，避免图片原生输入和工具调用冲突。深度思考请求若必须调用附件工具，会保留深度思考系统提示，但改走支持工具调用的执行路径。

页面历史和 Chat Memory 只保留稳定附件引用与元信息，不持续保存每轮展开后的完整附件正文。附件读取从 MinIO 流式获取对象；对象缺失时本轮读取失败，不回退到本地 `chat-uploads` 文件。

### 图片输入

图片只有在当前模型调用走支持图片的 OpenAI 兼容路径时，才作为 `image_url` 内容发送。模型不支持视觉、图片校验失败或模型配置不完整时，不能声称已经识别图片内容。

附件只允许当前上传用户访问：服务端按 `chat/{userId}/...` 前缀校验归属，不能仅凭 `fileId` 读取。图片预览接口同时校验用户、实际媒体类型和文件头；预览和图片 Data URI 都从 MinIO 流读取。

## 事件流与结构化消息

前端当前使用 `response_format=events`。后端返回 `application/x-ndjson`，每行是一个独立 JSON 事件：

| 事件 | 用途 |
| --- | --- |
| `delta` | 文本增量 |
| `tool_call` | MCP 工具调用状态，按 `data.callId` 合并同一调用 |
| `rag_search` | 知识库检索快照，按 `data.searchId` 合并同一检索 |
| `approval_required` | MCP 工具等待审批 |
| `approval_updated` | 审批或工具状态更新 |
| `done` | 本轮完成，携带最终结构化消息 |
| `error` | 本轮失败 |

客户端应逐行解析并忽略未知事件，不能把整个响应当成一个 JSON。未使用 `events` 时返回纯文本流，不包含最终结构化 `Message`。

持久化 Run 直接使用 `GET /api/v1/dih/chat/runs/{runId}/events`，事件字段和序号规则不同；普通问答仍使用本节的 Chat 事件。Run 的“执行过程”只订阅 `rag.search`、工具生命周期和 `context.compacted`，可通过 `types` 过滤并在满 500 条后按 `sequence` 继续分页。`sequence` 用于去重，`searchId`、`callId` 和 `compactionId` 分别用于合并同类活动。

最终消息可以包含：

| part | 用途 |
| --- | --- |
| `markdown`、`code` | 普通正文和代码 |
| `thinking` | 可展示的思考内容 |
| `notice`、`confirm`、`info-steps` | 通知、业务确认和信息补充 |
| `mcp-approval` | 工具审批卡 |
| `tool-call` | MCP 工具调用活动，保留输入、结果、错误和耗时 |
| `rag-search` | 知识库检索记录，保留查询范围、原因和命中摘要 |
| `visualization-*` | 图表、配置、看板和菜单产物 |
| `report-document`、`report-fragment` | 完整报表和选区改写 |
| `prompt-suggestions` | 新会话开场建议 |

非法结构化围栏会降级为普通 Markdown，不应导致页面崩溃。

## `online_search` 当前状态

请求和会话模型保留 `online_search` 字段，前端也会保存开关状态；当前后端没有根据该字段执行外部联网搜索的服务链路。

因此：

- 开启开关不代表回答已经访问互联网；
- 不应把回答中的链接或时效性内容当成联网检索证据；
- 需要外部系统数据时，应使用明确配置的业务 Agent、Skill 或 MCP 工具，并接受相应权限和审批约束。

## 常见问题

### 模型列表为空或只有 `auto`

检查 OpenAI 兼容地址、Key、默认模型和 `/v1/models` 兼容性。`auto` 存在不代表目标服务可用。

### 页面一直等待或流式内容解析失败

检查请求是否使用 `response_format=events`、响应类型是否为 NDJSON、代理是否缓冲流式响应，以及客户端是否按行解析。

### 页面有历史，但模型忘记早期内容

检查上下文窗口、历史预算、摘要预算和会话长度。页面历史与模型记忆本来就是两层数据。

### 附件上传成功但回答没有引用内容

确认文件是否为支持的文本或图片类型、是否被字符预算截断、图片模型是否支持视觉。其他文件只传递元信息。

### 附件上传或预览失败

检查 `MINIO_ENDPOINT`、凭据、`zenvis-chat` Bucket 和对象是否仍存在。聊天附件以 MinIO 为唯一内容来源，不能从本地 `chat-uploads` 或 `zenvis-attachments` 回退读取；对象缺失时需要重新上传。

### RAG 故障但问答仍有结果

这是 fail-open 行为。查看后端 RAG 日志中的 `no_knowledge_base`、`no_bound_knowledge_base`、`embedding_disabled`、`no_match` 或 `retrieval_error`，再按[RAG 与知识库运维](/04-AI与数据智能/RAG与知识库运维.md)排查。

### 知识库检索显示“已跳过”

展开检索卡查看 `reason`。`no_bound_knowledge_base` 表示当前 Skill 没有绑定知识库，`no_knowledge_base` 表示普通问答没有可用知识库，`embedding_disabled` 表示向量检索被关闭，`empty_query` 表示本轮没有可检索文本。这些原因不会影响模型继续回答。

### 工具调用显示若干次后提示预算耗尽

先区分“实际执行次数”和“模型尝试次数”。Schema 非法的调用不会出现在工具活动记录中，也不会消耗预算；如果实际执行次数少于配置上限却提示 `tool_call_budget_exhausted`，应检查预算计数是否发生在参数校验之前。当前实现只在调用进入执行阶段后扣减。

### 报表正文被截断且没有写入右侧文档

先确认当前报表是否处于持久化 Run。Run 模式下检查暂停原因是否为 `OUTPUT_TRUNCATED`，缩短当前章节或步骤后继续，其他已保存章节不会丢失。旧单轮回退模式仍检查 `finish_reason=length`、`maxOutputTokens` 和报表围栏；应优先恢复 Run，而不是重复生成完整文档。

### 任务一直显示执行中或等待审批

打开对话头部的“智能体任务”，检查状态、租约恢复次数、`pendingAction` 和事件记录。`WAITING_APPROVAL` 需要处理对应 MCP 审批；`PAUSED` 会显示预算、截断、模型错误或未知工具结果原因。具体排查见[智能体任务与持久化运行](/04-AI与数据智能/智能体任务与持久化运行.md#运维与排障)。

### 业务智能体没有使用深度思考

这是设计边界。`deep_think=true` 只改变 `type=ask` 的推理模式，业务 Agent / Skill 使用各自的工作流和工具边界，详见[业务智能体与工作流](/04-AI与数据智能/业务智能体与工作流.md)。

### 业务智能体没有获得 RAG 参考资料

先确认当前启用的 Skill 是否绑定知识库，再检查绑定知识库是否已构建。业务会话只检索所选 Skill 绑定范围的并集；未绑定时不会查询向量库，也不会回退到全库。

## 运维验收

- 健康检查和模型列表可访问；
- 普通问答能收到 `delta` 和 `done`；
- 重新打开会话后消息、附件元信息和结构化 part 正常；
- 聊天附件写入 `zenvis-chat`，其他用户不能读取，对象缺失时返回失败而不是读取本地文件；
- `tool_call` 和 `rag_search` 能按 ID 增量更新，且不会与旧 Markdown 日志重复显示；
- 深度思考开关只影响普通问答；
- 文本附件的每文件和总字符预算生效；
- 图片和不支持附件的提示符合实际处理结果；
- RAG 关闭或故障时普通问答和业务会话可降级；
- 普通问答使用全库范围，业务 Skill 使用绑定范围且未绑定时不检索；
- 非法工具参数不消耗调用预算，实际执行次数与工具活动记录一致；
- 持久化 Run 能跨页面关闭恢复，事件按序号无重复、无丢失；
- 多轮会话刷新后，每一轮任务的卡片仍位于各自回复中，不覆盖、不合并到最后一个 Run；
- `WAITING_USER` 能自动弹出完整问题，提交后任务继续；关闭弹窗后同一问题不会重复弹出；
- 任务卡执行过程能区分检索、工具和上下文压缩，历史活动按 `types` 恢复且详情默认折叠；
- 运行中 steer、暂停、继续和取消不会创建第二个并发活动 Run；
- 报表分章节写入时，截断不提交半截章节且保留其他已完成章节；
- 旧单轮报表输出截断时不写入文档，并展示可解释的失败通知；
- `online_search` 未被描述为已实现的联网搜索。
