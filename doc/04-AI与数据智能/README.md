# AI 与数据智能

本目录面向 ZenVis 使用人员和运维人员，说明数智中心的问答、业务智能体、MCP 工具、后台分析任务、Skill、RAG 知识库和报表工作台。

这里维护“如何使用、如何配置、如何排障”。系统内部组件关系见[AI 与 MCP 架构](/06-架构设计/AI与MCP架构.md)，工程接手见[`zenvis-backend` 开发对接指南](/07-开发指南/zenvis-backend-开发对接指南.md)和[`zenvis-frontend` 开发对接指南](/07-开发指南/zenvis-frontend-开发对接指南.md)，完整接口字段见[DIH 与 AI API](/08-API参考/RestfulAPI/DIH与AI.md)。

## 当前边界

- 当前内置运行时智能体只有数据接入、数据可视化和报表制作。
- 插件或自定义专项能力通过 `skill:<skillId>` 聊天入口提供；插件制作不是当前内置智能体。
- 普通问答和深度思考可以使用公共 RAG，但不获得 Skill 或 MCP 工具。
- 业务智能体使用显式 Skill 和受控工具，不检索公共 RAG。
- `online_search` 当前只作为会话状态保存，尚未形成联网搜索执行链路。
- 没有配置大模型时，普通问答不可用；精确命中的内置演示仍可进入确定性流程。

## 最小可用检查

### 1. 后端与模型

```bash
curl -fsS http://localhost:11001/api/v1/dih/health
curl -fsS \
  -H "Authorization: Bearer <API_BEARER_TOKEN>" \
  http://localhost:11001/api/v1/dih/model/list
```

登录后的浏览器请求通过前端 `/zenvis` 代理访问同一组 `/api/v1/**` 接口。模型列表包含 `auto`；如果只有 `auto` 但实际模型不可用，发送消息仍会失败。

### 2. 基础服务

```bash
docker compose -f deploy/docker-compose.yml ps
```

普通 AI 问答需要后端、MySQL 和可用模型。启用 RAG 时还需要 embedding 服务与 Redis Stack。数据接入、可视化或外部工具调用还可能依赖 Vectum、Kafka、ClickHouse 和 MCP Server。

### 3. 页面入口

- 数智中心能创建并重新打开会话；
- 三个内置智能体入口与启用状态一致；
- Skill 聊天入口只展示已启用且允许聊天的 Skill；
- AI 分析任务抽屉可以读取队列状态；
- MCP 管理页能读取服务、工具策略、审批和审计。

## 通用安全规则

- 不把模型 API Key、MCP Token、数据库密码、客户地址或真实业务数据复制到文档和截图。
- 高风险工具保持 `ASK` 或 `DENY`；不要为了排障长期改成 `ALLOW`。
- MCP 调用参数和结果可能进入审计记录，调用前应控制敏感字段和返回规模。
- 不使用数据库直接改状态的方式跳过工作流、任务或审批状态机。
- 删除向量文档、索引、会话或归档前先确认作用域和恢复方式。
