# 业务智能体与工作流

本文说明 ZenVis 当前三个内置业务智能体的使用方式、确定性工作流、确认与审批边界、产物生命周期和排障方法。

## 当前内置智能体

| 页面名称 | 会话类型 | 主要能力 |
| --- | --- | --- |
| 数据接入 | `agent_data_access` | 生成或更新 Meta，创建、检查或修复 PushTask |
| 数据可视化 | `agent_data_visualization` | 查询真实实体数据，生成图表、页面、应用、看板和菜单 |
| 报表制作 | `agent_report` | 汇总会话素材，生成、编辑、修订、归档和导出报表 |

运行时入口来自 `skill_config` 中已启用的 Skill 配置。管理员禁用对应 Skill 后，入口和实际执行能力会相应变化。

插件制作不是当前内置业务智能体。插件或客户专项能力应通过已启用的 `skill:<skillId>` 聊天入口提供，仍受 Skill 工具白名单、MCP 策略和资源预算约束。

## 共同运行边界

- 业务智能体不检索公共 RAG，避免知识库文档改变执行流程。
- `deep_think=true` 不改变业务智能体的 Workflow、Skill 或工具权限。
- Agent 不能用自然语言声明代替真实工具结果。
- 业务确认、MCP 审批、工具执行和读回验证是独立阶段。
- 服务端保存工作流状态、候选快照、证据和修订号，前端不能通过修改卡片跳步。
- 达到工具预算、重复失败上限或上下文上限后，应基于已有证据停止或给出阻塞原因。

## 工作流与证据

数据接入和数据可视化共享工作流基础设施。卡片通常包含：

- `workflowId`、`workflowVersion`、`stateRevision`；
- 当前 `step`、对象类型和允许动作；
- `evidenceRefs` 和校验状态；
- 服务端锁定的候选、查询或配置摘要。

用户提交动作时，服务端精确校验会话、消息、part、工作流、状态修订号和允许动作。旧卡片、过期修订、被篡改候选或不允许的跳步操作会被拒绝。

### 业务确认与 MCP 审批

| 机制 | 决定什么 | 不能替代什么 |
| --- | --- | --- |
| 业务确认卡 | 是否采用实体、字段、查询方案或候选配置 | 不能批准高风险工具 |
| MCP 审批卡 | 某一次 `ASK` 工具是否执行 | 不能替代业务方案确认 |
| 读回验证 | 写入结果是否与已确认内容一致 | 不能由模型文字声明代替 |

业务卡通常调用 `/api/v1/dih/chat/workflow/action`，工具审批调用 `/api/v1/dih/mcp/approvals/{requestId}/decision`。完整字段见[DIH 与 AI API](/08-API参考/RestfulAPI/DIH与AI.md)和[MCP 服务管理 API](/08-API参考/RestfulAPI/MCP服务管理.md)。

## 数据接入

数据接入支持：

- 只创建或更新 Meta；
- 直接创建 PushTask/Vectum 数据推送；
- 完成 Meta 后继续创建数据推送。

### Meta 流程

```text
信息收集
  → config_tree
  → 候选配置确认
  → 写前重查
  → 可选覆盖确认
  → config_add / config_apply
  → config_read
  → 完成或阻塞
```

运维规则：

- 候选配置的完整内容、摘要、目标目录和文件名在确认后锁定。
- 新文件按创建、应用、读回的顺序执行；已有文件内容不同时必须单独确认覆盖。
- 同名同内容可以按幂等成功处理。
- `config_read` 与候选 JSON 语义一致前，不生成成功记录。
- “添加配置到系统”只表示进入写入阶段，高风险工具仍逐次应用 MCP 策略。

### PushTask 流程

```text
候选任务确认
  → 格式检测
  → sourceMark 冲突检查
  → 创建或复用
  → 状态读回
  → system 日志验证
  → 有证据修复
  → 完成或阻塞
```

- 多个同 `sourceMark` 任务冲突时停止，不猜测目标。
- 创建响应异常后先按 `sourceMark` 读回，避免重复创建。
- 成功记录需要唯一任务、运行状态和本轮 system 日志证据。
- 自动修复只针对日志已经证明的问题；网络、认证、权限和密钥错误直接阻塞。
- 异常数据和正常数据必须按插件任务约定进入对应输出或 DLQ。

### 数据接入排障

| 现象 | 检查 |
| --- | --- |
| Meta 没有生成 | `config_tree`、候选确认和工作流修订是否有效 |
| 写入后没有成功卡片 | MCP 审批、`config_apply` 和 `config_read` 是否全部成功 |
| 创建出重复任务 | `sourceMark` 是否稳定，创建异常后是否先执行读回 |
| 任务存在但无数据 | Vectum、Kafka、源地址、转换、ClickHouse 和 DLQ |
| 修复反复失败 | 查看当前轮 system 日志，不允许无证据连续改配置 |

## 数据可视化

普通请求固定经过：

```text
意图确认
  → 实体 Meta
  → 严格实体选择
  → 字段 Meta
  → 查询方案确认
  → 执行锁定查询
  → ECharts 产物
  → 可选入库或写入配置
  → 读回验证
```

### 严格候选

- 实体必须来自本轮实体 Meta 工具返回。
- 字段必须使用已选择实体的准确逻辑 `name` 再查询。
- 卡片选项与服务端候选快照同时校验。
- 自由输入、过期候选、物理表名、物理列名和编造字段会被拒绝。
- 查询确认卡应展示实体、字段角色、指标、维度、过滤、排序、目标工具和完整参数。

### 查询与图表

| 需求 | 典型工具 |
| --- | --- |
| 指标卡 | `entity_summary` |
| 时间趋势 | `entity_trend` |
| 计数 TopN | `entity_distribution` |
| 多指标聚合、透视或热力图 | `entity_aggregate` |
| 数值分布 | `entity_histogram` |
| 相关性或气泡图 | `entity_scatter` |
| 明细 | `retrieval_search`、`entity_list` |
| 关系与时间线 | `entity_relations`、`entity_relation_timeline` |

批准后平台严格执行卡片中的工具和参数，不接受 Agent 重新生成请求或传入任意 SQL。

图表产物保存真实查询信息、`queryMeta` 和纯 JSON `echartsOption`。对话预览和右侧图表库使用同一渲染组件：

- 加入图表库按产物 ID 幂等复制当前快照；
- 预览使用入库时快照；
- 刷新只复用原安全查询工具和参数；
- 刷新失败保留旧快照；
- 缺少安全查询参数的历史记录不能刷新。

### 页面、看板和菜单

- 低代码或 HTML 配置写入后使用 `config_read` 校验。
- Dashboard 创建后使用 `dashboard_view` 读回。
- Menu 创建前查询类型、父级和同名记录，创建后使用 `menu_view` 读回。
- 审批拒绝、创建失败或关键字段不一致时，不保存成功记录。
- 静态 HTML 只调用允许的同源 API，不执行任意脚本、URL 或 SQL。

### 数据可视化排障

| 现象 | 检查 |
| --- | --- |
| 实体或字段没有选项 | Meta 工具是否成功，`evidenceRefs` 是否存在 |
| 查询确认后没有图表 | 执行工具和参数是否与批准方案一致，响应是否含 `echarts.option` |
| 图表无法渲染 | `echartsOption` 是否为纯 JSON，查看 `chart_render_failed` 遥测 |
| 图表库无法预览 | 历史记录是否缺少快照；不要隐藏预览错误 |
| 看板或菜单未出现 | 检查 MCP 审批和创建后的查看接口读回 |

## 报表制作

报表制作由中间对话区和右侧文档工作台组成：

- 对话区负责指令、附件、素材和 AI 生成；
- 工作台负责当前文档、人工编辑、自动保存、修订、归档、恢复和导出。

### 素材与来源

可选择的素材包括当前用户可访问的：

- 会话附件及其解析/截断状态；
- 消息和结构化 part；
- 图表、分析记录和后台任务结果；
- MCP 调用审计和数据查询时间。

服务端重新校验来源，伪造或越权引用会被丢弃。缺失或冲突来源保留为“待确认”，Agent 不得编造证据。

图片附件采用分阶段处理：先提取图片证据，再把证据交给允许使用只读工具的报表阶段；不会因为本轮有图片就放开或禁用全部工具。

### 完整生成与选区改写

- 完整生成或整篇重写返回 `report-document`，更新当前文档并生成修订。
- 选区润色、缩写或扩写返回 `report-fragment`，不进入完整文档保存链路。
- 选区结果应用前再次校验文档版本、全文哈希和原片段哈希。
- 生成期间原文变化时只显示预览，不覆盖错误位置。

### 保存、修订和归档

```text
AI 完整生成或人工保存
  → 稳定 documentId
  → revision 递增
  → 用户显式归档
  → 不可变 artifact
  → 恢复后生成新的 revision
```

- 保存和完整生成携带 `base_revision`。
- 服务端使用乐观修订控制；旧版本写入返回 HTTP 409，不覆盖新内容。
- 当前正文、历史修订和不可变归档分别保存。
- 只有用户显式归档才创建 artifact；AI 生成不会自动归档。
- 重命名只修改归档名称，恢复不会倒退当前修订号。

### 导出

| 格式 | 实现 |
| --- | --- |
| Markdown | 前端下载当前规范正文 |
| HTML | 前端下载净化后的完整 HTML |
| DOCX | 服务端导出 |
| PDF | 服务端导出 |

DOCX/PDF 导出以当前 Markdown 或 HTML 为源，处理表格、链接、图片、代码块和嵌套列表。报表内容或来源包含敏感数据时，下载和归档前应按业务要求脱敏。

### 报表排障

| 现象 | 检查 |
| --- | --- |
| 完整生成没有更新右侧文档 | 是否返回有效 `report-document`，本轮是否标记失败 |
| 保存提示冲突 | 重新加载最新 revision，合并后再保存 |
| 选区结果替换错位 | 文档或选区哈希已变化，应只使用预览 |
| 归档没有出现 | 是否显式执行归档；普通保存只产生 revision |
| DOCX/PDF 导出失败 | 当前文档、格式、图片资源和后端导出日志 |

## 确定性无模型演示

开场白中的精确示例在模型可用性检查前路由：

- 数据接入：用户事件完整接入演示；
- 数据可视化：临时图表、单页面应用、带侧边栏应用、数据看板、添加菜单；
- 报表制作：四个固定报表示例。

演示不是普通自由输入的模糊兜底。配置、任务、看板和菜单等写操作仍调用真实 MCP，并进行读回验证。

为了展示真实审批，内置演示的默认 `ASK` 写工具强制逐次审批：

- 既有 `ALLOW` 覆盖或会话授权不能跳过演示审批；
- 演示只提供“允许本次”和“拒绝执行”；
- 全局 `DENY` 始终优先。

## 失败账本与重试

工作流记录失败阶段、工具、请求摘要、真实错误、可重试性、检查点和已保留产物。

- 读操作瞬时失败可以有限重试。
- 写操作不盲目重试，依赖幂等标识和读回判断。
- 审批拒绝、配置读回不一致、任务不唯一或日志存在错误时，不生成成功记录。
- 重试必须从服务端给出的检查点继续，不能重新使用旧卡片绕过状态版本。

## 运维验收

- 三个内置入口与 Skill 启用状态一致；
- 普通问答入口没有获得业务 Agent 工具；
- 数据接入候选、写入、读回和 PushTask 日志链完整；
- 可视化实体、字段和查询方案来自真实 Meta；
- 图表入库、预览和刷新复用同一安全查询；
- 看板、菜单和配置创建后完成读回；
- 报表保存冲突不会覆盖新正文；
- Markdown、HTML、DOCX 和 PDF 导出符合当前文档；
- 演示可在无模型环境进入，但不能绕过 MCP 审批和 `DENY`。
