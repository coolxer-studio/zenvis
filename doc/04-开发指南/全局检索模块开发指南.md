# 全局检索前端开发指南

本文说明 `src/views/retrieval` 的职责划分和状态流，帮助新同事在不重新引入重复查询、过期响应覆盖或输入框重建问题的前提下维护全局检索。

产品说明和完整接口定义已统一到根文档：

- [全局检索产品说明](../01-产品与使用/使用手册/功能说明-全局检索.md)
- [Retrieval 详细设计](../03-架构设计/retrieval-module.md)
- [Retrieval Controller 接口](../05-API参考/控制器/RetrievalController.md)

## 1. 页面结构

| 文件 | 职责 |
| :--- | :--- |
| `src/views/retrieval/index.vue` | 唯一查询状态源；加载实体/规则、发起检索、保存删除规则、处理并发请求 |
| `src/views/retrieval/components/filter.vue` | 编辑普通条件或高级表达式；不自行加载规则，不自行请求数据 |
| `src/views/retrieval/components/table.vue` | 表格展示、展示列选择、分页和排序事件 |
| `src/service/api/api-retrieval.ts` | Retrieval 接口封装和取消请求参数 |
| `src/types/type-retrieval.ts` | 请求、规则详情、失效项和表格状态类型 |
| `src/service/request-wrapper.ts` | 支持 `AbortSignal` 和静默错误处理的通用请求封装 |

## 2. 核心状态

`index.vue` 中最重要的状态如下：

| 状态 | 含义 |
| :--- | :--- |
| `currentFilter` | 当前实体、模式、条件、表达式和展示字段 |
| `activeRule` / `activeRuleName` | 当前已保存过滤器；0 表示新建状态 |
| `entityList` / `attributeList` | 当前可用元数据 |
| `loadedConfig` / `loadedIssues` | 加载规则时的原始配置和问题，用于判断问题是否已被用户修复 |
| `currentSorter` | 当前实体的排序字段和方向 |
| `tableState` | 表格列、数据、loading 和分页 |

不要在 `filter.vue` 或 `table.vue` 再维护一份完整查询配置。子组件只维护编辑所需的短生命周期草稿，并通过事件把变化交给父页面。

## 3. 初始化和规则加载

### 3.1 新建状态

```text
GET /retrieval/entity/list
        ↓
GET /retrieval/display/attribute/list?entity=...
        ↓
POST /retrieval/do
```

页面使用第一个实体和元数据中的默认展示列。若没有默认展示列，至少选择当前字段列表的第一个字段。

### 3.2 已保存规则

```text
GET /retrieval/rule/detail?id=...
        ↓
原子应用 config + entity_list + attribute_list + issues
        ↓
有效规则：POST /retrieval/do
失效规则：停留在编辑态
```

不要恢复旧版同时调用 `entity/list?rule_id`、`attribute/list?rule_id` 和 `display/attribute/list?rule_id` 的做法。多个响应完成顺序不确定，会把条件和展示列拼成不同规则或不同实体的混合状态。

## 4. 并发和取消约定

页面有两套独立的防过期机制：

- `loadGeneration`：实体或规则每切换一次就递增。只有当前 generation 可以应用详情和元数据。
- `dataRequestId`：每次数据查询递增。只有最新 request ID 可以写入表格和关闭 loading。

对应请求还使用 `AbortController` 主动取消旧请求。取消属于正常控制流：

- 使用 `{ silent: true }` 避免通用请求层弹错。
- catch 中先检查 `axios.isCancel(error)`。
- 旧请求的 finally 不能修改最新请求的 loading。

切换实体或规则前调用 `clearDataState()`，立即清空旧表格、列、排序和分页，避免网络等待期间仍展示上一个实体的数据。

## 5. 条件输入组件的状态反馈

`filter.vue` 使用 `draft.criteria_list` 保存可编辑条件，并把单值编辑框转换为接口所需的 `value_list`。

输入事件会触发以下回路：

```text
输入字符
  → 更新 draft
  → emit update:modelValue
  → 父组件更新 currentFilter
  → props.modelValue 回写 filter.vue
```

回写配置与当前草稿相同时，`modelMatchesDraft()` 必须直接返回，不能重新映射整个 `criteria_list`。否则条件行的 `key` 会变化，Element Plus 的 `el-input/el-autocomplete` 会在每个字符后卸载重建，表现为：

- 输入文字立即消失或不显示。
- 光标和焦点丢失。
- 自动补全请求行为异常。

外部真正切换了规则、实体或条件时才重建草稿。新增条件时生成稳定 `key`，不要使用数组下标作为可编辑行标识。

## 6. 展示列、排序和响应字段

- 表格列的 `dataIndex` 使用元数据逻辑字段 `name`。
- 后端响应也始终以逻辑 `name` 为键，不使用 `label`、`display_name` 或物理 `column_name`。
- 展示字段至少保留一个；选择变化后重置到第一页并查询。
- 排序字段随实体切换清空，发送 `sort_by` 和 `order: asc/desc`。
- 分页参数为 `page` 和 `size`，页大小选项为 10、20、50、100，后端上限 200。
- 条件输入组件只读取属性的 `search_type`：`date`、`datetime`、`number` 分别使用日期、日期时间和数字输入组件，其他值回退普通输入；`auto_complete` 文本字段继续使用自动补全。
- `json` 字段点击查看结构化详情，`array` 字段按页面展示约定渲染。

## 7. 失效规则编辑

`/rule/detail` 返回：

```ts
type RetrievalRuleDetail = {
  config: RetrievalRuleConfig;
  status: 'valid' | 'invalid';
  issues: RetrievalRuleIssue[];
  entity_list: TEntityListResponse[];
  attribute_list: TAttributeListResponse[];
};
```

`remainingIssues` 根据当前编辑值动态判断问题是否仍存在：

- 普通条件缺失字段可移除。
- 缺失展示字段可移除，但必须至少保留一个有效展示字段。
- 高级表达式缺字段时保留原文，修改表达式后才视为已处理。
- `LEGACY_SQL_DISABLED` 只有重新编辑旧表达式后才能解除。
- 有未处理问题时禁止搜索和保存。

启动恢复缓存规则时，如果规则不存在、无权访问或已失效，页面会删除 `__rule__` 并进入新建状态；不要让启动流程自动执行失效规则。

## 8. 保存、更新和删除

- 新建：`POST /retrieval/rule/create`，成功响应 `{ id }`。
- 更新：`POST /retrieval/rule/update`，标准字段为 `id`；后端兼容旧 `rule_id`。
- 删除：`POST /retrieval/rule/delete`，只提交 `{ id }`。

更新时可以部分提交，但前端通常发送当前完整配置。`criteria_list: []` 表示主动清空普通条件，`display_list: []` 非法。切换实体时必须发送新实体展示字段和对应检索条件。

规则成功保存后刷新规则列表，并同步 `activeRule`、名称和 `__rule__` 缓存。删除当前规则必须同时清除这三处状态。

## 9. API 和类型约定

- Retrieval JSON 使用 `snake_case`。
- GET 参数放入 `config.params`，其他请求放入 `config.data`。
- `request()` 的 `silent` 只控制统一错误提示，不改变成功响应解包。
- 自动补全使用 `/api/v1/entity/{entity}/{attribute}/auto-complete`，只对元数据 `auto_complete` 字段启用。
- 候选值接口 `/api/v1/retrieval/candidate/list` 兼容 `attributeId` 或 `entity + attribute`。

修改接口时先更新 `src/types/type-retrieval.ts`，不要在组件中重新声明相似但字段不同的匿名结构，也不要用 `any` 绕过 snake_case 契约。

## 10. 开发检查清单

本项目没有 Jest/Vitest，不要为 Retrieval 单独引入新的测试框架。提交前至少运行：

```bash
yarn test
yarn build:pro
```

浏览器网络面板检查：

1. 加载有效规则只有一次详情请求和一次数据请求。
2. 失效规则只有详情请求，没有自动数据请求。
3. 快速连续切换规则后，只显示最后一个规则的数据。
4. 被取消请求不弹错误，loading 最终正确结束。
5. 输入普通条件时文字、焦点和条件行保持稳定。
6. 新建、更新、删除、刷新恢复、分页、排序、展示列和自动补全工作正常。

## 11. 常见错误改动

| 改动 | 后果 |
| :--- | :--- |
| 子组件在元数据回调中调用查询 | 一个规则加载触发多次 `/do` |
| 并行加载规则的实体、条件和展示列 | 新旧规则状态混合 |
| 不检查 generation/request ID | 慢响应覆盖用户最后选择 |
| 所有 finally 都关闭 loading | 旧请求提前关闭新请求 loading |
| 每次 props 回写都重建条件数组 | 输入文字消失、焦点丢失 |
| 表格使用物理列或展示名称取值 | 表格出现空列 |
| 实体切换后保留排序字段 | 后端返回排序字段不存在 |
| 缓存失效规则并自动执行 | 启动后立即报字段或表达式错误 |
