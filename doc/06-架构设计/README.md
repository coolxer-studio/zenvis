# 架构设计

本目录从组件、数据、扩展、智能能力、运行环境和安全边界六个视角说明 ZenVis。内容面向架构师、平台开发者、插件开发者和部署维护人员，并以当前代码、构建清单与运行配置为事实来源。

## 架构原则

- **配置驱动**：Meta、页面、菜单、看板、推送任务和 Agent 能力优先通过受控配置表达。
- **逻辑模型优先**：业务接口使用逻辑实体和属性，物理表、列和存储实现收敛在后端。
- **平台内核稳定**：业务能力通过插件、REST API、MCP Tool 和业务服务 Starter 扩展。
- **读写边界明确**：分析数据、平台配置、会话状态和向量数据分别使用适合的存储。
- **AI 行为受控**：Skill、Agent scope、工具策略、审批和审计共同限定模型可执行动作。
- **失败可恢复**：元数据使用原子快照，插件升级保留恢复状态，异步任务记录完整生命周期。

## 系统全景

```text
浏览器 / 第三方系统 / 业务服务 / MCP Client
          │
          ├── Web 与低代码页面
          ├── REST API
          ├── MCP SSE + Message
          └── 心跳与业务事件
          │
          ▼
ZenVis Frontend（Vue 3） ────────┐
          │                       │
          ▼                       │
ZenVis Backend（Spring Boot）     │
  ├── 系统、权限与平台配置        │
  ├── Meta、Retrieval 与实体分析  │
  ├── 插件生命周期与动态 API      │
  ├── DIH、RAG、Agent 与 MCP      │
  └── 业务服务注册与事件管理       │
          │                       │
          ├── MySQL：平台与事务数据
          ├── ClickHouse：分析实体数据
          ├── Redis：Session 与运行状态
          ├── Redis Stack：向量索引
          ├── Kafka：数据接入消息
          └── Vectum：采集、转换与写入
```
