# 安全与权限架构

本文描述 ZenVis 当前真实的认证、权限、数据归属、MCP 审批、插件和页面容器边界。后端使用 Spring MVC 拦截器，而不是 Spring Security 过滤器链。

## 信任边界

```text
互联网 / 外部网络
  │
  ├── Browser ── Cookie Session ───────────────┐
  ├── Third-party REST ── API Bearer Token ───┤
  ├── MCP Client ── MCP Bearer Token ─────────┤
  └── Business Service ── 公开上报入口 ───────┤
                                               ▼
                                      ZenVis Backend
                                        │     │
                             用户/角色/审计   工具策略/审批
                                        │     │
                                        ▼     ▼
                     MySQL / ClickHouse / Redis / MinIO / 外部 MCP
```

不同入口使用不同凭据和授权上下文。REST API Token 不能替代 MCP Token，MCP 授权也不能自动获得平台管理员权限。

## 认证矩阵

| 入口 | 认证方式 | 用户上下文 | 主要用途 |
| --- | --- | --- | --- |
| Web 与普通 REST | Redis Session / Cookie | 登录用户 | 平台页面和交互 |
| 第三方 REST | API Bearer Token | 配置映射的系统用户 | 系统集成和自动化 |
| MCP 协议端点 | MCP Bearer Token | MCP Server 边界 | MCP Client 连接 |
| 业务服务心跳与事件 | 当前为公开 POST 上报 | 服务身份来自请求体和注册信息 | Starter 上报 |
| 登录、验证码、系统信息和健康接口 | 公开或单独放行 | 无登录用户 | 建立会话与健康检查 |

公开不表示可以接受任意数据。业务服务上报仍需请求校验、大小限制、离线判断和审计；部署层应限制来源网络。

## REST 认证链路

`AuthorityInterceptor` 注册到 Spring MVC：

```text
请求
  → 判断是否为明确公开路径
  → 判断是否属于受保护路径
  → 存在 Authorization: Bearer
       ├── 常量时间比较 API Token
       └── 加载 app.security.api.bearer-user
  → 否则检查 Redis 中的 Session ID
  → 刷新 Session 超时
  → Controller
```

API Bearer Token 成功后，把映射用户 ID 和名称写入请求属性。Controller、JPA 审计和领域服务据此复用用户归属与操作审计。

Session 与 Bearer 的边界：

- Session 适合浏览器交互和登录生命周期。
- Bearer 适合受控系统集成，不创建浏览器 Session。
- Token 未配置时，携带任意 Bearer 请求都会被拒绝。
- Bearer 映射用户不存在时请求被拒绝。
- 文档和日志不得输出 Token 原文。

## MCP 认证链路

`McpBearerTokenInterceptor` 覆盖全部 `/mcp/**` 分组端点，并在普通权限拦截器之前执行：

```text
/mcp/{serviceCode}/sse 或 /mcp/{serviceCode}/message
  → 读取 Authorization: Bearer
  → 常量时间比较 MCP Token
  → 失败返回 401 + WWW-Authenticate
  → 成功进入 Spring AI MCP Server
```

MCP Token 未配置时端点默认拒绝访问。外部 MCP Client 配置的 Header 属于独立连接凭据，应存储在后端受控配置中，不下发给浏览器。

## 用户、角色与菜单

MySQL 保存用户、角色、用户角色、菜单和角色权限关系。超级管理员角色在平台初始化时同步全部菜单权限。

角色菜单主要决定：

- 登录后可见菜单。
- 页面和操作入口的权限集合。
- 插件安装菜单如何进入平台权限模型。

前端权限用于隐藏和禁用交互，不是安全边界。敏感写操作仍需后端校验用户上下文、对象状态和领域规则。当前系统不能把“菜单不可见”等同于所有对应 REST 路径都有独立方法级授权。

## 数据访问边界

### Retrieval 规则

过滤器列表、详情、更新、删除和执行都绑定创建用户。不存在和越权返回同类错误，避免通过 ID 枚举其他用户规则。

### 实体数据

当前 Retrieval 没有完整的实体级、字段级和行级权限模型。`RetrievalAccessPolicy` 只提供扩展接口，默认实现不能被描述成已有细粒度数据授权。

第三方 REST Bearer 映射到具体系统用户，使规则归属和审计具有稳定身份，但不自动增加字段或行级限制。

### AI 数据

- 普通问答使用全部未删除知识库的 RAG 和用户提供上下文。
- 业务 Agent / Skill 只在所选 Skill 绑定知识库的并集内执行 RAG；未绑定时不检索，避免跨业务知识库读取。
- 业务 Agent 通过 Skill 和受控工具读取实时数据。
- 临时图表、可视化应用和数据大屏分别使用独立的实体 Meta、分析工具与写入工具白名单。
- Agent 不得直接访问数据库连接或执行任意 SQL。

### 对象存储

- 通用 `/api/v1/minio` 接口只允许访问默认 `zenvis-attachments` Bucket，不能指定 RAG、聊天、插件或报表 Bucket。
- 四个业务 Bucket 只通过对应领域接口访问；领域服务固定选择 Bucket，调用方不能通过请求参数切换存储域。
- 聊天附件对象键包含真实 `userId` 和随机 `fileId`，上传、预览、文本上下文和图片 Data URI 读取都按当前用户前缀校验归属。不能仅凭 `fileId` 猜测或枚举其他用户附件。
- 下载与预览由后端鉴权后流式返回，不签发 presigned URL，也不把 MinIO 地址交给浏览器。
- 图片预览先根据实际文件头识别 PNG、JPEG、WebP、GIF 或 BMP，再允许图片媒体类型；扩展名或客户端 `Content-Type` 不能单独作为可信依据。
- 插件包、升级候选、快照和报表修订使用统一对象键校验，拒绝绝对路径、`..`、反斜杠和空路径段。

## MCP 工具授权

工具执行依次受全局策略、Agent scope、Skill allowlist、会话/任务授权和审批状态约束。

| 策略 | 含义 |
| --- | --- |
| `ALLOW` | 在其他边界满足时直接执行 |
| `ASK` | 创建审批并等待批准 |
| `DENY` | 无条件拒绝，授权不能覆盖 |

```text
工具调用
  → 规范化 Server 与原始工具名
  → 全局策略
  → Agent scope
  → Skill allowlist
  → 会话或任务授权
  → 审批
  → 执行
  → 审计状态与结果摘要
```

拒绝、超时、取消、执行失败和成功都进入审计。后台分析任务的自动审批只处理允许自动批准的 `ASK`，不能覆盖 `DENY`。

## 插件安全

### 归档与文件

- 上传归档必须防止路径穿越。
- 插件包以 `zenvis-plugins` 中的对象为权威副本，解压目录和下载缓存只用于运行与校验。
- 插件文件只能写入自己的安装和工作目录。
- 运行包排除源码、构建缓存、历史归档、日志和凭据。
- 插件最大上传限制不代表所有接近限制的包都适合发布。

### 动态 API

- 每个插件使用独立 ClassLoader。
- API JAR 数量受限，Controller 包名和 Bean 名必须唯一。
- 路由在升级和卸载时显式注销。
- 插件不得覆盖平台类或依赖后端内部实现。
- MySQL 迁移使用版本和 SHA-256 防止历史脚本被改写。

### 数据影响

升级以保留数据为原则，卸载会删除插件关联的 ClickHouse 表和数据。卸载属于高风险动作，必须展示影响并形成操作日志。

## 页面与 URL 安全

- 插件链接只允许相对地址或 `http/https`。
- Meta `link_template` 只使用当前实体逻辑字段，占位值逐项 URL 编码。
- 外部应用 iframe 在前端检查 URL 协议和 `VITE_IFRAME_ALLOWED_ORIGINS`。
- HTML 页面从受控目录通过 `/html-page/**` 提供。
- 系统图标等资源从受控目录通过 `/system-files/**` 提供。
- DOM 中的富文本和 Markdown 必须经过允许规则与清理，不能直接信任模型或插件 HTML。

iframe 来源检查属于浏览器侧防护，生产环境仍应通过 CSP、反向代理和网络访问控制限制可嵌入来源。

## 凭据与配置

- 数据库、Redis、MinIO、模型、MCP 和 Vectum 凭据通过环境变量或密钥系统注入。
- MinIO 凭据需要创建和访问默认 Bucket 及四个业务 Bucket；权限不足时后端启动失败，不能用公共匿名 Bucket 规避。
- 前端只允许包含公开运行配置，不得携带后端 Token。
- 插件包和 RAG 文档不得包含凭据。
- 日志对 Token、密码、检索值和附件内容执行脱敏或摘要化。
- 示例配置使用占位符，不复制部署文件中的实际值。

## 当前边界

- 认证由 MVC 拦截器实现，不应在文档中宣称已启用 Spring Security。
- 当前代码中的 Referer/Host CSRF 检查未作为主要认证机制启用；部署应使用安全 Cookie、同源代理、TLS 和来源控制。
- 菜单权限不能替代后端对象授权。
- Retrieval 细粒度数据权限仍是扩展点。
- 对象存储访问控制由后端领域服务承担；生产环境不应允许浏览器或普通业务插件直接使用 MinIO 管理员凭据。
- 公开业务服务上报入口应由网络边界、请求校验和后续认证演进共同保护。
- Actuator 和静态资源按 Web 配置放行，生产反向代理只应暴露必要端点。

## 安全变更检查

1. 新增公开路径时同步更新认证矩阵和 API 文档。
2. 新增 MCP Tool 时定义默认策略、风险等级、Agent scope 和审计摘要。
3. 新增插件能力时检查安装、升级、卸载和恢复的文件及数据影响。
4. 新增外部页面时检查协议、来源、CSP 和 iframe 行为。
5. 新增数据接口时明确用户归属和对象授权，不能只依赖前端菜单。
6. 修改配置项时确认敏感值不会进入前端、日志、文档或插件包。
