# 系统与组件架构

本文说明 ZenVis 各工程的职责、前后端分层、运行期组件关系、请求链路和后端启动顺序。

## 工程边界

| 工程 | 运行时角色 | 主要职责 |
| --- | --- | --- |
| `zenvis-frontend` | Web 应用 | 登录、菜单、检索、DIH、低代码、外部页面和平台管理界面 |
| `zenvis-backend` | 平台服务 | REST、MCP、权限、Meta、数据查询、插件、AI 和业务服务管理 |
| `zenvis-plugin` | 统一插件源 | 平台、社区与企业插件包，动态 API 源码和打包工具 |
| `zenvis-dependencies/zenvis-business-service-spring-boot-starter` | 外部应用依赖 | 封装服务注册、心跳、事件队列和关闭通知 |
| `agent-skills/create-zenvis-plugin` | 研发工具 | 指导 Agent 创建、检查和打包插件，不参与后端运行 |
| `deploy` | 运行环境 | Compose 服务、开放配置、持久化目录和反向代理配置 |
| `doc` | 文档站 | Docsify 文档入口，不参与产品运行 |

各工程可以独立构建。平台、社区和企业插件统一位于 `zenvis-plugin`，使用同一平台安装契约；插件仓库和业务服务 Starter 是平台扩展面，不应反向依赖后端内部 Entity、Repository 或未公开工具类。

## 前端架构

### 技术基线

当前前端基于 Vue 3、TypeScript、Vite、Vue Router、Pinia、Axios、Element Plus 和 ECharts。AMis 用于配置化页面，WangEditor 用于报表文档编辑，Monaco Editor 用于配置编辑。

### 路由与页面容器

前端使用 Hash Router，基础路由由 `src/router/index.ts` 维护：

| 路由 | 页面职责 |
| --- | --- |
| `/user/login` | 登录 |
| `/dashboard/index` | 平台首页 |
| `/retrieval/index` | Meta 驱动的全局检索 |
| `/service/dih` | DIH 会话、Agent、报表和分析任务 |
| `/service/low-code-app/:menuParams` | 多页面低代码应用 |
| `/service/low-code-page/:menuParams` | 单页面低代码配置 |
| `/service/external-app/:menuParams` | 受控外部 iframe |
| `/service/html-page/:menuParams` | 后端托管的静态 HTML |
| `/plugin/config/:menuParams`、`/policy/:menuParams` | 配置管理 |
| `/system/about` | 系统信息 |

菜单由后端配置提供，页面容器根据菜单类型和参数解释目标资源。路由守卫只负责会话入口、Token 参数接收和登录跳转；业务权限仍由后端接口和领域服务负责。

### 请求与状态

Axios 请求层使用 `VITE_BASE_URL`，默认根路径，并启用 `withCredentials`。前端业务模型使用 TypeScript，接口 JSON 统一采用 `snake_case`，公共响应通过 HTTP 状态和业务 `status` 共同判断。

页面级状态保存在组件或组合式函数中，跨页面登录状态和用户权限使用 Pinia 与受控本地缓存。异步页面必须处理请求取消和过期响应，不能让旧响应覆盖新选择。

## 后端架构

### 技术基线

后端基于 Spring Boot 3.2、Spring MVC、Spring Data JPA、Spring AI、Redis、MySQL 和 ClickHouse JDBC。应用显式配置 MySQL 与 ClickHouse 数据源，并关闭默认单数据源自动配置。

### 分层职责

```text
com.coolxer
├── aop/                 请求日志、REST 与 MCP 拦截器
├── configuration/       Web、数据源、AI、MCP 和动态扩展配置
├── controller/
│   ├── config/          配置管理与配置 MCP Tool
│   ├── dashboard/       首页看板
│   ├── dih/             会话、Skill、报表、MCP 管理
│   ├── retrieval/       检索、实体和分析
│   └── system/          用户、角色、菜单、插件和任务
├── service/             领域编排与实现
├── dao/                 MySQL、ClickHouse Entity 与 Repository
├── model/               DTO、VO、Meta 和查询模型
└── component/           初始化与平台级组件
```

- Controller 处理协议、校验和当前用户上下文，不承载跨领域事务。
- Service 负责领域规则、状态机和外部系统编排。
- DAO 分别绑定 MySQL 与 ClickHouse 持久化上下文。
- Configuration 负责数据源、Web、AI、MCP 和动态类加载边界。

### HTTP 请求链路

```text
Client
  → Nginx / 直接访问后端
  → McpBearerTokenInterceptor（仅 MCP 协议端点）
  → AuthorityInterceptor（平台 REST 与受控资源）
  → LogAopAspect
  → Controller
  → Service
  → Repository / Query Engine / 外部服务
  → ResponseWrap 或流式响应
```

后端没有使用 Spring Security 过滤器链。认证由 Spring MVC `HandlerInterceptor` 完成；具体信任边界见[安全与权限架构](/06-架构设计/安全与权限架构.md)。

## 启动初始化顺序

`InitComponent` 在应用启动后按固定顺序建立运行状态：

1. 初始化平台基础数据。
2. 确保插件升级与迁移相关表结构存在。
3. 首次执行 MySQL 初始化脚本并写入完成标记。
4. 首次执行 ClickHouse 初始化脚本并写入完成标记。
5. 恢复上次中断的插件升级。
6. 加载并校验完整 Meta 快照。
7. 根据 Meta 初始化或增量升级 ClickHouse 表结构。
8. 扫描已安装插件，每个插件最多加载一个动态 API JAR。

初始化过程把数据库结构、Meta 和动态 API 放在对外稳定运行之前。必要结构变更失败时应中止启动，不能带着部分 Schema 继续接收写入。

## 外部业务服务

业务服务通过 Starter 主动上报，不被打包进 ZenVis 后端：

```text
业务应用
  → Starter 自动配置
  → 启动注册 / 周期心跳 / 异步事件 / 关闭通知
  → ZenVis 公开上报接口
  → Business Service Registry
  → 管理端概览、实例和事件
```

Starter 负责身份、传输、重试和事件队列；ZenVis 负责状态计算、保留策略和查询。详细接入方式见[业务服务接入](/05-业务服务接入/README.md)。

## 组件依赖原则

- 前端只依赖公开 REST、静态资源和菜单契约。
- 插件只依赖平台公开扩展契约，不依赖后端内部实现。
- Retrieval 只接受逻辑实体与属性，物理查询封装在查询引擎。
- Agent 通过 Skill 和受控工具获得能力，不直接访问数据库。
- 外部业务服务通过 Starter 或公开 REST 上报，不共享平台数据库。
- 部署工程提供运行配置，源码工程不得依赖 Compose 中的固定地址或凭据。
