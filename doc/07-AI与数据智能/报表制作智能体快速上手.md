# 报表制作智能体快速上手

本文介绍报表制作智能体的交互方式、文档生命周期和核心实现。当前实现把 `agent_report` 从普通聊天升级为具备独立文档、修订、归档、素材追溯和安全导出的 AI 写作工作台。

## 一句话理解

报表制作智能体由两部分组成：

- **中间对话区**：承接用户指令、附件、素材选择、AI 回复和流式生成。
- **右侧报表文档区**：承载当前可编辑文档，支持自动保存、撤销、修订查看、显式归档、版本比较、恢复和导出。

AI 生成只更新当前文档并产生修订，不会自动创建归档。只有用户点击“归档”才会生成不可变快照。

## 文档生命周期

```text
AI 完整生成 / 人工保存
        |
        v
稳定 documentId + revision 递增
        |
        | 用户显式归档
        v
不可变 artifact（记录真实 revision/version）
        |
        | 恢复归档
        v
当前文档产生新的 revision
```

- 同一会话的当前报表保持稳定 `documentId`。
- 保存和完整生成均携带 `baseRevision`。服务端在事务内加锁、校验并写入；旧版本返回 HTTP 409，不覆盖新内容。
- 当前正文只保存到独立文档和修订表；`ChatSession.extraData.report` 仅保留 ID、版本、摘要和来源索引。
- 归档正文是创建时的不可变快照。重命名只修改归档名称，恢复会产生新修订。

## 用户能做什么

### 生成或改写完整报表

用户可以直接描述需求，或使用“生成初稿、继续写、正式语气、摘要、标题、结论”等快捷操作。请求会携带：

```json
{
  "report_action": {
    "type": "full_generate 或 full_rewrite",
    "documentId": "当前文档 ID",
    "baseRevision": 3,
    "sourceRefs": []
  }
}
```

完整结果必须返回一个 `report-document`。空正文、重复完整报表、非法格式、超长内容和不完整结果会明确标记失败，不会静默退化并覆盖当前文档。

### 选择素材和查看来源

右侧素材区可选择当前会话附件、图表库记录、分析记录和后台任务。保存的 `sourceRefs` 可包含：

- 附件 ID、解析状态和截断状态
- 消息 ID、part ID
- 图表记录 ID、分析任务 ID
- MCP 调用审计 ID、查询条件和数据时间

客户端提交的来源不会被直接信任：服务端会用当前用户可访问的最近会话素材和当前文档已有来源进行校验，伪造或越权引用会被丢弃。

报表中的来源可以跳转到附件预览。缺失或冲突的来源应保留为“待确认”，智能体不得编造证据。

图片附件采用同一轮的分阶段处理：先提取图片证据，再把证据交给允许使用只读 MCP 工具的报表阶段，因此上传图片不会禁用该轮全部工具。

### 选区局部改写

用户选中文本并右键选择润色、缩写或扩写。请求使用 `selection_rewrite`，记录 `selectionId`、原片段哈希、`documentId` 和 `baseRevision`。

服务端只返回 `report-fragment`，不会进入完整文档持久化链路。结果应用前，前端会再次校验文档版本、整篇内容哈希和原片段哈希；若生成期间内容发生变化，只展示预览，由用户决定是否使用，不会替换错误位置。

### 保存、归档和导出

- 编辑后自动保存，界面展示“保存中、已保存、冲突”状态。
- 支持撤销、修订记录、归档比较、归档重命名、删除和恢复。
- 支持 Markdown、净化后的 HTML、服务端 DOCX 和 PDF 导出。
- DOCX/PDF 统一 A4 页面、页眉页脚、页码，并保留表格、链接、图片、代码块和嵌套列表。
- 演示模板会显示“演示数据”标识，不与正式归档混淆。

## 存储模型

报表正文不再作为 `extraData` 的主存储。三个独立表分别承担当前状态、历史修订和不可变归档：

| 表 | 用途 |
|---|---|
| `t_ai_report_document` | 当前文档、稳定 ID、当前 revision、格式、正文和来源 |
| `t_ai_report_revision` | 每次生成或保存产生的历史修订 |
| `t_ai_report_artifact` | 用户显式创建的不可变归档快照 |

`extraData.report` 仅保留轻量引用，其他子域（如图表库和工作流状态）由服务端合并并原样保留，浏览器不再提交完整 `extra_data`。

## 报表专用接口

| 接口 | 用途 |
|---|---|
| `GET /api/v1/dih/chat-session/{sessionId}/report` | 读取当前文档、修订和归档 |
| `GET .../report/materials` | 读取当前用户最近会话中的附件、图表、任务和智能体产物 |
| `POST .../report/save` | 按 `baseRevision` 原子保存 |
| `POST .../report/archive` | 显式创建归档 |
| `POST .../report/artifacts/{id}/restore` | 从归档恢复为新修订 |
| `POST .../report/artifacts/{id}/rename` | 重命名归档 |
| `DELETE .../report/artifacts/{id}?base_revision=...` | 删除归档 |
| `GET .../report/export/{docx|pdf}` | 服务端导出 |

## 输出协议

完整报表使用：

````markdown
```zenvis:report-document-config
# 报表标题

## 摘要

...
```
````

选区改写返回 `report-fragment`，不能返回完整报表围栏。聊天请求中的 `report_action` 决定服务端采用完整文档还是片段协议。

默认以 Markdown 作为规范源；明确生成 HTML 时保留 HTML 格式。编辑器内部 HTML 不会改变源格式，保存时通过 GFM 转换保留表格、链接、图片、代码块和嵌套列表。

## 工具权限

`report-agent/skill.json` 显式列出实体元数据、查询统计和 `analysis_task_list/view` 等只读工具。外部 MCP 默认不暴露；已加载 Skill 但没有工具边界时按 fail-closed 处理，不会回退为全部工具。配置写入、实体删除和任务删除工具不得进入报表 Agent 工具列表。

## 主要文件

### 后端

| 文件 | 作用 |
|---|---|
| `AgentMcpToolService` | Skill 工具白名单和 fail-closed 边界 |
| `DihChatApplicationService` | 报表动作协议、分阶段图片证据、结果校验和生成修订 |
| `ReportDocumentService` | 原子保存、冲突检测、修订和归档生命周期 |
| `ReportDocumentController` | 报表专用 API |
| `ReportExportService` | DOCX/PDF 服务端导出 |
| `ChatMessagePartParser` | 解析结构化报表围栏 |

### 前端

| 文件 | 作用 |
|---|---|
| `type-dih.ts` | 文档、修订、归档、来源和动作类型 |
| `api-dih.ts` | 报表专用 API |
| `use-chat-stream.ts` | 发送 `report_action` |
| `use-panel-record-sync.ts` | 同步文档、片段和可选素材 |
| `view-right-report.vue` | 编辑、保存、冲突、归档、来源、比较和导出 |
| `report-document-format.ts` | GFM/HTML 无损转换、净化和哈希 |
| `e2e/report-workbench.spec.ts` | 保存修订、409 冲突和迟到选区改写的浏览器回归 |

## 验证

后端重点测试：

```bash
mvn -Dtest=AgentMcpToolServiceTest,ReportDocumentServiceTest,ReportExportServiceTest,ChatMessagePartParserTest,DihChatApplicationServiceTest test
```

前端测试与构建：

```bash
yarn test
yarn test:e2e
yarn build
```

手工验收：

- 确认报表 Agent 看不到 `config_apply`、`entity_delete`、`analysis_task_delete` 和未声明的外部 MCP 工具。
- 连续生成、编辑只增加修订；显式归档后才出现不可变版本。
- 让 AI 回复与人工保存并发，旧版本保存应收到明确冲突且不覆盖正文。
- 编辑含表格、链接、图片、代码块和嵌套列表的 Markdown，再保存和导出检查结构。
- 选择附件、图表或任务作为素材，检查修订中的 `sourceRefs`。
- 发起选区改写后修改原文，迟到结果应只显示预览。
