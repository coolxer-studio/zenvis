# MCP Tool 总览与接入

ZenVis 同时扮演 MCP Server 和 MCP Client：

- 作为 Server，通过 MCP 协议向外部 Client 暴露 71 个内置工具。
- 作为 Client，连接后台配置的外部 MCP Server，并把经过筛选的工具提供给业务 Agent。

本目录列出当前代码静态注册的内置工具。外部工具由运行时服务动态发现，不能在静态文档中完整枚举。

## MCP Server 端点

| 项目 | 当前配置 |
| --- | --- |
| Server 名称 | `zenvis-mcp-server` |
| 版本 | `1.0.0` |
| 类型 | `SYNC` |
| SSE 端点 | `/sse` |
| 消息端点 | `/mcp/message` |
| Tools capability | 启用 |
| Resources、Prompts、Completion | 关闭 |

完整地址由 ZenVis 后端地址加端点组成，例如：

```text
http://localhost:11001/sse
http://localhost:11001/mcp/message
```

端点可通过 `spring.ai.mcp.server.sse-endpoint` 和 `spring.ai.mcp.server.sse-message-endpoint` 调整。

## 认证

MCP 端点要求：

```http
Authorization: Bearer <MCP_BEARER_TOKEN>
```

配置：

```bash
MCP_BEARER_TOKEN=<独立随机令牌>
```

生产和 SaaS 配置默认值为空；Token 为空时服务端拒绝所有 MCP 端点访问。开发配置包含便于本地启动的默认值，不能用于生产。MCP Token 与普通 REST API 的 `API_BEARER_TOKEN` 相互独立。

概念性 Client 配置：

```json
{
  "name": "zenvis",
  "url": "http://localhost:11001/sse",
  "headers": {
    "Authorization": "Bearer <MCP_BEARER_TOKEN>"
  }
}
```

不同 MCP Client 的配置字段可能不同，以对应 Client 文档为准。

## 工具参数命名

- 顶层方法参数使用工具 Schema 中的参数名，例如 `request`、`ruleId`、`sourceMark`。
- DTO/请求对象内部字段遵循 Schema，通常使用 `snake_case`，例如 `approval_mode`、`display_list`。
- 可选参数以工具 Schema 的 `required` 数组为准，不要把 Java 方法类型是否可空当作唯一依据。
- 调用方应先读取 MCP `tools/list` 返回的 JSON Schema，再生成参数。

## 本地工具与外部工具

| 类型 | 来源 | 工具名与策略键 |
| --- | --- | --- |
| 本地工具 | 本仓库 7 个 `*McpTool` 类 | 工具名固定；策略键 `local::<toolName>` |
| 外部工具 | 后台配置的 MCP Server | 原始工具经 Spring AI 格式化；稳定身份由服务代码和原始工具名共同确定 |

外部 Server 的新增、启停、刷新、工具查看和测试调用通过 [MCP 服务管理 REST API](/08-API参考/RestfulAPI/MCP服务管理.md) 完成。

## Agent 调用链

```text
Agent 类型与已选 Skill
  → 全局 MCP 开关与 Agent scope
  → Skill local/mcp allowlist
  → 本地与外部工具发现
  → ALLOW / ASK / DENY 策略过滤
  → ToolCallbackProvider
  → 模型工具调用
  → 审批、执行与审计
```

普通 `ask` 不应无条件获得所有工具；业务 Agent 只在任务确实需要外部数据或动作时调用。参数不足时必须追问，不能编造实体、字段、任务 ID 或配置路径。

## 结果和错误

MCP Tool 返回的是工具结果，不套 REST `ResponseWrap`。常见结果包括：

- Boolean：写操作是否成功。
- VO/PageRowsVo：结构化业务对象或分页数据。
- Map/List：动态实体、选项或日志信息。
- AnalyticsResponse：分析表格、元信息和 ECharts JSON。
- 结构化拒绝/审批状态：工具未执行时供 Agent 继续解释。

调用方应同时处理协议错误、工具抛出的业务异常、审批拒绝、策略禁止和返回体截断。完整策略见[权限审批与运行约束](/08-API参考/MCPtool/权限审批与运行约束.md)。

## 安全原则

- 不向模型或工具参数泄漏 API/MCP Token。
- 工具输入必须来自用户明确意图、Meta 或可信系统结果。
- 读取工具不代表结果可无限返回，仍受分页和结果长度限制。
- 写入、删除、应用配置、创建任务等工具默认 `ASK/HIGH`。
- 全局 `DENY` 优先于 Skill、会话或任务授权。
