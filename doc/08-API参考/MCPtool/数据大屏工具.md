# 数据大屏工具

`dashboard` 服务为数据大屏智能体提供受管大屏生命周期。模型只提交结构化
`DashboardSpec` 或 `DashboardChangeSet`；HTML、AMIS、API 路径、ECharts 脚本、文件布局、
Dashboard 记录和菜单策略全部由服务端生成。新流程只读系统数据，不创建菜单。

端点为 `/mcp/dashboard/sse` 与 `/mcp/dashboard/message`，实现类为
`com.coolxer.controller.dih.DashboardMcpTool`（Spring Bean 名为
`visualizationDashboardMcpTool`）。所有工具要求已登录的对话工作流上下文，并绑定当前用户、
会话和活动 `visualization_dashboard` 工作流。

## 工具清单

| 工具 | 审批 | 风险 | 用途 |
| --- | --- | --- | --- |
| `visualization_dashboard_list` | `ALLOW` | `LOW` | 列出带受管清单的数据大屏、版本、模式、发布状态和 Dashboard 记录 ID |
| `visualization_dashboard_get` | `ALLOW` | `LOW` | 读取清单、完整 Spec、文件摘要和只读兼容标记 |
| `visualization_dashboard_validate` | `ALLOW` | `LOW` | 校验 Meta、布局和查询，执行真实只读取样并生成受控预览 |
| `visualization_dashboard_apply` | `ASK` | `HIGH` | 使用锁定摘要一次发布配置与 Dashboard，全量读回，失败回滚 |

合计 4 个工具。该服务不提供任意文件写入、HTML/AMIS 正文、菜单 CRUD、配置 CRUD、
SQL 或实体写操作入口。

## visualization_dashboard_list

无参数。返回每个受管大屏的 `dashboard_id`、`name`、`dashboard_version`、`mode`、`theme`、
`dashboard_type`、`dashboard_record_id`、`publish_status`、`spec_digest`、`file_digest`
和 `updated_at`。

只枚举存在受管清单的大屏。无清单历史大屏不会出现在该列表，也不能被新流程自动接管。

## visualization_dashboard_get

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `dashboardId` | 是 | 稳定大屏标识，例如 `user-event-dashboard` |

受管大屏返回：

- `read_only=false`、`managed=true`；
- 清单元数据、发布状态、Dashboard 类型和记录 ID；
- `spec_digest`、`file_digest`、`meta_digest`；
- `files` 文件摘要和完整 `spec`；
- Dashboard 读回状态、`code`、`source`、`html_path`、`config_index` 和 `is_default`。

无清单历史大屏返回 `read_only=true`、`managed=false`、`compatibility=legacy`，不会生成
可更新的 Spec。更新受管大屏时必须使用此接口返回值作为变更基线：
`dashboard_version`、`spec_digest`、`file_digest`。任一基线漂移都必须重新读取。

## visualization_dashboard_validate

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `specJson` | 二选一 | 新建大屏时提交完整 `DashboardSpec` JSON |
| `changeSetJson` | 二选一 | 更新受管大屏时提交 `DashboardChangeSet` JSON，内含完整新 Spec 和基线摘要 |

只允许在 `DASHBOARD_VALIDATING` 阶段调用，不写配置或 Dashboard。校验失败后仍保持该阶段，
模型按 `diagnostics` 修正后重新校验；只有不可恢复条件或后续发布失败才进入 `BLOCKED`。
在 `BLOCKED` 阶段允许先重新读取 Meta/清单，再重新校验，但不得跳过校验直接发布。

服务端执行：

1. 解析并规范化 Spec，拒绝 HTML、CSS、JavaScript、AMIS、API URL、SQL、配置正文、菜单参数和记录写操作。
2. 按已发布 Meta 校验实体、字段、时间字段、图表类型、查询工具、操作符和查询组合。
3. 校验 12 列布局、行跨度、区块唯一性、区块数量和明细表只读约束。
4. 对每个唯一查询执行一次有界真实只读查询；空结果只产生警告，查询失败或字段不存在阻断。
5. 将同一 Spec 编译为 HTML 或 AMIS，生成确定性摘要和受控预览文件。
6. 保存 30 分钟内的候选、版本、摘要和预览文件，仅当前用户、会话和工作流可访问。

成功返回 `passed=true`、`status=validated`、`workflow_id`、`dashboard_id`、
`dashboard_version`、`mode`、`previous_mode`、`candidate_digest`、`validation_digest`、
`spec_digest`、`meta_digest`、`file_digest`、`spec`、`files`、`diagnostics`、`manifest`
和 `preview`。`preview` 至少包含真实 iframe 地址和查询取样摘要。

校验成功不会自动发布。正常路径由模型输出 `zenvis:visualization-dashboard-preview` 预览卡并结束本轮，
由用户确认真实数据预览。为避免确认入口依赖模型输出格式，服务端还会根据成功的工具结果或锁定的
`DASHBOARD_VALIDATING` 工作流补全完整卡片：模型只返回 Markdown 时仍会生成卡片，不完整或摘要
不一致的模型卡片会被替换。卡片 ID 稳定且不超过 64 字符，完整摘要保留在元数据中。

预览确认完成后工作流才进入 `DASHBOARD_APPLYING`。用户必须点击卡片上的“确认发布大屏”并完成
二次确认；聊天框输入“确认发布”不构成卡片动作。批准后卡片状态变为 `approved`，
`allowedActions` 清空，不再显示发布按钮。

## visualization_dashboard_apply

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `workflowId` | 是 | 当前工作流 ID，必须来自 validate 结果 |
| `candidateDigest` | 是 | validate 返回的候选摘要 |
| `validationDigest` | 是 | validate 返回的校验摘要 |

只允许在 `DASHBOARD_APPLYING` 阶段调用，并且必须已完成预览卡上的业务发布确认。
`ASK/HIGH` 审批只批准工具执行，不替代方案确认或真实预览确认。服务端重新校验用户、会话、
版本、清单摘要、Meta 摘要、模式锁定和候选差异，然后：

1. 快照目标配置文件和 Dashboard 记录，拒绝人工修改、缺失文件和清单漂移。
2. 写入大屏正文和受管清单，并逐文件读回。
3. 按稳定 `code=<dashboard_id>`、`source=dashboard:<dashboard_id>` 创建或更新 Dashboard。
4. 读回 Dashboard 名称、类型、HTML 路径或配置索引和来源。
5. 任一步骤失败时恢复旧配置和 Dashboard，不产生半成功状态。

返回状态：

- `verified`：配置与 Dashboard 均写入并读回，`applied=true`。
- `blocked`：摘要、快照、写入或读回失败，`applied=false`；已尽力回滚。

成功结果包含真实 `dashboard_id`、`dashboard_version`、`mode`、`file_digest`、
`dashboard_record_id`、`dashboard_type`、`dashboard_code`、文件摘要、Dashboard 读回字段
和诊断。新流程不调用 `menu_*`，不创建菜单。

发布成功后的记录卡按真实 `dashboard_id` 和锁定的 `applyResult` 关联对应 `VERIFIED` 工作流，
不依赖 `activeByAgent`。活动工作流已清理时仍能输出真实 Dashboard ID、版本、模式和成功状态，
不会新建 `BLOCKED` 工作流。

## DashboardSpec

顶层字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema_version` | 是 | 固定 `1.0` |
| `dashboard_id` | 是 | 3–64 位小写字母、数字或短横线，以字母开头、字母或数字结尾 |
| `name`、`description` | 是 | 名称最多 80 字符，说明最多 500 字符 |
| `mode` | 否 | `HTML_PAGE` 或 `LOW_CODE_PAGE`，默认 `HTML_PAGE` |
| `theme` | 否 | 首版只支持 `DARK_TECH` |
| `refresh_interval_seconds` | 否 | 30–3600 秒，默认 60 |
| `time_field` | 是 | 全局时间口径字段，必须存在于每个被查询实体 Meta |
| `default_time_range` | 否 | 默认 `LAST_7_DAYS`，必须在允许范围内 |
| `allowed_time_ranges` | 否 | `LAST_24_HOURS`、`LAST_7_DAYS`、`LAST_30_DAYS`、`THIS_MONTH`、`ALL_TIME` |
| `layout` | 是 | 12 列网格，1–12 行；每行 `span` 合计不超过 12 |
| `blocks` | 是 | 1–16 个区块，且每个区块必须被布局引用一次 |

区块只允许三类：

- `metrics`：绑定 `entity_overview` 或 `entity_summary`，包含 1–8 个指标卡。
- `chart`：绑定 `entity_trend`、`entity_distribution`、`entity_aggregate`、
  `entity_histogram` 或 `entity_scatter`；`chart_hint` 只允许 `LINE`、`BAR`、`AREA`、
  `PIE`、`SCATTER`、`BUBBLE`、`HISTOGRAM`。
- `records`：使用 `entity_list` 语义的只读明细，1–10 列、最多 6 个筛选、每页 5–50 条；
  不允许新增、编辑、删除、批量操作、导入或导出。

`records` 的字段、筛选操作符和默认排序字段都必须来自已发布 Meta。查询请求由服务端补全
统一时间字段和默认时间范围；模型不能指定任意 API 地址、SQL、adaptor 或脚本。

## DashboardChangeSet

更新受管大屏时提交：

| 字段 | 说明 |
| --- | --- |
| `dashboard_id` | 目标大屏，必须与完整 Spec 一致 |
| `base_dashboard_version` | 当前发布版本 |
| `base_spec_digest` | 当前规格摘要 |
| `base_file_digest` | 当前受管文件摘要 |
| `spec` | 完整的新 `DashboardSpec` |

变更集是完整替换，不做隐式局部合并。版本、规格、文件或 Meta 摘要漂移时阻断，模型必须重新
调用 `visualization_dashboard_get` 后生成新方案。HTML 与低代码模式首次发布后锁定；切换模式
必须使用新的 `dashboard_id` 新建大屏。

## 存储与发布约定

| 模式 | 正文 | 清单 | Dashboard 类型 | 稳定标识 |
| --- | --- | --- | --- | --- |
| HTML | `html-page_config/<dashboardId>.html` | `html-page_config/<dashboardId>.manifest.json` | `HTML_PAGE` | `code=<dashboardId>`、`source=dashboard:<dashboardId>` |
| 低代码 | `<dashboardId>_config/index.json` | `<dashboardId>_config/_dashboard.json` | `LOW_CODE_PAGE` | `code=<dashboardId>`、`source=dashboard:<dashboardId>` |

HTML 模式使用同源、固定版本的 `/echarts/echarts.min.js`，不依赖 CDN。模板包含品牌区和标题区、
KPI 卡片带、主图表区、辅助图表、只读明细表，以及加载、空态、错误态、手动刷新、全局时间切换
和默认 60 秒自动刷新。所有用户文本由服务端转义；查询工具、API 路径和渲染脚本只来自服务端
白名单编译器。

发布不改变用户默认看板，不创建菜单。历史菜单记录仍可只读展示，但新大屏通过现有看板列表进入。
无清单历史大屏保持只读；新流程不会接管、迁移或覆盖。

## 预览与安全

validate 成功后可通过只读 REST 预览读取：

| 方法 | 路径 | 输入 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/dih/chat/workflows/{workflowId}/dashboard-preview` | `chat_id`、`token` | 读取本次候选的 HTML 或低代码预览入口 |
| GET | `/api/v1/dih/chat/workflows/{workflowId}/dashboard-preview/files` | `chat_id`、`token`、`path` | 读取清单内受控预览文件 |

令牌绑定当前用户、会话、工作流和验证尝试，默认 30 分钟有效。接口只从
`DashboardPreviewRegistry` 的编译产物读取，不直接暴露配置目录；未列入清单的路径、路径穿越、
跨用户、跨会话、错误令牌或过期令牌均返回 404。响应使用 `Cache-Control: no-store`、
`X-Content-Type-Options: nosniff`、CSP 和 `Referrer-Policy: no-referrer`。

服务重启后内存注册表清空，旧预览卡不能继续读取或发布；必须重新执行
`visualization_dashboard_validate`。

## 错误处理

- `DASHBOARD_ID_INVALID`、`DASHBOARD_MODE_UNSUPPORTED`、`DASHBOARD_THEME_UNSUPPORTED`：Spec 基本约束不合法。
- `DASHBOARD_MODE_LOCKED`：尝试修改已发布大屏的模式；使用新 `dashboard_id` 新建。
- `DASHBOARD_VERSION_STALE`、`DASHBOARD_SNAPSHOT_CHANGED`：版本、规格、文件或 Meta 摘要漂移，重新读取后生成新方案。
- `LAYOUT_*`：列数、行数、跨度、重复引用或区块缺失不合法。
- `REPRESENTATIVE_QUERY_EMPTY`：真实查询为空，属于警告；预览显示空态但仍可发布。
- `REPRESENTATIVE_QUERY_FAILED`：真实查询失败，阻断校验。
- `CANDIDATE_MISMATCH`：发布摘要与工作流锁定候选不一致。
- `DASHBOARD_WRITE_FAILED`：配置或 Dashboard 写入/读回失败，已尝试恢复快照。
- 预览不存在、过期或越权：重新 validate 并使用新预览卡，不要复用旧摘要。
- 校验成功但没有预览卡：刷新会话并重新校验；新轮次会由平台补卡，历史消息不会追溯补卡。
- 阶段不允许或找不到卡片：使用最新预览卡确认；不要在聊天框输入“确认发布”，该文本不是卡片动作。

成功记录必须使用 `zenvis:visualization-dashboard-record`、`recordKind=dashboard` 和 apply
返回的真实 Dashboard 记录 ID、版本、模式、文件摘要与状态。不得输出 config 或 menu 成功记录。
