# 数据应用工具

`data-app` 服务为可视化应用智能体提供受管 AMIS 数据应用生命周期。模型只提交结构化 `DataAppSpec` 或 `DataAppChangeSet`，AMIS、API 路径、adaptor、表单控件、菜单参数和文件布局均由服务端生成。

端点为 `/mcp/data-app/sse` 与 `/mcp/data-app/message`，实现类为 `DataAppMcpTool`。所有工具要求已登录的对话工作流上下文，并绑定当前用户、会话和活动 `visualization_app` 工作流。

## 工具清单

| 工具 | 审批 | 风险 | 用途 |
| --- | --- | --- | --- |
| `visualization_app_list` | `ALLOW` | `LOW` | 列出带 `_app.json` 清单的受管应用 |
| `visualization_app_get` | `ALLOW` | `LOW` | 读取清单、规格、页面和受管文件摘要 |
| `visualization_app_validate` | `ALLOW` | `LOW` | 校验规格、编译 AMIS、执行真实查询并生成只读预览 |
| `visualization_app_apply` | `ASK` | `HIGH` | 一次发布锁定版本的配置和菜单并全量读回 |
| `visualization_app_retry_menu` | `ASK` | `HIGH` | 仅重试 `PARTIAL_MENU` 的菜单发布与读回 |

合计 5 个工具。该服务不提供任意文件写入、菜单 CRUD、配置 CRUD 或 AMIS 正文提交入口。

## visualization_app_list

无参数。返回每个受管应用的 `app_id`、`name`、`app_version`、`mode`、`home_page_id`、`publish_status`、`menu_id`、`pages` 和 `updated_at`。

只枚举存在 `_app.json` 的应用；无清单历史应用不会出现在该列表。

## visualization_app_get

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `appId` | 是 | 稳定应用标识，例如 `user-event-analysis` |

返回 `manifest`、`spec`、`app_version`、`spec_digest` 和 `files[]`。每个文件包含 `path`、`digest`、`present`、`drift` 和 `size`。无清单目录返回 `read_only=true`、`managed=false`、`compatibility=legacy`，不得更新或覆盖。

更新已有应用时必须使用返回的 `app_version` 作为 `base_app_version`，并使用 `spec_digest` 作为 `base_spec_digest`。

## visualization_app_validate

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `specJson` | 新建时是 | 完整 `DataAppSpec` JSON |
| `changeSetJson` | 更新时是 | 页面/应用元数据/菜单变更集 JSON |

只允许在 `APP_VALIDATING` 阶段调用，不写配置或菜单。对因校验失败且尚无写入证据而进入 `BLOCKED` 的会话，可在重新读取 Meta 和应用后再次校验。服务端执行：

1. 解析并规范化规格，合并 `put_pages` 和 `delete_page_ids`。
2. 校验应用/页面标识、页面和区块上限、Meta 实体/字段/操作符/展示类型。
3. 校验版本、`base_spec_digest`、Meta 摘要和受管文件摘要。
4. 按 Meta 编译 AMIS 6.7.0 配置并绑定现有实体查询、`/retrieval/do` 与 CRUD 接口。
5. 对每个代表性查询执行一次有界真实查询。
6. 生成只读预览文件和工作流锁定摘要。

返回 `passed`、`status`、`app_version`、`mode`、`candidate_digest`、`validation_digest`、`spec_digest`、`meta_digest`、`spec`、`files`、`deleted_files`、`diagnostics`、`menu` 和 `preview`。校验失败返回 `status=invalid`，工作流保持 `APP_VALIDATING`；模型应按 `diagnostics` 修正规格后重新校验，不能绕过继续发布。只有不可恢复条件或后续配置写入/读回失败才进入 `BLOCKED`。

校验成功不会自动进入 `PERSIST_CONFIRMATION`。模型必须输出只读预览卡并结束本轮，由用户点击“确认发布应用”；该业务确认完成后，工作流才进入 `PERSIST_CONFIRMATION`/`APP_APPLYING`。在 `APP_VALIDATING` 直接调用 `visualization_app_apply` 会被拒绝。

## visualization_app_apply

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `workflowId` | 是 | 当前工作流 ID，必须来自 validate 结果 |
| `candidateDigest` | 是 | validate 返回的候选摘要 |
| `validationDigest` | 是 | validate 返回的校验摘要 |

只允许在 `PERSIST_CONFIRMATION`/`APP_APPLYING` 阶段调用，并且必须已完成预览卡上的业务发布确认。`ASK/HIGH` 审批只批准工具执行，不替代该业务确认。一次审批覆盖配置和菜单。服务端重新校验用户、会话、版本、清单摘要、Meta 摘要和候选差异，并按以下顺序执行：

1. 快照所有受管文件，拒绝人工修改、缺失文件和清单漂移。
2. 写页面文件，再写 `site.json`；删除页面在导航更新后执行。
3. 最后写 `_app.json` 并全量读回比较语义内容。
4. 创建或按清单 `menuId` 更新菜单，通过菜单详情接口读回名称、类型、路由、参数和来源。
5. 单页升级为多页时保留 `index.json`，菜单成功后删除兼容文件。

返回状态：

- `verified`：配置和菜单均写入并读回。
- `partial_menu`：配置成功，菜单失败；保留旧入口，可重试菜单。
- `blocked`：配置写入或读回失败；已尽力恢复快照，不记录发布成功。

## visualization_app_retry_menu

参数与 `apply` 相同。只允许在 `PARTIAL_MENU` 阶段调用，复用锁定候选和已成功配置，不重写页面、`site.json` 或规格。菜单更新和读回一致后返回 `verified`；失败继续保持 `partial_menu`。

## DataAppSpec

顶层字段：

| 字段 | 说明 |
| --- | --- |
| `schema_version` | 固定 `1.0` |
| `app_id` | 3–64 位小写字母、数字或短横线，以字母开头 |
| `name`、`description` | 应用名称和描述 |
| `home_page_id` | 当前页面中的首页 |
| `pages` | 1–6 个页面 |
| `menu` | 可选菜单名称、父级和排序 |

页面包含 `page_id`、`title`、`icon` 和 `blocks`。区块只允许：

- `metrics`：`entity_overview` 或 `entity_summary` 查询，1–8 个指标卡。
- `chart`：`entity_trend`、`entity_distribution`、`entity_aggregate`、`entity_histogram` 或 `entity_scatter`。
- `records`：实体、1–20 列、最多 8 个筛选，可选详情、新增、编辑和单条删除。

## DataAppChangeSet

更新字段：

| 字段 | 说明 |
| --- | --- |
| `app_id` | 目标应用 |
| `base_app_version` | 当前应用版本 |
| `base_spec_digest` | 当前规格摘要 |
| `put_pages` | 新增或整体替换的页面 |
| `delete_page_ids` | 删除的页面 |
| `home_page_id` | 删除首页时的新首页 |
| `name`、`description`、`menu` | 可选应用元数据和菜单变更 |

模型不能重命名已有 `page_id`，不能删除最后一页，不能指定文件路径、菜单类型、菜单路由、菜单参数、AMIS 节点、URL 或脚本。

## 固定接口绑定

| 区块或动作 | 服务端绑定 |
| --- | --- |
| 指标 | `/api/v1/entity/overview|summary/query` |
| 图表 | `/api/v1/entity/trend|distribution|aggregate|histogram|scatter/query` |
| 带筛选列表 | `POST /api/v1/retrieval/do` |
| 详情 | `GET /api/v1/entity/{entity}/{zenvis_id}/view` |
| 新增 | `POST /api/v1/entity/{entity}/add` |
| 编辑 | `POST /api/v1/entity/{entity}/{zenvis_id}/update` |
| 单条删除 | `DELETE /api/v1/entity/{entity}/{zenvis_id}`，必须二次确认 |

实际部署带网关前缀时，路径以编译结果中的 `/zenvis` 前缀为准。

## 预览与安全

validate 成功后可通过只读 REST 预览读取：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/dih/chat/workflows/{workflowId}/app-preview/site` | 读取 `site.json` |
| GET | `/api/v1/dih/chat/workflows/{workflowId}/app-preview/files?path=...` | 读取清单内页面文件 |

令牌绑定当前用户、会话、工作流和验证尝试，默认 30 分钟有效。接口只读取编译清单内文件，禁止路径穿越；配置目录不会直接暴露。预览模式不渲染新增、编辑和删除动作。

## 错误处理

- `CANDIDATE_MISMATCH`：发布摘要与锁定候选不一致。
- `APP_SNAPSHOT_CHANGED`：版本、规格、Meta 或受管文件在确认后变化。
- `APP_WRITE_FAILED`：配置写入或读回失败，已尝试恢复旧文件。
- `MENU_PUBLISH_FAILED`：配置成功但菜单失败，返回 `partial_menu`。
- `MENU_RETRY_FAILED`：菜单重试仍失败，保持 `partial_menu`。
- `APP_VALIDATING` 阶段拒绝：尚未完成业务发布确认或卡片已陈旧；刷新会话并使用最新预览卡确认，不要由模型直接调用 apply。
- `缺少可视化应用选择记录标识`：会话、消息或预览/发布卡 part ID 任一缺失，通常来自旧卡或未完整持久化的消息；重新执行 validate 并只使用新生成的预览卡。

同一失败最多重试 2 次。配置和菜单成功前不得输出 `verified` 应用记录。
