# MCP Tool 权限、审批与运行约束

ZenVis 在工具进入 Agent、模型发起调用和工具真正执行三个阶段分别实施范围过滤、策略判断和审计。工具出现在静态目录中，不代表任意 Agent 都能调用。

## 默认策略与风险

每个内置工具通过 `@McpToolApproval` 声明：

| 策略 | 行为 |
| --- | --- |
| `ALLOW` | 无人工审批即可执行，但仍记录调用 |
| `ASK` | 执行前产生审批请求 |
| `DENY` | 禁止调用 |

风险等级包括 `LOW`、`MEDIUM`、`HIGH`、`UNKNOWN`。当前内置读取工具通常是 `ALLOW/LOW`，写入、删除、应用配置、创建任务和运行调度通常是 `ASK/HIGH`。

超级管理员可通过 [MCP 服务管理 REST API](/08-API参考/RestfulAPI/MCP服务管理.md#工具策略) 配置覆盖策略。有效策略计算为：

```text
configured_policy 非空 ? configured_policy : default_policy
```

设置 `DENY` 后，全局策略优先于会话授权、任务授权、Agent scope 和 Skill 声明。

## 工具身份

| 来源 | 稳定策略键 |
| --- | --- |
| 本地工具 | `local::<toolName>` |
| 外部工具 | `external::<serverId>::<originalToolName>` |

外部工具还具有 `serverCode`、原始工具名和经过 Spring AI 格式化的 Agent 工具名。审批和授权绑定精确 `tool_key`，不能只按显示标题或相似名称匹配。

## 审批范围

| Scope | 来源 | 作用 |
| --- | --- | --- |
| `ONCE` | `approved` | 只批准当前 `request_id` |
| `SESSION` | `approved_session` | 当前用户、Chat 会话和精确工具持续允许 |
| `TASK_AUTO` | AI 分析任务 `AUTO` 模式 | 当前自动审批调用的审计标记 |
| `TASK_RUN` | `approved_task` | 当前任务 execution 和精确工具持续允许 |

拒绝使用 `rejected`。聊天审批支持 `approved`、`approved_session`、`rejected`；任务审批额外支持 `approved_task`。

普通审批超时由：

```properties
app.ai.mcp.approval.timeout-seconds=300
```

控制，最小按 1 秒处理。AI 分析任务的人工审批可以挂起等待决定或任务取消。服务重启会把未完成工具调用标记为失效；已产生的外部副作用不会自动回滚。

## 调用状态

调用审计状态：

```text
PENDING
  → APPROVED
  → RUNNING
  → SUCCEEDED / FAILED

PENDING
  → REJECTED / EXPIRED / CANCELLED

任意调用
  → DENIED（有效策略为 DENY）
```

终态为 `SUCCEEDED`、`FAILED`、`REJECTED`、`DENIED`、`EXPIRED`、`CANCELLED`。审计渠道包括 `CHAT_AGENT`、`BACKGROUND_AGENT`、`MCP_SERVER`、`MANUAL`。

## Agent scope

全局开关：

```properties
app.ai.mcp.enabled=true
```

按 Agent 类型配置外部 Server 范围：

```properties
app.ai.mcp.agent-scopes.default=*
app.ai.mcp.agent-scopes.<agentType>=server-a,server-b
```

值语义：

| 值 | 含义 |
| --- | --- |
| `*`、`all` 或空 | 允许全部已启用外部 Server |
| 逗号分隔服务代码 | 只允许列出的 Server |
| `none`、`off`、`false`、`disabled` | 禁用该 Agent 的 MCP |

未配置 Agent 专用 scope 时回退到 `default`，默认是全部外部 Server。全局关闭时返回空工具上下文。

## Skill allowlist 与工具边界

Skill runtime 通过 allowlist 声明可使用的工具：

```json
{
  "tools": {
    "local": [
      "retrieval_list_entity",
      "retrieval_list_attribute",
      "retrieval_search"
    ],
    "mcp": {
      "asset-center": [
        "asset_query"
      ]
    }
  }
}
```

- `local` 是 ZenVis 内置工具原始名称白名单。
- `mcp` 的 key 是外部 Server `code`，value 是该 Server 原始工具名白名单。
- Agent scope 和 Skill Server 范围取交集。
- 显式选择了 Skill 但 Skill 没有工具边界时，平台不会自动放开全部工具。
- 已声明空列表表示不给该 Skill 对应工具。

数据可视化 Agent 还具有专用限制：

- `entity_aggregate`
- `entity_histogram`
- `entity_scatter`

这三个工具会从其他 Agent 的集合中排除；数据可视化 Agent 也必须由所选 Skill 明确允许本地工具。

## 单轮工具预算

Skill 可提供正整数覆盖值；缺失或非正数回退到平台默认：

| 配置 | 默认值 | 说明 |
| --- | ---: | --- |
| `app.ai.dih.agent.default-limits.max-tool-calls` | 8 | 单轮最大工具调用次数 |
| `app.ai.dih.agent.default-limits.max-repeated-failures` | 2 | 同类重复失败上限 |
| `app.ai.dih.agent.default-limits.max-tool-result-chars` | 8000 | 单次工具结果字符数 |
| `app.ai.dih.agent.default-limits.max-accumulated-tool-result-chars` | 24000 | 累计结果字符数 |
| `app.ai.dih.agent.default-limits.max-accumulated-tool-result-tokens` | 12000 | 累计结果估算 Token |

对应环境变量：

```text
AI_DIH_MAX_TOOL_CALLS
AI_DIH_MAX_REPEATED_FAILURES
AI_DIH_MAX_TOOL_RESULT_CHARS
AI_DIH_MAX_ACCUMULATED_TOOL_RESULT_CHARS
AI_DIH_MAX_ACCUMULATED_TOOL_RESULT_TOKENS
```

达到预算后 Agent 应基于已有结果作答或说明限制，不能通过递归、换名或重复查询绕过。

## 不同运行场景

### Chat Agent

- `ASK` 产生 NDJSON `approval_required`。
- 会话审批绑定当前用户、Chat ID 和精确工具。
- 删除会话或停止当前生成会清理相应等待状态；全局 `DENY` 始终优先。
- 确定性演示可强制逐次审批，即使存在会话授权。

### 后台 AI 分析任务

- `AUTO` 模式自动批准 `ASK` 并记录 `TASK_AUTO`。
- `MANUAL` 模式进入 `WAITING_APPROVAL`。
- `approved_task` 只覆盖当前 `execution_id`。
- 重新入队会产生新 execution，旧授权失效。

### MCP Server 或管理端测试

- 仍应用同一有效策略和审计包装。
- 首次 `ASK` 不执行底层工具；批准后由受控流程继续。
- 不允许客户端自行构造审批通过状态。

## 运维检查

1. 通过策略列表确认工具 `available`、默认策略和配置覆盖。
2. 通过 `/api/v1/dih/mcp/agent/prompt` 查看某个 Agent 的实际工具集合。
3. 用调用审计按 `request_id`、工具、状态、任务或 execution 查询全过程。
4. 修改 Skill 或 scope 后重新检查工具提示词。
5. 对 `HIGH` 工具抽查审批参数是否足以识别真实副作用。
