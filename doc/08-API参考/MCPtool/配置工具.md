# 配置 MCP 工具

当前配置工具共 10 个：`ConfigMcpTool` 提供 9 个读取、草稿展开、变更或路径操作能力，`ConfigValidationMcpTool` 提供 1 个静态校验能力。

## 工具清单

| 工具名 | 参数 | 返回 | 默认策略 | 风险 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `config_tree` | `type: String` | `List<ConfigVo>` | `ALLOW` | `LOW` | 获取配置类型的文件树 |
| `config_schema` | `type: String`、`fileName: String` | Object | `ALLOW` | `LOW` | 读取文件对应的 JSON Schema |
| `config_read` | `type: String`、`fileName: String` | String | `ALLOW` | `LOW` | 读取配置文件全文 |
| `config_meta_draft` | `fileName: String`、`draft: String` | `MetaConfigDraftService.DraftResult` | `ALLOW` | `LOW` | 将精简实体/字段草稿确定性展开为完整 Meta JSON，不写文件 |
| `config_apply` | `type: String`、`configDto: ConfigDto`、可选 `force: Boolean` | Boolean | `ASK` | `HIGH` | 保存并应用现有配置；Meta 默认拒绝未通过校验的候选 |
| `config_add` | `type: String`、`configDto: ConfigDto` | Boolean | `ASK` | `HIGH` | 创建空配置文件；正文由 `config_apply` 写入 |
| `config_rename` | `type: String`、`fileName: String`、`newFileName: String` | `ConfigPathOperationResult` | `ASK` | `HIGH` | 在同一父目录内重命名配置文件或目录，禁止覆盖 |
| `config_delete` | `type: String`、`fileName: String`、`recursive: Boolean` | `ConfigPathOperationResult` | `ASK` | `HIGH` | 删除文件或目录；非空目录必须显式递归 |
| `config_ensure_root` | `type: String` | Boolean | `ASK` | `HIGH` | 幂等创建配置类型根目录 |
| `config_validate` | `type: String`、`fileName: String`、`text: String` | `ConfigValidationResult` | `ALLOW` | `LOW` | 静态校验格式、结构和可用 Schema |

工具 Schema 的顶层参数使用 `fileName`、`configDto`；`ConfigDto` 内部字段以工具实际 JSON Schema 为准，核心字段为 `file_name` 和 `text`。

## 推荐调用顺序

修改现有配置：

```text
config_tree
  → config_read
  → config_schema（存在时）
  → config_meta_draft（Meta 精简草稿，推荐）
  → 生成候选文本
  → config_validate
  → 向用户展示变更
  → config_apply（需要审批）
  → config_read 复核
```

新建低代码配置：

```text
config_ensure_root（需要审批）
  → config_add（需要审批）
  → config_validate
  → config_apply（需要审批）
  → config_read 复核
```

重命名或删除配置：

```text
config_tree（确认源路径、目标路径与目录成员）
  → config_read（需要确认影响范围时）
  → 用户确认
  → config_rename / config_delete（需要审批）
  → config_tree + config_read 核验路径与内容
  → Meta 严格重载并刷新 Schema
```

路径操作不经过 `config_add` / `config_apply`，不会改写文件正文。`config_rename` 的
`newFileName` 只能是同一父目录下的单个名称；`config_delete` 对非空目录默认拒绝，
必须由调用方显式传 `recursive=true`。配置类型根目录始终不可重命名或删除。

## 参数说明

### `type`

配置类型，例如 `web`、`agent`、`meta`、`device_id`，也可以是低代码配置索引。服务端负责把类型解析到受控配置根目录，工具不允许访问该目录之外的文件。

### `ConfigDto`

```json
{
  "file_name": "example.json",
  "text": "{\"enabled\":true}",
  "commit_msg": "更新示例配置"
}
```

`config_apply` 要求文件已存在；`config_add` 要求文件不存在，只创建空文件，不会把 `text` 写入正文。`config_apply` 对 `meta` 等类型不仅保存文件，还会触发对应的应用动作，例如严格重载元数据和刷新 ClickHouse Schema。

Meta 的 `config_apply` 默认执行服务端语义校验；未通过时拒绝修改文件，也不会触发应用。只有已经通过工作流 `force_approve` 的用户显式确认，才可以传入 `force=true`。强制写入必须在结果中保留 `forced` 和真实校验状态，不能伪装成校验通过。

### `ConfigValidationResult`

返回字段：

| 字段 | 说明 |
| --- | --- |
| `passed` | 静态校验是否通过 |
| `blocked` | 是否因格式需要专项验证而阻断 |
| `configType` | 归一化后的配置类型，例如 `meta` |
| `fileName` | 被校验的文件名 |
| `format` | 识别出的格式 |
| `errors` | 必须修复的问题 |
| `warnings` | 风险或专项校验提示 |
| `normalizedText` | 确定性规范化后的完整文本；通过时应使用该文本写入 |
| `candidateDigest` | 候选配置的稳定摘要，用于锁定确认卡和强制写入 |
| `diagnostics` | Meta 深度校验诊断，元素含 `code`、`path`、`severity`、`message`、`repairHint` |
| `repairs` | 平台可确定的修复项，元素含 `path`、`before`、`after`、`reason` |

Meta 类型会额外执行实体、字段、操作符、`auto_create`、TTL、链接模板、跨文件冲突和保留字段等语义检查；结果会一次性返回全部诊断，而不是只返回第一条异常。`errors` 保留为兼容字段，智能体修订时应优先按 `diagnostics[].path` 与 `repairHint` 定位问题。

当前通用验证支持 JSON、Properties、CSV、XML、Conf 和文本结构。YAML 等需要运行环境专项验证的格式可能返回 `blocked=true`，不能把静态校验通过解释为配置在目标运行时一定可用。

### `ConfigPathOperationResult`

| 字段 | 说明 |
| --- | --- |
| `success` | 操作是否整体成功 |
| `operation` | `rename` 或 `delete` |
| `kind` | `file` 或 `directory` |
| `sourcePath` | 配置根下的相对源路径 |
| `targetPath` | 重命名目标路径；删除为空 |
| `changed` | 文件系统是否已真实变更 |
| `applied` | Meta 严格重载与 Schema 刷新是否成功；非 Meta 类型文件操作完成为 true |
| `affectedPaths` | 受影响的文件和目录相对路径 |
| `message` | 成功摘要或真实失败原因 |

当 `changed=true` 且 `applied=false` 时，文件系统操作已发生但 Meta 未成功生效。
调用方必须保留现场、展示失败状态并允许重试，不得回滚或宣称应用成功。

## 示例

读取 Schema：

```json
{
  "type": "web",
  "fileName": "system_info.json"
}
```

校验候选配置：

```json
{
  "type": "web",
  "fileName": "system_info.json",
  "text": "{\"displayName\":\"ZenVis\",\"enabled\":true}"
}
```

应用候选配置：

```json
{
  "type": "web",
  "configDto": {
    "file_name": "system_info.json",
    "text": "{\"displayName\":\"ZenVis\",\"enabled\":true}",
    "commit_msg": "更新系统名称"
  }
}
```

强制写入仅在元数据工作流已经完成二次确认后使用：

```json
{
  "type": "meta",
  "configDto": {
    "file_name": "example_event.json",
    "text": "<锁定候选>"
  },
  "force": true
}
```

## 安全约束

- `config_validate` 不写文件，也不替代运行时专项检查。
- 未读取原文件和 Schema 前不得直接生成覆盖内容。
- 审批卡应展示目标类型、文件名以及关键旧值/新值。
- 不在配置正文或审批描述中回显 Token、密码等敏感值。
- `config_ensure_root` 是幂等操作，但仍会改变文件系统，默认需要审批。
- 路径操作默认禁止路径逃逸、符号链接逃逸、根目录操作和目标覆盖。
- 删除 Meta 只移除配置文件与运行态定义，不删除 ClickHouse 表或历史数据。
