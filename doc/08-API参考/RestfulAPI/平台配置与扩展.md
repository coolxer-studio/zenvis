# 平台配置与扩展 API

本页合并配置、首页看板、看板管理、插件生命周期和数据推送代理接口，共 5 个 Controller、37 个路由。

## ConfigController

基础路径：`/api/v1/config/{type}`

`type` 是配置类型或低代码配置索引，例如 `web`、`agent`、`meta`、`device_id`。服务端只允许在对应配置根目录中访问文件。

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/config/{type}/tree` | 路径 `type` | `List<ConfigVo>`，配置文件树 |
| GET | `/api/v1/config/{type}/schema` | query `file_name` | JSON Schema 对象 |
| GET | `/api/v1/config/{type}/read` | query `file_name` | 包装后的文件文本 |
| GET | `/api/v1/config/{type}/get` | query `file_name` | 不使用 `ResponseWrap` 的配置对象 |
| POST | `/api/v1/config/{type}/modify` | `ConfigDto` | 保存现有文件 |
| POST | `/api/v1/config/{type}/apply` | `ConfigDto` | 保存并执行对应配置类型的应用动作 |
| POST | `/api/v1/config/{type}/add` | `ConfigDto` | 新建文件 |
| POST | `/api/v1/config/{type}/rename` | `ConfigDto` | 重命名文件 |
| POST | `/api/v1/config/{type}/delete` | `ConfigDto` | 删除文件 |

`ConfigDto`：

| 字段 | 说明 |
| --- | --- |
| `file_name` | 文件全名，必填 |
| `original_file_name` | 重命名时的原文件名 |
| `text` | 完整配置文本 |
| `commit_msg` | 提交说明 |
| `id` | 兼容备用字段 |

`modify` 只保存；`apply` 会先保存再触发类型相关的重载动作。修改前应先读取 Schema 和原文件，写入后再读取验证。需要通过 Agent 修改配置时，优先使用带审批策略的 [配置 MCP 工具](/08-API参考/MCPtool/配置工具.md)。

## HomeBoardController

基础路径：`/api/v1/dashboard/home`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/dashboard/home/overview` | 无 | `SystemOverviewVo`，系统状态概览 |
| GET | `/api/v1/dashboard/home/entity-statistics` | query `range`，默认 `TODAY` | `EntityStatisticsVo`，实体趋势和数据量排行 |

`range` 使用 `EntityStatisticsRange` 枚举。首页接口只提供摘要；需要多维统计、直方图或关系分析时使用[实体分析接口](/08-API参考/RestfulAPI/数据检索与实体.md#entityanalyticscontroller)。

## DashboardController

基础路径：`/api/v1/system/dashboard`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/system/dashboard/add` | `DashboardDto` | 创建看板 |
| DELETE | `/api/v1/system/dashboard/{id}` | 看板 ID | 删除看板 |
| DELETE | `/api/v1/system/dashboard/bulk/{ids}` | 看板 ID 列表 | 批量删除 |
| POST | `/api/v1/system/dashboard/{id}/update` | 看板 ID、`DashboardDto` | 更新看板 |
| POST | `/api/v1/system/dashboard/{ids}/bulk-update` | 看板 ID 列表、`DashboardDto` | 批量更新 |
| GET | `/api/v1/system/dashboard/list` | `DashboardSearchDto` query | `PageRowsVo<DashboardVo>` |
| GET | `/api/v1/system/dashboard/{id}/view` | 看板 ID | `DashboardVo` |
| GET | `/api/v1/system/dashboard/type/list` | 无 | 看板类型选项 |
| POST | `/api/v1/system/dashboard/list` | 无 | 全部看板列表 |

注意：同一路径 `/list` 同时存在 GET 和 POST。GET 用于分页管理列表，POST 返回全部用户自定义看板。

`DashboardDto` 主要字段：

| 字段 | 说明 |
| --- | --- |
| `name`、`code` | 名称和业务编码 |
| `type` | `DashboardType` |
| `url` | 路由或外部地址 |
| `config_index` | 低代码配置索引 |
| `html_path` | HTML 看板相对路径 |
| `is_default` | 是否默认；更新时为 `null` 表示保留原值 |
| `source` | 来源，用于标识插件导入资源 |

设置新的默认看板会替换原默认项；批量更新不能同时产生多个默认看板。HTML 路径必须是平台允许的相对路径。

## PluginController

基础路径：`/api/v1/system/plugin`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/system/plugin/upload` | multipart `file` | 上传并解析插件包 |
| POST | `/api/v1/system/plugin/icon/base64` | multipart `file` | 将图标转换为 Base64 |
| POST | `/api/v1/system/plugin/add` | `PluginDto` | 创建插件记录 |
| DELETE | `/api/v1/system/plugin/{id}` | 插件 ID | 删除插件记录 |
| DELETE | `/api/v1/system/plugin/bulk/{ids}` | 插件 ID 列表 | 批量删除 |
| GET | `/api/v1/system/plugin/list` | `PluginSearchDto` query | `PageRowsVo<PluginVo>` |
| GET | `/api/v1/system/plugin/{id}/view` | 插件 ID | `PluginVo` |
| GET | `/api/v1/system/plugin/{id}/readme` | 插件 ID | README Markdown |
| GET | `/api/v1/system/plugin/{id}/doc/tree` | 插件 ID | 插件文档树 |
| GET | `/api/v1/system/plugin/{id}/doc/view` | query `file` | 指定 Markdown 文档内容 |
| ANY | `/api/v1/system/plugin/{id}/export` | 插件 ID | 下载插件归档；当前代码使用未限定方法的 `@RequestMapping` |
| GET | `/api/v1/system/plugin/{id}/logs` | 插件 ID | 安装/升级日志流 |
| POST | `/api/v1/system/plugin/{id}/install` | 插件 ID | 安装插件 |
| POST | `/api/v1/system/plugin/{id}/upgrade` | `PluginUpgradeDto` | 升级插件 |
| POST | `/api/v1/system/plugin/{id}/upgrade/recover` | 插件 ID | 恢复升级前版本 |
| POST | `/api/v1/system/plugin/{id}/uninstall` | 插件 ID | 卸载插件 |

`PluginDto` 包含 `name`、`icon`、`package_name`、`version`、`description`、`author`、`plugin_path`。`name` 和 `package_name` 必填，包名必须唯一。

调用顺序通常是：

1. 上传插件包并检查解析结果。
2. 创建或更新插件记录。
3. 调用安装/升级。
4. 持续读取 `/logs`，直到日志包含完成或失败标记。
5. 安装失败时检查日志；升级失败可调用恢复接口。

插件文档内容由插件包维护；路径必须来自 `/doc/tree`，不要允许用户提交任意服务器文件路径。

## PushTaskController

基础路径：`/api/v1/system/push-task`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| ANY | `/api/v1/system/push-task/**` | 原始路径、query、header 和 body | 代理到 Vectum `/vectum/api/v1/task/**` |

当前 Controller 不是一组独立 CRUD 路由，而是一个通配代理：

- 去掉 ZenVis 前缀 `/api/v1/system/push-task`，替换为 Vectum `/vectum/api/v1/task`。
- 保留 HTTP 方法、query 和请求体。
- 转发普通请求头，但会移除调用方的 `Authorization`。
- 如配置 `app.services.data.bearer-token`，使用该值重新设置下游 Bearer Token。
- 下游基础地址来自 `app.services.data.url`。
- 只有下游 HTTP 200 会原样返回字符串响应；其他状态或转发异常转换为 ZenVis 失败。

因此 `/add`、`/{id}`、`/{id}/toggle`、日志等子路径属于所连接 Vectum 版本的契约，不应被描述成 `PushTaskController` 自己声明的固定路由。需要 Agent 创建、检查或修复受管推送任务时，使用[数据推送 MCP 工具](/08-API参考/MCPtool/数据推送工具.md)，这些工具在服务层提供更严格的来源和审批约束。

## 变更安全

- 配置应用、插件安装升级、推送任务写操作都可能改变运行状态，应由管理员执行并保留审计记录。
- 不把 API Token、MCP Token 或下游数据服务 Token 写入配置正文、日志或示例。
- 插件导入前验证包结构、版本和来源；生产升级前准备可恢复版本。
- 删除配置、插件或默认看板前先检查引用关系。
