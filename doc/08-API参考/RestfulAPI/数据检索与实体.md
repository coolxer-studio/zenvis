# 数据检索与实体 API

本页合并检索规则、动态实体 CRUD 和实体统计分析接口，共 3 个 Controller、32 个路由。所有实体名和字段名都必须使用 Meta 中的逻辑 `name`，不能传物理表名、物理列名或任意 SQL。

## RetrievalController

基础路径：`/api/v1/retrieval`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/retrieval/do` | `RetrievalRequestDto` | `DataListVo`，执行条件检索 |
| POST | `/api/v1/retrieval/rule/create` | `RetrievalRuleCreateDto` | `IdVo`，创建当前用户的检索规则 |
| POST | `/api/v1/retrieval/rule/update` | `RetrievalRuleUpdateDto` | `IdVo`，更新当前用户的检索规则 |
| POST | `/api/v1/retrieval/rule/delete` | `RetrievalRuleDeleteDto` | 删除当前用户的检索规则 |
| GET | `/api/v1/retrieval/rule/list` | 无 | `DataListVo`，规则列表 |
| GET | `/api/v1/retrieval/rule/get` | query `id` | 原始 `RetrievalRule` |
| GET | `/api/v1/retrieval/rule/detail` | query `id` | `RetrievalRuleDetailVo`，逻辑配置、当前 Meta 和失效项 |
| GET | `/api/v1/retrieval/entity/list` | query `rule_id?` | `DataEntityResultVo` |
| GET | `/api/v1/retrieval/attribute/list` | query `entity?`、`rule_id?` | 条件字段 Meta |
| GET | `/api/v1/retrieval/candidate/list` | `attributeId?` 或 `entity`+`attribute`，`text?` | 候选值 |
| GET | `/api/v1/retrieval/display/entity/list` | query `rule_id?` | 展示实体 Meta |
| GET | `/api/v1/retrieval/display/attribute/list` | query `entity?`、`rule_id?` | 展示字段 Meta |

### 检索请求

```json
{
  "type": "normal",
  "entity": "asset",
  "criteria_logic": "and",
  "criteria_list": [
    {
      "attribute": "ip",
      "operator": "equal",
      "value_list": ["10.0.0.1"]
    }
  ],
  "display_list": [
    {
      "entity": "asset",
      "attribute_list": ["ip", "device_name"]
    }
  ],
  "page": 1,
  "size": 20,
  "sort_by": "device_name",
  "order": "asc"
}
```

| 字段 | 说明 |
| --- | --- |
| `type` | `normal` 或 `advanced` |
| `entity` | 当前逻辑实体名 |
| `criteria_list` | 普通检索条件 |
| `criteria_logic` | `and` 或 `or` |
| `sql` | 高级 Where 表达式，不是完整 SQL |
| `display_list` | 展示实体与逻辑字段 |
| `page`、`size` | 页码和检索页大小 |
| `sort_by`、`order` | 逻辑排序字段，方向 `asc/desc` |

`display_list` 必须存在，只允许一个展示实体且必须与 `entity` 一致。普通条件最多 50 个，展示字段最多 100 个。REST 检索的 `size` 上限以当前 DTO/服务校验为准；对应 MCP 工具进一步限制为 50。

常用操作符：

| 操作符 | 说明 |
| --- | --- |
| `equal`、`notequal` | 等于、不等于 |
| `match`、`contains` | 模糊匹配 |
| `greatthan`、`greatequalthan` | 大于、大于等于 |
| `lessthan`、`lessequalthan` | 小于、小于等于 |
| `between` | 两个值之间 |
| `in` | 值集合 |
| `isnull`、`isnotnull` | 空、非空 |

字段最终可用操作符以属性 Meta 返回的 `operator_list` 为准。保存规则时使用逻辑配置；读取 `/rule/detail` 可以识别 Meta 变更后失效的实体、字段或候选值。

## EntityCoreController

基础路径：`/api/v1/entity/{entity}`

`entity` 是 Meta 逻辑实体名；记录主键是平台 `zenvis_id` UUID。

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/entity/{entity}/add` | 动态 JSON 字段 Map | 新增记录 |
| DELETE | `/api/v1/entity/{entity}/{id}` | `zenvis_id` | 删除记录 |
| DELETE | `/api/v1/entity/{entity}/bulk/{ids}` | ID 列表 | 批量删除 |
| POST | `/api/v1/entity/{entity}/{id}/update` | 动态 JSON 字段 Map | 更新记录 |
| POST | `/api/v1/entity/{entity}/{ids}/bulk_update` | ID 数组、动态 JSON 字段 Map | 批量更新；注意路径使用下划线 |
| GET | `/api/v1/entity/{entity}/list` | 动态 query、`page`、`per_page` | `PageRowsVo<Map>` |
| GET | `/api/v1/entity/{entity}/{id}/view` | `zenvis_id` | 单条动态记录 |
| GET | `/api/v1/entity/{entity}/{attribute}/mapping` | 逻辑字段名 | 映射选项 |
| GET | `/api/v1/entity/{entity}/{attribute}/list` | 逻辑字段名 | 去重值选项 |
| GET | `/api/v1/entity/{entity}/{attribute}/auto-complete` | query `term?` | 相似值选项 |

新增和更新请求只提交 Meta 定义的业务字段。平台维护字段由服务端管理：

- `zenvis_id`
- `zenvis_insert_time`
- `zenvis_update_time`

列表 query 中的业务过滤和排序同样必须使用逻辑字段名。动态实体结构因 Meta 配置不同而不同，接入方应先通过 Retrieval Meta 接口获取字段，而不是硬编码任意实体的 Schema。

## EntityAnalyticsController

基础路径：`/api/v1/entity`

十个接口均使用 POST，返回统一 `AnalyticsResponse`，其中包含查询 `meta`、表格 `result` 和可直接交给 ECharts `setOption` 的纯 JSON `echarts.option`。

| 方法 | 路径 | 请求类型 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/entity/overview/query` | `OverviewQueryRequest` | 多实体累计量、当前周期和对比周期 |
| POST | `/api/v1/entity/summary/query` | `SummaryQueryRequest` | 单实体多指标汇总 |
| POST | `/api/v1/entity/trend/query` | `TrendQueryRequest` | 按时间粒度生成趋势 |
| POST | `/api/v1/entity/distribution/query` | `DistributionQueryRequest` | 任意标量字段 TopN |
| POST | `/api/v1/entity/aggregate/query` | `AggregateQueryRequest` | 最多两个维度的多指标聚合 |
| POST | `/api/v1/entity/histogram/query` | `HistogramQueryRequest` | 数值字段直方图 |
| POST | `/api/v1/entity/scatter/query` | `ScatterQueryRequest` | 散点图或气泡图有限取样 |
| POST | `/api/v1/entity/value-statistics/query` | `ValueStatisticsQueryRequest` | 指定值跨实体字段统计 |
| POST | `/api/v1/entity/relations/query` | `RelationQueryRequest` | 源字段与目标字段关系聚合 |
| POST | `/api/v1/entity/relation-timeline/query` | `RelationTimelineQueryRequest` | 关系分类时间轴 |

### 公共分析约定

- 时间预设：`TODAY`、`YESTERDAY`、`LAST_24_HOURS`、`LAST_7_DAYS`、`LAST_30_DAYS`、`THIS_MONTH`、`CUSTOM`；部分接口支持 `ALL_TIME`。
- 时间粒度：`AUTO`、`MINUTE`、`FIVE_MINUTES`、`FIFTEEN_MINUTES`、`HOUR`、`DAY`、`WEEK`、`MONTH`、`QUARTER`、`YEAR`。
- 对比方式：`NONE`、`PREVIOUS_PERIOD`、`YEAR_OVER_YEAR`。
- 条件继续使用 `criteria_list[{attribute,operator,value_list}]` 和 `criteria_logic`。
- 时间字段默认 `zenvis_insert_time`，也可显式指定 Meta 日期时间逻辑字段。
- 分组、关系和分类字段必须是兼容的标量类型。
- 请求不接受 SQL、物理标识符、任意 URL、JavaScript 或前端 adaptor。

### 示例

```json
{
  "entity": "traffic",
  "dimensions": [
    {
      "name": "day",
      "field": "event_time",
      "kind": "TIME",
      "granularity": "DAY"
    },
    {
      "name": "action",
      "field": "action",
      "kind": "FIELD"
    }
  ],
  "metrics": [
    {"name": "records", "operation": "COUNT"},
    {"name": "bytes", "operation": "SUM", "field": "bytes_sent"}
  ],
  "time_range": {"preset": "LAST_30_DAYS"},
  "criteria_list": [],
  "criteria_logic": "and",
  "limit": 200,
  "chart_hint": "AREA"
}
```

指标支持 `COUNT`、`DISTINCT_COUNT`、`SUM`、`AVG`、`MIN`、`MAX` 和 `PERCENTILE`。多维聚合最多两个维度、20 个指标、50 个条件；直方图区间 5–100；散点默认 500、最大 2000 个点；分布 TopN 最大 100。

## 查询与写入安全

- 获取实体和字段 Meta 后再构造请求，始终使用 `name`，`label` 只用于展示。
- 写接口会改变实体数据，应限制调用者权限；Agent 写操作默认要求审批。
- 关系、聚合和图表查询必须使用服务端受控能力，不允许拼接 SQL。
- 查询返回可能被截断，应检查 `meta.truncated`、`has_more` 等字段。
