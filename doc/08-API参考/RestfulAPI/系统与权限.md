# 系统与权限 API

本页合并系统信息、登录、用户、角色、菜单与权限接口，共 5 个 Controller、36 个路由。除登录流程自身外，管理接口均要求有效 Session 或 REST API Bearer Token。

## AboutController

基础路径：`/api/v1/system/about`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/system/about/info` | 无 | `SystemInfoVo`，查询产品与系统信息 |
| PUT | `/api/v1/system/about/info/update` | JSON `SystemInfoDto` | 更新系统标题、产品、版本、介绍及联系信息 |
| POST | `/api/v1/system/about/icon/upload` | multipart `file` | 上传浏览器图标 |
| POST | `/api/v1/system/about/logo/upload` | multipart `file` | 上传系统 Logo |
| POST | `/api/v1/system/about/banner/upload` | multipart `file` | 上传系统 Banner |

`SystemInfoDto` 字段：

| 字段 | 说明 |
| --- | --- |
| `system_title` | 系统标题 |
| `product_name`、`product_version` | 产品名称与版本 |
| `product_introduction` | 产品介绍 |
| `service_phone`、`service_email` | 服务电话与邮箱 |
| `technical_email` | 技术支持邮箱 |
| `integrate_link` | 集成链接 |
| `copyright` | 版权信息 |

上传接口字段名固定为 `file`，成功时返回 `SingleValueVo` 或空成功响应。品牌文件通过 `/system-files/{filename}` 访问。

## LoginController

基础路径：`/api/v1/system/login`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/system/login/sign-in` | `LoginDto` | `LoginVo`，创建登录会话 |
| GET | `/api/v1/system/login/kaptcha` | 无 | 验证码图片并在 Session 保存验证码 |
| GET | `/api/v1/system/login/encrypt/key` | 无 | `PubKeyVo`，返回密码传输公钥 |
| POST | `/api/v1/system/login/sign-out` | Cookie/Session | 注销当前会话 |

登录请求：

```json
{
  "user_name": "admin@admin.com",
  "password": "<使用公钥加密后的密码>",
  "auth_code": "ABCD"
}
```

浏览器应保持登录、验证码和后续 API 使用同一个 Cookie 会话。服务对服务调用不要模拟验证码登录，应使用 [REST API Bearer Token](/08-API参考/RestfulAPI/概览与接入.md#rest-api-bearer-token)。

## UserController

基础路径：`/api/v1/system/user`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/system/user/add` | `UserDto` | 创建用户 |
| DELETE | `/api/v1/system/user/{id}` | 用户 ID | 删除用户 |
| POST | `/api/v1/system/user/{id}/update` | 用户 ID、`UserDto` | 更新用户 |
| POST | `/api/v1/system/user/{ids}/bulk-update` | 逗号分隔 ID、`UserDto` | 批量更新 |
| GET | `/api/v1/system/user/list` | `UserSearchDto` 查询参数 | `PageRowsVo<UserVo>` |
| GET | `/api/v1/system/user/{id}/view` | 用户 ID | `UserVo` |
| POST | `/api/v1/system/user/update-password` | `PasswordChangeDto` | 修改当前用户密码 |

`UserDto` 的主要字段是 `email`、`name`、`password`、`role_id`。邮箱必填且必须合法；用户名长度 2–50；密码长度 6–20。修改密码请求包含 `old_password` 和 `password`，操作对象始终是当前认证用户。

列表查询继承分页参数，并可按 `name`、`email`、角色等 `UserSearchDto` 字段过滤。返回对象不应向调用方暴露密码。

## RoleController

基础路径：`/api/v1/system/role`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/system/role/add` | `RoleDto` | 创建角色 |
| DELETE | `/api/v1/system/role/{id}` | 角色 ID | 删除角色 |
| DELETE | `/api/v1/system/role/bulk/{ids}` | 角色 ID 列表 | 批量删除 |
| POST | `/api/v1/system/role/{id}/update` | 角色 ID、`RoleDto` | 更新角色 |
| POST | `/api/v1/system/role/{ids}/bulk-update` | 角色 ID 列表、`RoleDto` | 批量更新 |
| GET | `/api/v1/system/role/list` | `RoleSearchDto` 查询参数 | `PageRowsVo<RoleVo>` |
| GET | `/api/v1/system/role/{id}/view` | 角色 ID | `RoleVo` |
| GET | `/api/v1/system/role/type/list` | 无 | 角色下拉选项 |
| GET | `/api/v1/system/role/permission/tree` | 无 | 完整菜单权限树 |

`RoleDto` 包含角色 `name` 和以逗号分隔的 `menu_ids`。权限树来源于当前菜单数据，保存权限时只提交允许分配的菜单 ID。

## MenuController

基础路径：`/api/v1/system/menu`

| 方法 | 路径 | 输入 | 返回/用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/system/menu/add` | `MenuDto` | 创建菜单 |
| DELETE | `/api/v1/system/menu/{id}` | 菜单 ID | 删除菜单 |
| DELETE | `/api/v1/system/menu/bulk/{ids}` | 菜单 ID 列表 | 批量删除 |
| POST | `/api/v1/system/menu/{id}/update` | 菜单 ID、`MenuDto` | 更新菜单 |
| POST | `/api/v1/system/menu/update-order` | `MenuOrderRowDto` | 保存一级、二级菜单排序 |
| POST | `/api/v1/system/menu/{ids}/bulk-update` | 菜单 ID 列表、`MenuDto` | 批量更新 |
| GET | `/api/v1/system/menu/list` | `MenuSearchDto` 查询参数 | 分页菜单树 |
| GET | `/api/v1/system/menu/{id}/view` | 菜单 ID | `MenuVo` |
| GET | `/api/v1/system/menu/parent-menu/list` | 无 | 一级菜单下拉选项 |
| GET | `/api/v1/system/menu/type/list` | 无 | 菜单类型选项 |
| GET | `/api/v1/system/menu/level/list` | 无 | 菜单级别选项 |

`MenuDto`：

| 字段 | 说明 |
| --- | --- |
| `name` | 菜单名称，必填 |
| `type` | 菜单类型枚举 |
| `route`、`params` | 路由与类型相关参数 |
| `create_root_path` | 策略配置类菜单是否创建根目录 |
| `parent_id`、`level` | 父菜单和菜单级别 |
| `order_number` | 排序号 |
| `superscript` | 角标文字 |
| `children` | 子菜单，仅树结构场景使用 |
| `source` | 菜单来源 |

`MenuOrderRowDto.rows` 是排序后的一级菜单列表，每项可包含 `children`；`ids` 是兼容字段。内置且不可编辑的菜单不会被更新或删除。

## 权限与安全注意

- 用户、角色、菜单写操作应限制给管理员。
- Bearer Token 映射用户同样受现有角色权限约束，不等于超级管理员。
- 文件上传应限制大小和媒体类型，生产环境还应在网关层限制请求体。
- 登录密码先取得公钥再加密传输；TLS 仍然是生产环境必需条件。
- 删除角色前应确认没有仍需该角色的用户；删除菜单会影响权限树和导航。
