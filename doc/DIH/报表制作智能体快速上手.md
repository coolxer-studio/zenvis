# 报表制作智能体快速上手

本文用于帮助新同事快速理解报表制作智能体的产品形态、交互方式和核心实现。当前能力目标是把 `agent_report` 从普通聊天升级为类似在线文档的 AI 写作工作台。

## 一句话理解

报表制作智能体由两部分组成：

- **中间对话区**：承接用户指令、附件、AI 回复和流式生成过程。
- **右侧报表文档区**：承载最终可编辑文档，支持保存、归档、复制、Markdown/HTML 下载和局部改写。

当 AI 输出完整报表时，后端会解析 `zenvis:report-document-config` 富消息，前端自动把它同步到右侧编辑器。

## 用户能做什么

### 生成完整报表

用户可以直接描述需求，例如：

```text
请基于当前会话和附件生成一份风险事件复盘报告，包含摘要、时间线、影响范围、原因分析和整改建议。
```

报表智能体会优先生成 Markdown 报表。完整报表一般包含标题、摘要、目录、背景/范围、素材说明、正文分析、关键发现、结论与建议。

### 使用演示示例

新建 `agent_report` 会话时，开场白会提供四个示例按钮：

- 用户事件分析报告
- 运营周报
- 风险事件复盘
- 可视化结论归档报告

这些示例命中后走 `ReportDemoResponseService` 的内置模板，在模型校验前直接返回固定报表草稿，不请求后台模型，也不会触发标题模型。它适合演示、培训和无模型环境下的功能验证。

### 整篇文档级快捷操作

右侧报表面板顶部保留整篇文档级快捷指令：

- 生成初稿
- 继续写
- 正式语气
- 摘要
- 标题
- 结论

这些操作会把当前右侧文档转成 Markdown，随用户指令一起发送到中间对话，要求 AI 返回完整修改后的报表，并输出 `zenvis:report-document-config`。

### 选区局部改写

润色、缩写、扩写不再是顶部按钮。用户需要：

1. 在右侧文档编辑器中选中一段内容。
2. 右键打开选区菜单。
3. 选择润色、缩写或扩写。

前端只把选中的片段发给 AI，并要求只返回处理后的片段。AI 返回后，右侧编辑器只替换原选区，不覆盖整篇报表。

## 核心数据流

### 完整报表同步

```text
AI 回复
  |
  | 输出 ```zenvis:report-document-config
  v
ChatMessagePartParser
  |
  | 解析为 type=report-document
  v
DihChatApplicationService.mergeStructuredExtraData
  |
  | 写入 extraData.report.currentDocument / documents / artifacts
  v
view-center 发布 dihReportRecordsUpdated
  |
  v
view-right-report 注入 wangEditor
```

### 选区改写

```text
用户在右侧编辑器选中文本并右键
  |
  v
view-right-report 缓存选区和片段内容
  |
  | dihReportQuickActionRequested(target=selection)
  v
view-center 发送中间对话请求
  |
  v
AI 返回处理后的片段
  |
  | dihReportSelectionRewriteCompleted
  v
view-right-report 恢复选区并替换片段
```

## 主要文件

### 后端

| 文件 | 作用 |
|---|---|
| `ChatSessionController` | 新会话开场白和报表示例 `prompt-suggestions` |
| `ReportDemoResponseService` | 报表示例内置模板，命中示例时不请求后台模型 |
| `SystemPromptConfig.agentReportSystemPromptTemplate` | 约束报表智能体输出完整报表和 `report-document-config` |
| `ChatMessagePartParser` | 解析 `zenvis:report-document-config` 为 `report-document` |
| `DihChatApplicationService` | 分发 `agent_report`、早期命中演示模板、合并 `extraData.report` |
| `ChatTitleService` | 报表示例会话标题使用本地固定标题，避免演示时请求标题模型 |

### 前端

| 文件 | 作用 |
|---|---|
| `type-dih.ts` | 定义 `ReportDocument`、`ReportArtifact` 和 `report-document` part 类型 |
| `view-center.vue` | 发布/接收报表记录事件，承接快捷写作和选区改写请求 |
| `view-right-report.vue` | 右侧报表工作台、wangEditor、保存归档导出、选区右键菜单 |
| `chat-message-renderer.vue` | 渲染 `report-document` 卡片和 `prompt-suggestions` 示例按钮 |

## 会话扩展数据

当前不新增报表数据库表，报表数据持久化在 `ChatSession.extraData`：

```json
{
  "report": {
    "currentDocument": {
      "id": "文档ID",
      "documentId": "文档ID",
      "title": "报表标题",
      "format": "markdown 或 html",
      "version": "v1.0.0",
      "status": "generated / edited / archived",
      "source": "agent_report",
      "updatedAt": "更新时间",
      "content": "报表正文",
      "outline": [],
      "sourceAttachments": []
    },
    "documents": [],
    "artifacts": []
  }
}
```

- `currentDocument`：右侧编辑器当前展示的文档。
- `documents`：历史生成/编辑文档记录。
- `artifacts`：归档版本，供“归档”页查看和下载。

## 输出协议

完整报表必须放在下面的围栏中：

````markdown
```zenvis:report-document-config
# 报表标题

## 摘要

...
```
````

解析后会得到：

- `part.type = report-document`
- `part.language = markdown 或 html`
- `metadata.configKind = report-document`
- `metadata.defaultFileName = report.md 或 report.html`
- `metadata.title`
- `metadata.format`
- `metadata.version`
- `metadata.updatedAt`
- `metadata.outline`

如果只是回答问题、解释修改建议、选区润色/缩写/扩写，不应该输出完整 `report-document-config`。

## 验证建议

后端重点测试：

```bash
mvn test -Dtest=ReportDemoResponseServiceTest,ChatTitleServiceTest,ChatMessagePartParserTest,DihChatApplicationServiceTest
```

前端重点测试：

```bash
yarn test
```

手工验收建议：

- 新建报表智能体会话，确认出现四个报表示例按钮。
- 点击示例后确认右侧编辑器自动填充草稿，且无需后台模型。
- 编辑文档后保存，刷新会话确认内容恢复。
- 归档后确认归档页出现版本记录。
- 下载 Markdown/HTML，确认文件内容可读。
- 选中一段正文右键润色/缩写/扩写，确认只替换选区。

## 当前边界

- 默认导出 Markdown 和 HTML；DOCX/PDF 后续可接后端导出服务。
- 素材来源优先使用当前会话、附件和已同步结构化记录；跨智能体素材库选择器未纳入当前版本。
- 选区改写依赖前端缓存当前选区，生成期间不要切换或大幅编辑同一文档区域。
