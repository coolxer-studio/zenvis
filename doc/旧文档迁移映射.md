# 旧文档迁移映射

本文记录子项目原文档与 ZenVis 根 `doc/` 的对应关系，用于确认融合后没有遗漏。迁移后的文档按产品主题重新组织，并继续根据当前代码修订；因此“已迁移”表示内容有明确承载位置，不要求修订后的文件与历史版本永远字节相同。

## 2026-07-21 核验结果

| 来源 | 历史源文件 | 已映射 | 目标缺失 | 资源校验 |
| --- | ---: | ---: | ---: | --- |
| 后端 `zenvis-backend/doc` | 135 | 135 | 0 | 83 PNG + 1 JPG 的 SHA-256 全部一致 |
| 前端 `zenvis-frontend/doc` | 4 | 4 | 0 | 共享 Banner 的 SHA-256 一致 |

后端 51 份 Markdown/TypeScript 文档均有独立承载文件，更新后的文件均未缩减到历史文件字节数的 90% 以下；接口和部署文档的差异来自按当前代码修正旧端口、字段、命令、路由与组件版本。插件目录不参与迁移或修改。

## 核验规则

1. 以历史 Git 树中的路径清单为源集合，以本文件中的新路径为目标集合。
2. Markdown 与 TypeScript 要有明确承载文件；图片按文件名和 SHA-256 核验。
3. README 既保留子项目独立入口，也允许在根文档中融合相同内容。
4. 后续代码变更可以修订新文档，但不能删除映射目标而不更新本清单。
5. `plugin-*` 的完整性以任务开始时的路径、状态和 SHA-256 基线为准，不以 Git HEAD 覆盖已有本地状态。
