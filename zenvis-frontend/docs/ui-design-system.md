# ZenVis UI Design System

> 版本：1.1.0 · 主题：`zenvis-light` · 密度：`compact`

本规范用于 ZenVis 主应用、内置低代码页面、可控 HTML 页面和插件看板。目标是让安全运营、数据分析与配置管理场景保持简洁、可信、高密度且易于扫描。Element Plus 是唯一基础 UI 技术栈，业务层不再自行定义另一套基础控件。

## 1. 品牌原则

1. **清晰优先**：先展示任务、状态和风险，再展示装饰。一个区域只保留一个主操作。
2. **紧凑但不拥挤**：默认控件高 32px；表格以扫描效率为主，内容区仍保留 12–24px 的分组间距。
3. **科技感来自秩序**：使用精确对齐、冷色语义、细边框和轻阴影，不依赖大面积渐变与强发光。
4. **状态必须可解释**：颜色不能成为唯一状态载体，同时使用文本、图标或状态点。
5. **全局稳定、局部灵活**：页面壳负责高度与滚动，业务组件负责内容布局；iframe 和全屏看板不继承错误的固定尺寸。

## 2. 设计令牌

`src/assets/styles/tokens.scss` 是样式侧唯一语义令牌源。页面只能引用 `--zv-*`，禁止把品牌色直接写入业务组件。`src/theme/design-tokens.ts` 提供插件协议中的只读令牌子集。

受控例外仅包括登录页品牌背景、全屏看板内容、图表色板以及遮罩/透明叠层。这些场景可在组件根节点定义局部语义变量或使用 `color-mix()` 调整透明度，但业务子元素仍须引用语义令牌；不得在按钮、表格、表单、导航和普通卡片中散落品牌色十六进制值。例外必须在代码中保持局部作用域，并在视觉验收清单中登记。

### 2.1 颜色

| 语义     | 令牌                  | 值        | 用途                             |
| -------- | --------------------- | --------- | -------------------------------- |
| 主色     | `--zv-primary`        | `#2f5ee5` | 主按钮、当前导航、主链接、焦点   |
| 科技强调 | `--zv-accent`         | `#0f9fa3` | 图表辅助序列、连接状态、轻量强调 |
| 成功     | `--zv-success`        | `#0f9f74` | 完成、在线、健康                 |
| 警告     | `--zv-warning`        | `#c27a08` | 风险提醒、等待处理               |
| 危险     | `--zv-danger`         | `#d1435b` | 失败、高风险、破坏性操作         |
| 信息     | `--zv-info`           | `#2563c7` | 一般提示、进行中                 |
| 页面背景 | `--zv-bg-page`        | `#f2f5fa` | 应用内容画布                     |
| 卡片     | `--zv-bg-surface`     | `#ffffff` | 页面壳、卡片、弹窗               |
| 次级背景 | `--zv-bg-subtle`      | `#f7f9fc` | 表头、筛选区、悬停               |
| 主文字   | `--zv-text-primary`   | `#15233a` | 标题、关键数值                   |
| 次级文字 | `--zv-text-secondary` | `#47556b` | 正文、标签                       |
| 辅助文字 | `--zv-text-muted`     | `#66758a` | 描述、时间、辅助信息             |
| 边框     | `--zv-border`         | `#dce4ef` | 控件、卡片                       |
| 分隔线   | `--zv-divider`        | `#e8edf4` | 行、标题栏、弱分组               |

主文字与白色背景需达到 WCAG AA。禁用态也必须可读；不可用状态不能仅通过降低透明度表达。

### 2.2 排版

- 字体：系统 UI 字体栈，中文优先使用现有 Alibaba 字体资源。
- 字号阶梯：12 / 13 / 14 / 16 / 18 / 24 / 32px。
- 正文：14px，行高 1.6；数据表格与表单标签可使用 13px。
- 页面标题：16–18px、600；分组标题：14–16px、600；关键指标：24–32px、600–700。
- 全大写英文仅用于不超过 24 个字符的品牌副标题，字距不超过 `0.12em`。
- 数字默认启用等宽数字。禁止用纯字号放大代替信息层级。

### 2.3 间距、圆角、阴影

- 间距以 4px 为基线：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48px。
- 圆角：4px 用于紧凑控件；6px 用于常规控件；8px 用于卡片；12px 用于弹窗和浮层。
- `--zv-shadow-1`：静态卡片；`--zv-shadow-2`：悬停卡片/顶栏；`--zv-shadow-3`：弹窗、下拉和高层浮层。
- 同一容器不可同时使用粗边框、重阴影和高饱和背景。

### 2.4 图标

- 仅使用 `@element-plus/icons-vue` 和项目已有图标库；常规尺寸 16px，工具栏 18px，空状态 32–48px。
- 图标必须与文字语义一致。纯图标按钮必须有 `aria-label` 和 tooltip。
- 不使用 emoji、文本符号、CSS 绘图或临时 SVG 代替产品图标。

### 2.5 动效

- 快速反馈 120ms，常规过渡 180ms，面板切换 240ms。
- 使用标准缓动 `cubic-bezier(0.2, 0, 0, 1)`；不使用循环发光干扰数据阅读。
- `prefers-reduced-motion: reduce` 下关闭非必要动画和光标滚动。

## 3. 栅格与响应式

| 宽度          | 规则                                                    |
| ------------- | ------------------------------------------------------- |
| `>= 1440px`   | 全宽管理布局，内容边距 24px；资源区 3–4 列，信息区 2 列 |
| `1024–1439px` | 内容边距 16–20px；次要用户文字可隐藏，导航允许收纳      |
| `768–1023px`  | 两列降为单列或窄双列；操作区允许换行                    |
| `< 768px`     | 内容边距 12px；所有面板单列；表格优先横向滚动或卡片化   |
| `390px`       | 主操作满宽；隐藏装饰与低优先级列；文本可换行但不可溢出  |

顶栏固定为 60px。页面应通过父级 flex 的 `min-height: 0` 建立唯一滚动区，禁止使用 `height: 95%`、视口常量减法或全局 `.main-content` 外边距。

## 4. 页面基础组件

### 4.1 UiPage

统一页面标题、说明、操作区和页面内滚动。

```vue
<UiPage title="策略管理" description="维护检测规则和处置流程" padding="normal">
  <template #actions>
    <el-button>导出</el-button>
    <el-button type="primary">新建策略</el-button>
  </template>
  <UiSection title="策略列表">...</UiSection>
</UiPage>
```

`padding` 可为 `normal`（24px）、`compact`（16px）或 `none`。全屏看板、三栏工作台使用 `none`，常规 CRUD 使用 `normal`。

### 4.2 UiSection

统一白色分组面板，提供标题、说明和操作插槽。复杂页面用多个 `UiSection` 分组；不要在卡片中继续嵌套三层卡片。

### 4.3 UiStatusBadge

语义为 `neutral / info / success / warning / danger`，可通过 `dot` 显示状态点。

```vue
<UiStatusBadge label="实时态势已连接" tone="success" dot />
```

状态文案应说明结果，如“同步失败”“等待审批”；避免只写“异常”或“状态 2”。

## 5. Element Plus 使用规范

### 按钮

- 每个视图最多一个高优先级主按钮；次要操作使用默认或文字按钮。
- 危险操作仅在真正不可逆时使用 danger，并二次确认。确认文案必须包含对象与影响。
- 工具栏按钮高 32px；登录、关键提交可使用 40px。

### 输入与表单

- 标签默认位于输入框左侧或上方，同一表单内保持一致。
- 必填项在标签和错误信息中明确；错误信息说明修复方式。
- 搜索在输入后回车和点击查询均可触发；重置恢复服务端默认值。
- 长表单按业务分组，抽屉适合辅助编辑，弹窗仅承载短任务。

### 工具栏与筛选区

推荐组合顺序：关键词 → 高频筛选 → 展开更多 → 空白弹性区 → 重置 → 查询。筛选区使用次级背景或白色细边框面板，不使用高饱和色块。

### 表格与分页

- 表头 40px，正文行约 40–44px；主标识列左对齐，数值右对齐，状态居中或左对齐。
- 操作列固定在右侧，优先保留“查看/编辑”，低频操作进入更多菜单。
- 默认截断长单行并提供 tooltip；日志、描述字段允许换行但需限制最大行数。
- 分页放在表格右下，结果数在左侧；空数据时保留表头并显示空状态。

### 卡片与标签

- 管理卡片使用白底、1px 边框、8px 圆角和一级阴影。
- 标签用于分类，状态使用 `UiStatusBadge`；禁止用多个随机颜色表达同一维度。

### 提示、弹窗与抽屉

- Message 用于轻量成功反馈；Notification 用于可延后处理的信息；Alert 用于当前区域持续风险。
- 弹窗宽度优先 480 / 640 / 800px，内容过长时内部滚动，底部操作固定。
- 抽屉用于上下文编辑和详情，桌面端宽 480–720px；移动端宽度 100%。
- 导航与对象选择型抽屉允许使用 280–360px 的紧凑宽度；标题、搜索和摘要固定，列表独立滚动。此类抽屉不得套用编辑型抽屉的宽度，也不得用悬在内容中部的关闭箭头替代明确的关闭按钮。

### 上传

- 上传前展示格式、大小、像素或比例要求；上传中显示进度；失败后保留重试入口。
- 图片预览必须使用真实资源，`object-fit` 与业务类型匹配。品牌 Logo 用 `contain`，Banner 可用 `cover`。

### 空状态与加载

- 首次加载使用骨架屏；局部刷新使用区域 loading，避免遮挡整个应用。
- 空状态说明“为什么为空”和下一步操作。无权限、网络失败、筛选无结果必须使用不同文案。
- 错误状态保留用户输入，并提供重试、返回或查看详情入口。

## 6. 页面模板

### 顶部导航

60px 白色顶栏，品牌区固定最小宽度，一级导航横向排列，当前项用主色文字、柔和底色和 2px 指示线。宽度不足时由 Element Plus 收纳；用户信息逐级降级为头像。

### 侧栏

深色业务侧栏只用于高频运营模块；宽度 220px，折叠后 56–64px。当前项使用同一主色体系，不与顶部导航竞争高亮强度。

### CRUD 页面

`UiPage` + 筛选 `UiSection` + 表格 `UiSection`。创建操作放页头右侧，批量操作仅在选中数据后出现。

### 配置编辑器

左侧导航/树，中间编辑器，右侧检查或预览。三栏均设置 `min-width: 0`，分隔条可拖动；保存状态在标题区持续可见。

### AI 三栏工作台

会话列表 / 对话区 / 上下文或工具区。中间列是唯一主焦点；小屏隐藏右栏，手机端将侧栏变为抽屉。生成中提供停止操作并明确引用来源。

### 数据看板

使用 `padding="none"`，看板自己控制网格和全屏。图表底色透明或白色；网格线使用分隔色；八色图表色板来自协议，不使用红绿作为唯一对比。

### 登录页

桌面双栏、移动单栏。品牌叙事位于左侧，表单集中在右侧；窗口高度内完整显示，不产生页面滚动。错误信息贴近字段，Enter 与按钮提交行为一致。

### 错误页

显示状态码、可理解的原因、主操作“返回首页”和次操作“重试”。不使用与产品无关的插画；无权限页提供申请权限或联系管理员路径。

## 7. 文案和内容规则

- 使用“动词 + 对象”：新建策略、保存配置、刷新验证码。
- 标题不加句号；说明文不超过两行；按钮通常 2–6 个汉字。
- 单行标识符省略并提供完整 tooltip；描述、版权、产品简介允许换行。
- 日期采用 `YYYY-MM-DD HH:mm:ss`，时区由 UI 协议提供；数量使用千分位。
- 危险确认需写明对象、不可逆后果和取消路径，禁止只问“确定吗”。
- 手机端优先保留状态、名称和主操作；低优先级列移动至详情或更多菜单。

## 8. 无障碍

- 所有交互必须可通过键盘到达，焦点环由 `--zv-focus-ring` 统一控制。
- 图标按钮提供可读名称；装饰图标使用 `aria-hidden="true"`。
- 表单错误与字段建立关联；弹窗打开后聚焦标题或首个输入，关闭后焦点返回触发器。
- 状态与图表同时提供文本/形状区分；正文对比度至少 4.5:1，大字至少 3:1。
- 200% 缩放和 390px 宽度下，不得出现不可访问的横向操作区域。

## 9. 插件 UI 接入协议

受控 iframe 加载完成后，主系统向解析并验证过的精确 origin 发送：

```ts
interface UiThemeContractV1 {
  readonly type: 'zenvis:ui';
  readonly contractVersion: '1.0.0';
  readonly themeId: 'zenvis-light';
  readonly colorScheme: 'light';
  readonly density: 'compact';
  readonly locale: string;
  readonly timezone: string;
  readonly reducedMotion: boolean;
  readonly tokens: Readonly<Record<string, string>>;
  readonly chartPalette: readonly string[];
}
```

插件准备好后发送 `{ type: 'zenvis:ui:ready', contractVersion: '1.0.0' }`。主系统验证 `event.source`、`event.origin` 和版本后再次发送主题。严禁使用 `'*'` 作为 `postMessage` 目标 origin。

AMIS、低代码页、内置 HTML 页和看板 iframe 可消费该协议。插件应将令牌映射到自己的 CSS 变量和图表主题；未实现协议时忽略消息即可。不可控外部应用不做样式注入，其加载、沙箱和业务行为保持原样。

## 11. 当前一致性基线与验收状态

- 顶部导航、登录页、“关于产品”、配置管理、DIH、全局检索过滤器和大屏看板抽屉已采用同一浅色科技风基础令牌。
- DIH 中心区只保留一套有效组件样式；附件、消息、输入区、Skill、加载态和交互按钮均由当前语义令牌样式负责，禁止重新引入并行的旧版 style 块。
