## 数据链路

`demo_logs → 严格 JSON 解析 → operation_type 路由 → 删除路由字段 → 对应 ClickHouse 表`

任务注册文件为 `02_push-task/config.json`，Vector 配置为 `push_operation.yaml`。合法样例覆盖全部十类实体；配置内置合法路由和非法 JSON 两个测试。磁盘缓冲、批处理、超时与有限重试用于降低短暂故障造成的数据丢失。

生产链路应把 `demo_logs` 替换为真实接入源；直接写 ClickHouse 的演示任务不承担租户鉴权、来源认证或消息总线重放能力。

## UI 与看板

- 低代码应用：`com.coolxer.plugin.operation`
- IP 调查页：`com.coolxer.plugin.operation.ip-statistics`
- 详情页：`com.coolxer.plugin.operation.detail-*`
- HTML 看板：`com.coolxer.plugin.operation.dashboard.operation-overview`

概览和看板使用 `/entity/overview/query`、`/entity/trend/query`、`/entity/distribution/query`；IP 调查使用 `/entity/value-statistics/query`。

## 升级边界

1. 1.2.1 将实体 ID 固定为 `6101–6110`，字段 ID 固定为 `610001–610203`，满足跨插件全局唯一校验。
2. 历史 `MergeTree()`、`ORDER BY (id)` 和 `PARTITION BY id` 保持不变；`sort_column: event_time` 仅影响查询默认排序。
3. 1.2.0 若从未成功安装或安装已回滚，可直接安装 1.2.1。
4. 1.2.0 若已成功安装，普通升级会因 ID 变更被增量校验拒绝，必须先执行平台级 ID 迁移，不能直接覆盖。

## 排障

- 安装出现 CGLIB 错误：确认使用 1.2.1 新 Jar；Repository 不应标注 `@Repository`，Service 方法不应标注 `@Transactional`。
- 页面提示静态资源不存在：确认安装包包含新的 `site.json`、列表文件和 `detail-*`/`ip-statistics` 子目录。
- 模拟数据不入库：检查任务是否启用、ClickHouse 环境变量、Vector 错误分支和表结构是否与 Meta 一致。
