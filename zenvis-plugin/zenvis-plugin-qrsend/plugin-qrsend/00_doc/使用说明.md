# QRSend 使用说明

> 本文档面向最终使用者，介绍如何通过 Zenvis 平台中的「二维码离线传输」菜单完成屏幕 → 摄像头 的离线数据传输。关于插件的架构、安装与升级，请参见 [README.md](README.md)。

---

## 一、功能定位

QRSend 用于在**无法建立网络连接**的两台设备之间传输数据。发送端将数据切分、压缩、喷泉编码（RaptorQ）后，以二维码流的形式在屏幕上持续播放；接收端用摄像头（或已录制视频、屏幕捕获）读取其中任意足够大的子集，即可完整重建原始数据。

典型场景：
- 隔离网 / 内外网之间交换文件
- 临时工位、无网络环境下的应急传输
- 需要物理隔离但又要传输小批量数据的合规场景

## 二、进入方式

1. 登录 Zenvis 平台。
2. 在左侧菜单点击 **「二维码离线传输」**。
3. 页面以 iframe 形式加载 QRSend，地址栏不会变化；若长时间空白，请确认当前账号已被分配该菜单权限。

## 三、核心操作

### 3.1 发送数据

1. 在发送端设备打开 QRSend，点击顶部导航 **「发送」**（`#/send`）。
2. 选择发送内容类型：
   - **文本**：直接粘贴或输入文字。
   - **文件**：选择一个或多个文件。
   - **文件夹**：选择整个目录，接收端会还原目录结构。
3. 如需加密，先在 **「设备」** 页完成配对（见第 3.4 节），然后在发送页勾选目标设备。
4. 点击 **「开始发送」**，屏幕进入全屏二维码播放状态。
5. 将屏幕对准接收端摄像头，保持环境光线充足，避免屏幕反光。

### 3.2 接收数据

在接收端设备打开 QRSend，点击顶部导航 **「接收」**（`#/receive`），选择任一接收通道：

| 通道 | 适用场景 | 操作要点 |
|------|----------|----------|
| **摄像头实时扫描** | 两台设备物理靠近 | 允许浏览器摄像头权限；对准发送端屏幕，保持 10~50 cm 距离，避免抖动 |
| **从视频文件接收** | 已提前录制发送端屏幕 | 支持常见视频格式（MP4、WebM 等）；视频需清晰、无剪辑跳帧 |
| **从屏幕捕获接收** | 发送端与接收端在同一台设备，或接收端可看到发送端屏幕 | 选择「屏幕捕获」，授权后框选发送端窗口 |

接收过程中页面会实时显示已接收的分段进度与校验状态。

### 3.3 断点续传

传输因故中断（如摄像头移开、页面刷新）时，接收端会生成一个 `QSR1-XXXXXXXX` 格式的 **resume code**。

恢复步骤：
1. 在接收端 **「收件箱」**（`#/inbox`）中找到未完成的会话，复制 resume code。
2. 在发送端重新进入 **「发送」**，粘贴 resume code。
3. 发送端仅补发缺失的分段，接收端继续扫描即可，无需重头开始。

> resume code 仅在当前浏览器会话有效；若接收端已清理存储，需重新完整传输。

### 3.4 设备配对与端到端加密

QRSend 支持基于 [age](https://age-encryption.org/) 的端到端加密。加密前需在两端设备上完成配对：

1. 在两台设备的 QRSend 中分别进入 **「设备」**（`#/devices`）。
2. 点击 **「添加设备」**，输入对方设备 ID（一串短编码）。
3. 双方核对页面上显示的 **指纹**（fingerprint），确认一致后保存。
4. 配对成功后，发送页勾选目标设备即可启用加密；接收端会自动解密。

> 设备私钥由浏览器 WebCrypto 生成，**不可导出**；更换浏览器或清理站点数据后需重新配对。

### 3.5 高级功能（功能预览）

在页面底部 **「功能预览」**（`#/preview`）中可开启实验特性，默认全部关闭：

| 功能 | 说明 | 建议场景 |
|------|------|----------|
| **双向传输** | 接收端回传缺失信息，发送端自动补发 | 大文件、易丢帧环境 |
| **自动调速** | 根据接收端扫描成功率动态调整二维码切换速度 | 光线复杂或摄像头性能一般时 |
| **声音反馈** | 接收端通过提示音告知扫描状态 | 发送端无人值守时 |
| **局域网加速** | 同局域网内通过 WebRTC 直连辅助传输 | 两台设备在同一局域网但不想插网线 |
| **彩色码** | 红绿蓝三码合一，单帧数据量提升约 3 倍 | 屏幕素质好、摄像头支持彩色识别 |
| **多码网格** | 单帧显示最多 8×8 个二维码 | 大屏、高分辨率场景 |

## 四、数据保存与清理

- 接收完成的文件默认保存在浏览器 **OPFS**（源私有文件系统）中，不占用本地磁盘目录，也不上传到 Zenvis 服务器。
- 在 **「存储」**（`#/storage`）页面可查看所有接收会话、导出文件、删除遗留数据或清理日志。
- 若需彻底清理浏览器侧所有痕迹（含设备 ID、已信任设备、缓存），请使用浏览器「清除站点数据」功能。

## 五、常见问题

| 问题 | 原因与解决 |
|------|------------|
| 页面提示「无法访问摄像头」 | 浏览器未授权摄像头权限；点击地址栏左侧锁形图标重新授权，或改用「从视频文件接收」 |
| 二维码播放很久但接收进度为 0 | 确认接收端对准的是**本插件**的二维码流（而非其他 QR 工具）；调整屏幕亮度、减少反光；尝试缩短距离 |
| 传输大文件时页面卡顿 | 大文件在 OPFS 中读写，若 OPFS 不可用会回退内存；建议单文件不超过 500 MB，或改用「文件夹」分批发送 |
| 发送端换了浏览器后无法续传 | resume code 与浏览器存储绑定；跨浏览器/设备续传需重新完整发送 |
| 页面提示「安全上下文不可用」 | 当前通过明文 HTTP 访问；WebCrypto、OPFS、Service Worker 需要 HTTPS 或 localhost 环境 |
| 局域网加速不生效 | 双方需在同一局域网且浏览器支持 WebRTC；功能预览中默认关闭，需手动开启 |

## 六、注意事项

1. **数据不经过平台**：QRSend 的所有编码、解码、加密均在浏览器本地完成，Zenvis 服务端仅托管静态页面，不接触传输内容。
2. **屏幕录制风险**：发送端播放二维码时，任何能看到屏幕的人都可能截获数据；敏感内容建议先完成设备配对再传输。
3. **浏览器兼容性**：推荐 Chrome / Edge 90+、Firefox 90+、Safari 15+；旧版本浏览器可能缺少 WebAssembly、ES Module Worker 或 AudioWorklet 支持。
4. **离线使用**：页面以 PWA 形式缓存，首次加载后断网仍可打开；但设备配对、局域网加速等功能需要网络或安全上下文支持。
