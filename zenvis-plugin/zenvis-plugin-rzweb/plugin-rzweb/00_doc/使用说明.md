# RzWeb 使用说明

> 本文档面向安全分析人员，介绍如何通过 Zenvis 平台中的「二进制分析」菜单使用 RzWeb 对二进制文件进行静态逆向分析。关于插件的架构、部署与限制，请参见 [README.md](README.md)。

---

## 一、功能定位

RzWeb 将 [Rizin](https://rizin.re) 逆向工程框架通过 WebAssembly 移植到浏览器，无需在本地安装 IDA Pro、Ghidra 或 Rizin，即可在 Zenvis 平台中直接上传二进制文件并完成静态分析。

核心能力：
- 反汇编（Disassembly）
- 十六进制查看（Hex Dump）
- 反编译（基于 Ghidra Decompiler）
- 控制流图（Graph）
- 字符串分析（Strings）
- 导入 / 导出表（Imports / Exports）
- 段信息（Sections）
- 交叉引用（Xrefs）
- 终端命令行（Terminal）

## 二、进入方式

1. 登录 Zenvis 平台。
2. 在左侧菜单点击 **「二进制分析」**。
3. 页面以 iframe 形式加载 RzWeb；若长时间空白或提示「跨域隔离不可用」，请参见第 5 节「运行环境」。

## 三、核心操作

### 3.1 打开二进制文件

1. 点击页面中央 **「Open File」** 或直接将文件拖入页面。
2. 支持格式：ELF、PE、Mach-O、DEX、 raw binary 等 Rizin 支持的格式。
3. 文件在浏览器本地解析，**不会上传到服务器**。

> 大文件（>100 MB）解析时间可能较长，建议先使用 `rz-bin -I` 等本地工具做初步筛选。

### 3.2 界面布局

RzWeb 默认采用多面板布局，可通过右上角布局切换按钮调整：

| 面板 | 用途 |
|------|------|
| **Disassembly** | 反汇编代码，支持跳转、重命名、注释 |
| **Hex Dump** | 原始字节十六进制视图 |
| **Decompiler** | 伪 C 代码（基于 Ghidra Decompiler） |
| **Graph** | 当前函数的控制流图 |
| **Strings** | 提取的字符串列表，支持搜索与跳转 |
| **Imports / Exports** | 导入 / 导出符号表 |
| **Sections** | 段（Section）地址、权限与大小 |
| **Xrefs** | 交叉引用，查看代码 / 数据被谁引用 |
| **Terminal** | Rizin 命令行，支持全部 `rz` 命令 |

### 3.3 常用分析流程

#### 快速定位入口点

1. 打开文件后，点击顶部 **「Analyze」** → **「Analyze All」**（或按 `aaa`）。
2. 在左侧函数列表中找到 `main` 或 `entry0`，双击跳转到反汇编视图。
3. 按 `Space` 在反汇编 / 控制流图之间切换。

#### 查看字符串并追踪引用

1. 切换到 **「Strings」** 面板，浏览或搜索可疑字符串（如 URL、注册表键、错误提示）。
2. 右键目标字符串 → **「Show Xrefs」**，跳转到引用该字符串的代码位置。
3. 在反汇编视图中按 `x` 也可对当前地址查看交叉引用。

#### 使用反编译器

1. 在反汇编视图中定位到目标函数。
2. 切换到 **「Decompiler」** 面板，查看对应的伪 C 代码。
3. 若伪代码为空，先在 Terminal 中执行 `aa` 或 `aaa` 完成分析。

#### 终端命令行

RzWeb 内置完整的 Rizin 命令行，在 **「Terminal」** 面板中输入命令：

```bash
# 查看文件信息
iI

# 列出所有函数
afl

# 跳转到指定地址
s 0x140001000

# 反汇编当前函数
pdf

# 搜索字符串
/ hello

# 查看导入表
ii

# 查看段信息
iS
```

> 完整命令参考 [Rizin 官方文档](https://book.rizin.re/)。

### 3.4 保存与导出

- **注释与重命名**：在反汇编视图中双击地址或按 `n` 重命名函数；按 `;` 添加注释。修改保存在浏览器 IndexedDB 中，刷新页面后保留。
- **导出伪代码**：Decompiler 面板支持复制全部伪 C 代码到剪贴板。
- **导出 Hex**：Hex Dump 面板支持选中区域复制为十六进制或 C 数组格式。

## 四、运行环境

### 4.1 COOP/COEP 与 SharedArrayBuffer

RzWeb 的 WebAssembly 多线程依赖 `SharedArrayBuffer`，浏览器要求页面满足跨域隔离条件：

- `Cross-Origin-Opener-Policy: same-origin`
- `Cross-Origin-Embedder-Policy: require-corp`

当前缓解方案：
- 页面通过 `coi-serviceworker.min.js` 在支持 Service Worker 的环境中动态注入上述响应头。
- 需要 **HTTPS** 或 **localhost** 环境，且浏览器允许注册 Service Worker。

**若无法启用跨域隔离，多线程 WASM 将降级为单线程，大文件分析速度显著下降。**

### 4.2 浏览器要求

- 支持 WebAssembly 与 ES Module Worker。
- 推荐 Chrome / Edge 90+、Firefox 90+；Safari 对 SharedArrayBuffer 的支持需 15.2+ 且同样要求跨域隔离。

## 五、常见问题

| 问题 | 原因与解决 |
|------|------------|
| 页面空白或提示「SharedArrayBuffer is not defined」 | 跨域隔离未生效；确认通过 HTTPS 访问，或联系管理员在网关为 `/zenvis/html-page/com.coolxer.plugin.rzweb/**` 添加 COOP/COEP 响应头 |
| 分析大文件时页面卡死 | 浏览器内存不足；建议关闭其他标签页，或改用本地 Rizin / Ghidra 处理 |
| 反编译面板为空 | 尚未执行分析；在 Terminal 输入 `aaa` 或点击「Analyze All」 |
| 中文 / 特殊字符字符串乱码 | 页面默认编码为 UTF-8；部分 Windows PE 中的 GBK 字符串需在 Terminal 中使用 `e cfg.encoding=gbk` 后重新搜索 |
| 函数列表为空 | 文件 stripped 或分析未完成；尝试 `aa`、`aaa` 或手动 `s entry0; af` |
| 刷新页面后注释丢失 | 浏览器 IndexedDB 被清理；避免使用隐私模式，或定期导出注释脚本 |

## 六、注意事项

1. **数据安全**：二进制文件全程在浏览器本地处理，不经过 Zenvis 服务端；但分析进度与注释存储在浏览器 IndexedDB 中，更换浏览器或清理数据后需重新分析。
2. **多线程限制**：跨域隔离未启用时，分析速度会显著下降，建议优先解决 COOP/COEP 配置。
3. **资源占用**：反编译与大文件分析会占用大量内存，建议单文件不超过 200 MB。
4. **命令行优先**：复杂分析（如自定义脚本、批量重命名）推荐在 Terminal 中使用 Rizin 命令完成，比 GUI 操作更高效。
