# TraceHub 资源与状态语义

## 资源范围

TraceHub 在一个只读服务中提供两类不可变资源：

| 资源 | 用途 | 数据载体 |
| --- | --- | --- |
| IOC 威胁情报快照 | 精确查询 IP、域名、URL、哈希、邮箱等指标 | `current.zioc` |
| IP 地理位置库 | 查询公网 IPv4/IPv6 的国家、省、市和 ISP | ip2region XDB |

TraceHub 不读取源 NDJSON、不连接业务数据库，也没有资源热更新接口。资源更新需要替换运行文件、重新构建镜像并滚动发布。因此，查询结果只代表 TraceHub 当前进程加载的快照。

四个 MCP 工具均为只读、幂等操作，不会新增、修改或删除任何资源。

## IOC 查询状态

| 状态 | 含义 | 能否据此判断安全 |
| --- | --- | --- |
| `matched` | 当前快照中存在至少一条精确匹配记录 | 不能单独定性事件，但可作为情报命中证据 |
| `not_found` | 当前快照覆盖该指标类型，但没有精确匹配 | 不能；只表示当前快照未命中 |
| `not_covered` | 当前快照未覆盖该指标类型 | 不能；表示没有可用的判断依据 |
| `invalid` | 输入无法规范化、类型不支持或参数非法 | 不能；应先修正输入 |
| `library_unavailable` | IOC 快照整体不可用 | 不能；表示无法判断 |

重要边界：

- `not_found` 不等于安全。快照可能没有收录该指标，或收录的是其他表示形式。
- `not_covered` 不等于无威胁。只是当前快照没有该类型的数据覆盖。
- `library_unavailable` 不是“未命中”，而是查询能力不可用，应提示修复资源后重查。
- `invalid` 是输入问题，不应写入研判结论作为威胁判定。

单条 IOC 查询可以返回 `library_unavailable` 项。批量查询在 IOC 快照整体不可用时可能直接返回工具错误而没有 `items`；这不是“整批未命中”，必须按资源不可用处理。

## IP 地理查询状态

| 状态 | 含义 |
| --- | --- |
| `matched` | 对应 IP 版本的 XDB 命中并返回地理位置字段 |
| `not_found` | 对应 IP 版本资源可用，但无该地址记录 |
| `not_covered` | 地址属于私网、回环、链路本地、组播、文档网段等特殊用途地址，不具备公网地理意义 |
| `invalid` | 不是合法的 IPv4/IPv6 地址 |
| `library_unavailable` | 所需 IP 版本的 XDB 不可用 |

IP 地理位置只提供上下文。它不能单独证明地址恶意，也不能把某个 ISP、城市或国家直接归因给攻击者。攻击者可能使用代理、VPN、云主机、跳板或 CDN。

## 资源可用性

TraceHub 健康状态：

- `/health/live`：进程存活即返回 `UP`。
- `/health/ready`：两类资源均可用时为 `UP`；仅一类可用时为 HTTP 200 + `DEGRADED`；全部不可用时为 HTTP 503。

资源状态检查：

- `GET /api/v1/resources`：IOC 与 IP 地理资源的总体状态。
- `GET /api/v1/ioc/library`：快照 manifest、记录数和类型统计。
- `GET /api/v1/ip-location/library`：IPv4/IPv6 XDB 的可用性、文件摘要、生成时间和批量上限。

管理页 `/ui`、Swagger `/docs` 和 `/openapi.json` 不需要认证；`/api/v1/*` 与 `/sse` 需要 Bearer Token。

## 证据优先级

在安全事件研判中，建议按以下顺序使用结果：

1. 明确输入是否合法、类型是否解析正确；
2. 是否 `matched`，命中了哪个字段，来自哪些记录；
3. 情报记录的 `last_seen` 与事件时间是否接近；
4. `severity`、`confidence`、`threat_types` 是否支持当前风险判断；
5. 多个指标是否指向同一记录、来源或基础设施；
6. 是否仍有 `not_found`、`not_covered` 或 `library_unavailable` 造成的证据缺口；
7. IP 地理位置是否与事件叙述一致，仅作为上下文。
