# 查询输入、规范化与结果字段

## MCP 工具参数

### `ioc_lookup`

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `value` | 是 | 待查询指标 |
| `type` | 否 | 明确类型或 `auto`，默认自动识别 |
| `max_matches` | 否 | 返回明细上限，默认 20，最多受服务端 `IOC_MAX_MATCHES` 限制 |

### `ioc_lookups`

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `indicators` | 是 | 指标对象数组，每项包含 `value` 和可选 `type` |
| `max_matches` | 否 | 每条指标最多返回的命明细数量 |

批量数量范围为 1 到 `IOC_MAX_BATCH_SIZE`，默认上限 200。结果保持输入顺序。非法单项标记为 `invalid`，不会中断其他项目。

### `ip_location_lookup` 与 `ip_location_lookups`

单条使用 `ip`；批量使用 `ips` 数组。批量上限为 `IP_LOCATION_MAX_BATCH_SIZE`，默认 200。IPv4 和 IPv6 均可查询，非法地址和特殊用途地址逐项返回状态。

## 支持的类型

明确类型：`ipv4`、`ipv6`、`domain`、`url`、`md5`、`sha1`、`sha256`、`sm3`、`imphash`、`tlsh`、`email`。

别名：`auto`、`ip`、`hash`。

- `auto`：按 IP、URL、邮箱、域名、TLSH、哈希格式依次推断。
- `ip`：解析为 IPv4 或 IPv6。
- `hash`：按长度推断，32 位十六进制同时尝试 MD5 和 imphash，64 位同时尝试 SHA-256 和 SM3。

建议提供明确类型，避免同一字符串被推断为多个候选。脱敏写法如 `hxxp[:]//`、`example[.]com` 不是标准输入；应先由分析人员确认并显式转换，同时保留原始值说明。

## 规范化规则

| 类型 | 规范化 |
| --- | --- |
| IPv4/IPv6 | 转为标准文本形式；IPv4 不接受 IPv6，反之亦然 |
| 域名 | 转小写并移除末尾一个点；只做完整域名匹配 |
| URL | scheme 和 host 转小写；移除 HTTP 80、HTTPS 443 默认端口；路径、查询串和片段保留 |
| MD5/imphash/SHA-1/SHA-256/SM3 | 转小写 |
| TLSH | 转大写 |
| Email | 本地部分保留原样，仅域名转小写 |

查询和索引使用同一规范化逻辑，最终比较完整的规范化键。几个常见后果：

- 查询 `sub.example.com` 不会因为父域 `example.com` 命中而返回命中。
- 查询 `https://example.com/a` 与 `https://example.com/b` 是不同 URL；查询参数和片段也不同。
- 查询 `Example.COM.` 会规范化为 `example.com`。
- 查询 URL 时应保留路径和查询串，不要只截取域名后声称完成 URL 核验。

## IOC 单条结果字段

| 字段 | 说明 |
| --- | --- |
| `value` | 原始输入值 |
| `requested_type` | 请求类型，缺省为 `auto` |
| `resolved_type` | 实际解析出的类型；无效输入时可能缺失 |
| `status` | `matched`、`not_found`、`not_covered`、`invalid`、`library_unavailable` |
| `match_count` | 总命中数，可能大于返回明细数 |
| `truncated` | 是否因 `max_matches` 截断明细 |
| `matches` | 命中明细数组 |
| `reason` | 未命中、未覆盖、无效或不可用的原因 |

批量结果还包含：

| 字段 | 说明 |
| --- | --- |
| `requested_count` | 请求项数 |
| `valid_count` | 非 `invalid` 项数 |
| `matched_count` | `matched` 项数 |
| `items` | 与输入顺序一致的逐项结果 |

## 命中记录字段

每个命中项包含：

| 字段 | 说明 |
| --- | --- |
| `matched_field` | 命中的指标类型或字段，用于说明为何命中 |
| `record.record_id` | 情报记录稳定标识 |
| `record.source` | 情报来源 |
| `record.indicators` | 该记录包含的全部指标 |
| `record.title` | 记录标题 |
| `record.description` | 记录描述 |
| `record.threat_types` | 威胁类型数组 |
| `record.severity` | 来源给出的严重度，0–100；`null` 表示未知 |
| `record.confidence` | 来源给出的置信度，0–100；`null` 表示未知 |
| `record.first_seen` | 首次出现时间，带时区；缺失表示未知 |
| `record.last_seen` | 最后出现时间，带时区；缺失表示未知 |
| `record.attributes` | 未进入通用模型的来源扩展字段 |

`severity` 和 `confidence` 是情报源结论，不是 TraceHub 对当前安全事件的最终定性。多个来源可能对同一指标给出不同结论。

## IP 地理结果字段

| 字段 | 说明 |
| --- | --- |
| `ip` | 查询地址 |
| `ip_version` | 4 或 6 |
| `status` | 地理查询状态 |
| `country`、`province`、`city` | 国家、省、市 |
| `isp` | 运营商或网络服务提供方 |
| `country_code` | 国家代码 |
| `raw_region` | XDB 原始区域字符串 |
| `reason` | 异常状态原因 |

地理位置只作线索补充。使用时应同时说明它来自静态 XDB、反映的是库中登记信息，不能证明当前实际使用者或攻击归属。
