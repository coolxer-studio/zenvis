# 限制、运维与降级

## 数据与语义限制

1. **静态快照**：IOC 和 XDB 是不可变资源，运行时不重载。查询结果只代表当前进程加载版本。
2. **未命中非安全**：`not_found` 仅说明当前快照没有精确匹配。
3. **未覆盖非无威胁**：`not_covered` 仅说明该类型或该特殊地址没有可用数据。
4. **不可用非未命中**：`library_unavailable` 表示资源不可用，必须标记为“无法判断”。
5. **域名不继承**：查询子域不会匹配父域记录，反之亦然。
6. **URL 精确匹配**：路径、查询串和片段参与匹配，不能只看主机名。
7. **地理位置非归因**：IP 地理位置不能单独证明恶意、攻击者身份或实际使用者。
8. **来源结论不等于最终定性**：`severity`、`confidence`、`threat_types` 来自情报源，可能存在分歧。

## 查询与输出限制

- IOC 批量默认最多 200 条；IP 地理批量默认最多 200 条，实际以服务端环境变量为准。
- 单个 IOC 的 `max_matches` 默认 20，实际以 `IOC_MAX_MATCHES` 为准。
- `match_count` 可能大于 `matches` 数量；`truncated=true` 时必须说明明细已截断。
- TraceHub 返回的是规范化精确匹配，不提供模糊搜索、通配符、父域继承或语义相似检索。
- MCP 工具只读，不提供数据导入、快照重载、封禁或处置接口。

## 研判 Skill 的运行预算

本插件 Skill 的默认限制：

| 限制 | 值 | 说明 |
| --- | --- | --- |
| `maxToolCalls` | 8 | 单轮最多工具调用次数 |
| `maxRepeatedFailures` | 2 | 同类失败连续 2 次后停止 |
| `maxToolResultChars` | 20000 | 单次工具结果字符上限 |
| `maxAccumulatedToolResultChars` | 48000 | 单轮累计结果字符上限 |

超出预算时应基于已有证据给出阶段性结论，并明确列出未完成项，不得编造缺失结果。

## 连接与认证

- MCP 使用 SSE `/sse`，REST 与 MCP 共用 TraceHub 的 `TRACEHUB_API_TOKEN`；插件固定请求头中的 `replace-with-at-least-16-characters` 必须由管理员替换。
- ZenVis 后端访问的是 `base_url`（默认 `http://127.0.0.1:8010`），用户浏览器访问的是菜单 `params`，两者可能不同。
- Token 缺失、仍为占位值、错误或过期会导致 401。插件安装仍可完成，但 MCP 连接显示失败。
- 浏览器 Origin 若不在 `TRACEHUB_MCP_ALLOWED_ORIGINS` 中，浏览器侧 MCP 连接可能被拒绝；ZenVis 后端作为服务端客户端默认不带 Origin。
- TraceHub 管理页允许被任意页面通过 iframe 嵌入，CSP 使用 `frame-ancestors *` 且不返回 `X-Frame-Options`；若 ZenVis 前端配置了 `VITE_IFRAME_ALLOWED_ORIGINS`，仍需把 TraceHub Origin 加入该前端白名单。
- TraceHub 页面 Token 只保存在 `sessionStorage`，关闭标签页后清除。

## 健康与降级

| 情况 | 表现 | 研判处理 |
| --- | --- | --- |
| `/health/ready` 为 `UP` | IOC 与 IP 地理均可用 | 正常查询 |
| `/health/ready` 为 `DEGRADED` | 仅一类资源可用 | 分别说明可用和不可用能力，不能把不可用当未命中 |
| `/health/ready` 为 503 | 两类资源不可用 | 停止查询，报告资源不可用 |
| MCP 未连接 | 工具不可见或调用失败 | 报告连接/认证/网络问题，不生成指标结论 |
| 单条查询 `library_unavailable` | 对应资源不可用 | 该项标记“无法判断” |
| 批量中部分 `invalid` | 其他项仍可返回 | 报告无效数量，不污染有效结果 |
| 结果被截断 | `truncated=true` | 说明仅展示部分命中，保留 `match_count` |

## 工具失败处理

1. 记录失败工具、查询参数和错误摘要。
2. 同类失败连续 2 次后停止重试。
3. 如果失败影响主结论，明确写“无法判断”，不要用其他字段推测。
4. 如果只是部分指标失败，可对成功项给出局部结论，并列出未覆盖项。
5. 不输出内部 Token、连接串或完整异常堆栈。

## 运维检查

- 使用 `/health/live` 检查进程，使用 `/health/ready` 检查资源。
- 使用 `/api/v1/resources` 查看 IOC 与 IP 地理的总体可用性。
- 使用 `/api/v1/ioc/library` 和 `/api/v1/ip-location/library` 核对快照/XDB 版本与摘要。
- 更新资源后必须重启 TraceHub；不要期望上传新文件后当前进程自动生效。
- 生产环境应限制网络访问、使用 TLS、轮换 Token，并避免管理页直接暴露到公网。
- 卸载插件只清理 ZenVis 侧托管资源和旧版 `00_doc` 向量来源，不删除 TraceHub 服务或数据。
