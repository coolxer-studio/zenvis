# Wireview 使用说明

> 本文档面向安全分析人员与网络工程师，介绍如何通过 Zenvis 平台中的「流量包分析」菜单使用 Wireview 对 PCAP/PCAPNG 抓包文件进行浏览器端协议解码与逐包分析。关于插件的架构、部署与限制，请参见 [README.md](README.md)。

---

## 一、功能定位

Wireview 基于 [Wiregasm](https://github.com/wireshark/wiregasm)（Wireshark 的 WebAssembly 移植），将 Wireshark 的核心协议解码能力带到浏览器中。用户无需在本地安装 Wireshark，即可在 Zenvis 平台中直接打开或拖入抓包文件，完成协议解析、显示过滤、会话跟踪与数据导出。

抓包文件全程在浏览器本地解析，**不会上传到服务器**，适合在隔离环境或涉密终端上使用。

## 二、进入方式

1. 登录 Zenvis 平台。
2. 在左侧菜单点击 **「流量包分析」**。
3. 页面以 iframe 形式加载 Wireview；若长时间空白，请确认当前账号已被分配该菜单权限。

## 三、核心操作

### 3.1 打开抓包文件

支持以下方式加载文件：

| 方式 | 操作 |
|------|------|
| **点击打开** | 点击首页 **「Open File」**，在文件选择器中选择 `.cap`、`.pcap`、`.pcapng` 文件 |
| **拖拽上传** | 将抓包文件直接拖入页面任意区域 |
| **内置示例** | 点击首页 **「try out an example」**，加载随包发布的 `shark1.pcapng` 演示样本 |

> 文件在浏览器本地解析，大文件（>500 MB）可能因内存不足导致解析失败；建议先用 `editcap` 或 `tcpdump` 按时间 / 大小切分。

### 3.2 界面布局

加载完成后默认展示三栏布局：

| 面板 | 用途 |
|------|------|
| **数据包列表**（上） | 按时间顺序展示所有数据包，含编号、时间、源地址、目的地址、协议、信息摘要；支持按协议着色 |
| **协议树**（中左） | 选中数据包后展示逐层协议字段（Frame → Ethernet → IP → TCP/UDP → 应用层协议） |
| **原始字节**（中右） | 十六进制与 ASCII 对照显示；支持选中字段高亮对应字节 |

### 3.3 显示过滤器

在顶部过滤器输入框中输入 Wireshark 显示过滤器表达式，按 **Enter** 或点击 **「Apply」** 生效。

常用示例：

```text
# 只看 HTTP 流量
http

# 只看 TCP 80 端口
tcp.port == 80

# 只看与特定 IP 的通信
ip.addr == 192.168.1.100

# 只看 DNS 查询
dns.flags.response == 0

# 只看重传包
tcp.analysis.retransmission

# 复合条件：HTTP POST 且包含特定字符串
http.request.method == "POST" && http contains "password"
```

> 支持 Wireshark 全部显示过滤器语法；语法错误时输入框会标红并提示。

### 3.4 会话与流跟踪

1. 在数据包列表中右键目标包 → **「Follow」** → 选择 **「TCP Stream」**、**「UDP Stream」** 或 **「HTTP Stream」**。
2. 弹出窗口展示该会话的完整双向数据流，支持以下操作：
   - 切换显示格式（ASCII、Hex、Raw、YAML）。
   - 过滤单向数据（客户端 → 服务端 / 服务端 → 客户端）。
   - 导出为文本文件或原始字节流。

### 3.5 字段过滤与导出

- **字段过滤**：在协议树中右键任意字段 → **「Apply as Filter」** 或 **「Prepare as Filter」**，快速生成针对该字段的过滤条件。
- **导出选中包**：菜单 **「File」** → **「Export Specified Packets」**，支持按显示过滤器结果导出为新的 PCAP 文件。
- **导出对象**：若流量中包含 HTTP 文件传输、SMB 文件操作等，可通过 **「File」** → **「Export Objects」** 提取还原文件。

### 3.6 统计与图表

通过顶部菜单 **「Statistics」** 访问：

| 功能 | 说明 |
|------|------|
| **Protocol Hierarchy** | 协议层级统计，展示各协议占比 |
| **Conversations** | 会话列表，按地址 / 端口 / 协议分组 |
| **Endpoints** | 端点统计，展示所有通信主机 |
| **I/O Graph** | 流量随时间变化曲线，支持多过滤器对比 |

## 四、运行环境

- 依赖 WebAssembly 与 ES Module Worker，**不依赖 SharedArrayBuffer**，无需 COOP/COEP 跨域隔离响应头。
- 推荐 Chrome / Edge 90+、Firefox 90+、Safari 15+。
- 页面引用 Google Fonts（Inter、JetBrains Mono），离线环境自动回退系统字体，不影响核心功能。

## 五、常见问题

| 问题 | 原因与解决 |
|------|------------|
| 拖入文件后无响应 | 文件格式不受支持或已损坏；确认扩展名为 `.cap`、`.pcap`、`.pcapng`；尝试用 Wireshark 本地打开验证文件完整性 |
| 大文件解析失败 / 页面崩溃 | 浏览器内存不足；建议单文件不超过 500 MB，或先用 `editcap -c 100000 big.pcapng split.pcapng` 切分 |
| 显示过滤器不生效 | 检查语法是否正确；注意字段名大小写敏感；可尝试在 Wireshark 本地验证同一表达式 |
| 协议树中某些协议显示为「Data」 | 对应协议解码器未编译进 Wiregasm；以随包 WASM 资源为准，可尝试导出后用本地 Wireshark 深入分析 |
| 导出对象为空 | 流量中未识别到可还原的文件传输；确认存在 HTTP 200 OK、SMB Write 等完整文件传输会话 |
| 中文 / 特殊字符显示乱码 | 应用层 payload 编码与页面 UTF-8 解码不一致；在原始字节面板中查看 Hex 更准确 |

## 六、注意事项

1. **数据安全**：抓包文件全程在浏览器本地处理，不写入 Zenvis 服务端存储；但浏览器可能缓存页面资源，敏感环境使用后建议清理浏览器数据。
2. **大文件限制**：超大 PCAP 的解析受浏览器可用内存限制；更大规模的历史流量分析应使用服务端抓包与结构化入库能力，而非本工具。
3. **功能差异**：Wiregasm 是 Wireshark 的 WebAssembly 移植，部分高级功能（如 Lua 插件、自定义解码器、GeoIP 地图）可能不可用；以随包资源实际表现为准。
4. **示例文件**：`shark1.pcapng` 仅用于功能演示，生产环境可联系管理员在打包前删除以减小插件体积。
